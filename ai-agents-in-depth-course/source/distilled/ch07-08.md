# Chapter 7. Model Post-Training — 파라미터에 능력을 새기는 법

## 7.0 챕터의 지도: 두 개의 대원칙 (Threads)

이 책의 핵심 공식은 Agent = LLM + Context + Tools. 7장은 LLM 자체(두뇌)를 다루며, post-training이 context/tools 활용 능력을 어떻게 파라미터에 "구워넣는지"를 설명한다. 6장 끝에서 말한 대로 **평가 시스템과 시뮬레이션 환경이 post-training의 두 초석**이다: 평가 환경이 연습장을, 평가 지표가 목표를 제공한다.

**Thread One: SFT memorizes, RL generalizes.** 같은 태스크·예산에서 SFT는 훈련 데이터의 답을 암기해 배포 환경이 달라지면 실패하고, RL은 전이 가능한 전략(strategy)을 학습해 unseen 상황에서도 안정적이다. 이것은 슬로건이 아니라 통제 실험으로 반복 검증되는 측정 가능한 현상이다 (실험 7-11 GeneralPoints, 7-12 V-IRL).

**Thread Two: Data and environment matter more than algorithms.** 업계에서 가장 반직관적이고 가장 가치 있는 교훈. 기성 RL 알고리즘(PPO, GRPO)은 "쓸 줄 알면 충분"하다. 성패를 가르는 것은 ① 시뮬레이션 환경(연습장이 현실과 충분히 닮았는가) ② 훈련 데이터(데모와 보상 신호가 충분히 좋은가) ③ 베이스 모델의 능력이다. SFT 데이터가 충분히 좋으면 RL이 아예 필요 없는 경우도 많다. 우선순위는 **prior (base model) > environment > algorithm**.

독자별 읽기 경로: Agent 애플리케이션 개발자(모델을 직접 학습하지 않는 사람)는 7.1 파노라마 + 7.4~7.5 (SFT vs RL 선택 프레임워크) + 7.9 (데이터/환경 우선)에 집중하고, 이 판단이 Harness 엔지니어링 설계 결정(프롬프트로 해결할지, 파인튜닝할지)에 영향을 준다.

## 7.1 3단계 파노라마: Pre-training → SFT → RL

Table 7-1 요약:
| 단계 | 데이터 | 최적화 목표 | 배우는 것 | 비용 |
|---|---|---|---|---|
| Pre-training | 대규모 인터넷 텍스트 | Next Token Prediction (NTP) | 언어 규칙, 세계 지식, 기초 추론 | 매우 높음 (수백만~수천만 달러) |
| SFT | 수천~수만 개의 input-output 데모 쌍 | NTP (응답 부분에만 loss) | 지시 수행, 출력 포맷, 스타일, 프로세스 프로토콜 | 낮음 (수 시간~수 일) |
| RL | 태스크 + 보상 함수 (정답 불필요) | 기대 보상 최대화 | 전이 가능한 의사결정 전략, 새 핲법 발견 | 높음 (SFT의 수십~수백 배) |

비유: Pre-training은 "만권의 독서", SFT는 "선생님이 표준 풀이를 시연", RL은 "직접 문제를 풀며 정오답으로 연마". 셋은 대안이 아니라 파이프라인이다.

### 7.1.1 Pre-training: Next Token Prediction
모든 "지능"은 다음 토큰 맞히기라는 단순 태스크 위에 서 있다. 핵심 통찰: **모델의 출력은 본질적으로 확률 분포**이고, "학습"이란 이 확률 분포를 조정하는 것(원하는 토큰의 확률↑, 원치 않는 토큰↓). 3단계의 차이는 "무엇이 원하는 것인가, 그 신호가 어디서 오는가"뿐이다. Pre-training만 거친 모델은 박식하지만 "질문에는 답한다"는 프로토콜을 모른다.

### 7.1.2 SFT의 본질: 같은 NTP, 다른 데이터
수학적으로 SFT와 pre-training은 같은 태스크(같은 loss로 다음 토큰 예측). 차이는 딱 두 가지:
1. **데이터가 다르다**: 정제된 "질문→이상적 답" 쌍.
2. **Loss masking**: 질문 부분 토큰은 마스킹하고 응답 부분에만 gradient를 흘린다. SFT와 pre-training의 유일한 실질적 공학 차이.

여기서 "SFT는 암기한다"가 자연스럽게 따라 나온다: 최적화 목표가 정답 토큰의 확률 최대화, 즉 "표준 답을 통째로 외우기". SFT가 인코딩하는 것은 **protocol knowledge**(어떻게 말하고 행동하는가: 포맷, 스타일, 프로세스)이지 **factual knowledge**(무엇을 아는가)가 아니다. 후자는 pre-training 또는 RAG의 영역.

**LoRA (Low-Rank Adaptation) 실전 규칙** (Schulman & Thinking Machines Lab, "LoRA Without Regret", 2025 인용): 원본 가중치 대신 저랭크 "패치"만 학습, 파라미터 1-5%로 full FT에 근접. 원본 동결로 catastrophic forgetting 위험 감소. 규칙: ① MLP 레이어 포함 모든 주요 가중치 행렬에 적용할 것(attention만 적용하면 정확도 손실) ② 최적 학습률은 full FT의 약 10배(SFT·RL 공통) ③ SFT는 중고랭크(64-256), RL은 저랭크(8-32) 심지어 rank=1도 충분 ④ 배포 시 하나의 추론 서버가 여러 LoRA 어댑터를 멀티테넌트로 로딩 가능.

### 7.1.3 왜 SFT가 RL보다 먼저인가 ("형 선행, 신 후속")
RL은 모델이 스스로 생성한 출력에 보상을 주는 방식인데, 보상 계산 전에 출력을 **파싱**할 수 있어야 한다. JSON/툴콜 형식이 엉망이면 보상 함수가 성공/실패조차 판별 못 해 RL이 학습 불가. SFT는 "파싱 가능한 출력을 먼저 안정화"하는 역할 → RL에 채점 가능한 출발점을 준다. 이것이 업계의 가장 견고한 **"SFT first, then RL" 2단 패러다임**. 중국화 원론에 빗대어: SFT가 먼저 "형(形)"(포맷, 구조)을 잡고, RL이 "신(神)"(전략, 일반화)을 추구한다.

경계 조건: "SFT 필수"는 "작은 베이스 모델 + 엄격한 구조화 출력" 설정에서 성립(실험 7-11: Llama-3.2-Vision-11B는 SFT 없이 직접 RL 시 완전 실패). 충분히 강한 베이스 모델은 SFT 생략 가능 — DeepSeek-R1-Zero가 직접 RL로 성공, 반성·장문 CoT가 자발 출현. 단 출력 가독성 불량·중영 혼용이 비용이라 R1에서는 "cold-start SFT"를 다시 추가.

### 7.1.4 SFT vs RL 본질 비교 (이 장에서 가장 중요한 표)
Table 7-2:
| 차원 | SFT | RL |
|---|---|---|
| 최적화 목표 | 정답 확률 최대화 (Maximum Likelihood) | 기대 보상 최대화 |
| 학습 신호 | 단일 표준 답 (토큰마다 지도) | 자가 생성 다수 응답 + 보상 (응답당 성패 신호 하나) |
| 데이터 형태 | input-output 데모 쌍 | 태스크 + 보상 함수 |
| 배우는 것 | 고정된 입력→출력 매핑 (암기) | 전이 가능한 전략 (일반화) |
| 분포 이동 시 | 환경 변핵도 옛 답 적용, 성능 하락 | 같은 전략으로 재계산, 안정 |
| 샘플 효율 | 높음 (수천 개로 유효) | 낮음 (SFT의 수십~수백 배) |
| 학습 안정성 | 높음, 빠른 수렴 | 낮음, 진동, 세심한 튜닝 필요 |
| 적합 용도 | 포맷/스타일/프로세스 고착, 고품질 데모, 안정 환경 | 신규 시나리오 일반화, 최적 전략 탐색, 어노테이션 고비용 |

**Mode-seeking vs mass-covering**: SFT의 최대우도는 mass-covering — 데모에 존재하는 모든 mode(답변 방식의 무리)를 저품질 mode까지 커버하려 한다. RL(KL 제약 정책 최적화, 수학적으로 reverse KL에 해당)은 mode-seeking — 보상 최고의 소수 mode에 확률을 집중하고 나머지를 버림("승자독식"). 이것이 RL 학습 모델이 더 "결단력 있게" 답하고 다양성을 희생하는 이유.

**왜 RL의 천장이 SFT보다 높은가 — RL은 "online"이기 때문** (3가지 이유):
1. **오프라인의 천장은 데이터, 온라인의 천장은 태스크.** SFT의 최적 결과는 데모의 완벽 복제 → 천장은 시연자의 수준(60점 선생의 데이터로 90점 학생 불가). RL은 보상만 본므로 데모에 없던 우수 전략을 독자 발견 가능 — 실험 7-13 SimpleVLA-RL의 "pushcut" 동작(인간 데모에 없던 자기 발명 동작)이 직접 증거.
2. **검증이 생성보다 쉽다 (verification-generation asymmetry).** SFT는 누군가 정답을 써내야 하지만 RL은 좋은지 판정할 수만 있으면 된다. 수학은 답 대조, 코드는 테스트, 정리는 prover로 검증. 이것이 RLVR(verifiable reward) 계열의 힘의 원천.
3. **온라인은 모델이 실제로 갈 궤적 위에서 훈련해 자기 실수 복구를 배운다.** 오프라인 모방의 고전 문제는 covariate shift: 학생이 데모에서 벗어난 상태에 들어가면 복구를 몰라 오류가 궤적 길이 T에 대해 대략 T²로 누적(온라인 데이터 훈련은 ~T로 압축). 7.12의 On-Policy Distillation이 강한 이유도 본질적으로 이 "online" 이점 + SFT의 "dense supervision" 이점의 결합.

## 7.4 SFT 실험들 — 프로토콜을 파라미터에 쓰기
SFT의 핵심 가치는 새 지식 주입이 아니라 **프로토콜 고착(solidifying protocols)**: 매핑 관계, 상호작용 포맷, 스타일 규범을 파라미터에 써서 긴 프롬프트 없이도 기대 출력이 나오게 하는 것. 수천~수만 개의 고품질 예시로 충분.

**SFT 데이터의 3대 출처**: ① 인간 전문가 데모 — 품질 천장 최고, 고비용, "시드 데이터"용 ② teacher-model 생성(합성 데이터) — 강한 모델이 대량 생산 후 필터링해 학생에게 증류 ③ model self-bootstrapping — 같은 문제에 다수 샘플링 → 검증기로 정답만 선별 → 자기 훈련(rejection sampling fine-tuning, RFT). 파이프라인: 태스크 분포와 출력 스키마 정의 → 후보 대량 생성 → 규칙 검증·포맷 체크·수동 샘플링으로 필터 → 중복 제거·혼합 비율·다양성 확보. "지저분한 10만 개보다 깨끗한 1만 개" — SFT는 데이터의 노이즈까지 파라미터에 그대로 쓴다.

- **실험 7-6 Voice SFT**: Orpheus(참조 오디오 이어붙여 화자 음색 일관성) vs Sesame(laugh/sigh 같은 paralinguistic 토큰 모델링). 실패 모드: 훈련 화자가 너무 적어 모두 같은 목소리, 토큰 overfitting으로 "기계적 웃음".
- **실험 7-7 Multilingual Thinking**: gpt-oss-20b에 reasoning language 지시 + 다국어 추론 예시 SFT. 훈련 데이터에 중국어가 전혀 없어도 추론 언어를 Chinese로 설정하면 중국어 CoT 수행 — zero-shot cross-lingual generalization. 이것은 SFT 자체의 일반화가 아니라 **다국어 pre-training이 만든 공유 표현 공간을 SFT가 활성화**한 것.
- **실험 7-8 Prompt Distillation**: "긴 프롬프트 + thinking 선생"의 행동을 "짧은/무 프롬프트 + non-thinking 학생"으로 압축. 긴 프롬프트와 중간 사고 과정은 버리고 입력→최종 결론만 학습. "대→소"와 "thinking→non-thinking" 두 차원(후자는 응답 속도 20-30배 개선). 주의: 증류는 선생의 경계를 계승 — 선생의 long-tail 체계적 오류가 학생에 하드코딩됨. 제품 안정·입력 분포 예측 가능·비용 제약 시 최적이지만, 탐색 단계에서는 명시적 사고 + 편집 가능한 프롬프트 유지가 핵심.
- **실험 7-9 CoT Distillation**: 완전한 사고 궤적을 학생에게 전이. 동급 파라미터 학생이 선생 능력의 70-80% 회복. DeepSeek-R1의 Qwen/Llama 증류 시리즈가 대표. "Thinking Wall" 현상: closed-source 추론 모델(o-series, Gemini)은 CoT를 재작성/요약해 숨김 → 오픈소스 추론 모델(DeepSeek V4, Kimi K3, GLM 5.2)을 선생으로. 실무 판단: 200B 이하 모델 학습에는 오픈소스 SOTA 선생이면 충분. 선생은 "세계 최고"일 필요 없이 "학생보다 명확히 강하면" 된다. 3단계: 궤적 수집(규칙 검증기로 오답 궤적 필터 = **rejection sampling**, 이 방식 SFT가 **RFT**) → SFT → 비교 평가. 비용: 학생이 선생의 체계적 오류와 장황한 사고 습관을 계승.

## 7.5 SFT vs RL 선택 프레임워크
**SFT 적합**: 포맷 안정화 필요(JSON, 대화 스타일), 고품질 데모 존재, 배포 환경이 훈련과 유사. **RL 필요**: 배포가 훈련과 체계적으로 다를 때(J/Q/K=10으로 훈련했는데 배포에선 11/12/13), 최적 전략 발견 필요(데모가 최적이 아닐 수 있음), 모든 경로를 데모하기에 어노테이션이 너무 비쌀 때.

실무 결정 순서:
1. **Post-training이 필요한가?** Harness 엔지니어링(프롬프트, 툴 설계, 컨텍스트 관리)으로 풀리면 학습 불필요. 대부분의 Agent 애플리케이션이 여기 해당.
2. **학습이 필요하면 SFT 먼저.** 출력 포맷·프로토콜 지식·스타일 통일에. 단, 대량 factual knowledge 주입에는 부적합(continued pre-training이나 RAG로).
3. **SFT로 부족하면 RL 추가.** 반드시 SFT로 출력 안정화 후에.

실용 테스트: **"데모를 더 추가핮도 신규 시나리오 성능이 안 오륨" → RL 전환 시점.** 근본 원인이 데모 수가 아니라 SFT의 최적화 목표 자체이기 때문.

## 7.6 Single-turn RL 실험
RL 알고리즘 최소 직관: **policy gradient** — 같은 문제에 여러 응답 생성, 고보상 응답 확률↑ 저보상↓. **PPO**는 업데이트 폭을 clip(가치 네트워크가 baseline 추정으로 세밀한 advantage). **GRPO**는 가치 네트워크 없이 같은 문제의 다수 응답을 그룹 내 상대 비교.

- **실험 7-10 AdaptThink**: RL로 "언제 생각하지 않을지" 학습. NoThinking이 간단 문제에선 comparable/우수, 어려운 문제에서만 Thinking 우위. 구성: Constrained Optimization Objective(NoThinking 장려 + 성능 하락 방지) + Importance Sampling(Thinking/NoThinking 샘플 균형, cold-start 문제 해결). 결과: 여러 수학 벤치마크에서 **응답 길이 45-64% 감소, 정확도는 유지/향상**. unseen 태스크 유형의 난이도도 올바르게 판단. Prompt distillation + AdaptThink = "fast-slow dual system": 증류가 thinking 필요 태스크 비율을 줄이고, AdaptThink이 나머지의 트리거 전략을 최적화.
- **실험 7-11 GeneralPoints** (Chu et al. 2025, "SFT Memorizes, RL Generalizes", arXiv:2501.17161): 24 게임 변형. Rule 변형: 훈련 J/Q/K=10, 테스트 J=11/Q=12/K=13. Visual 변형: 훈련 검정 수트(스페이드·클로버), 테스트 빨강 수트(하트·다이아). Llama-3.2-Vision-11B, SFT 초기화 후 동일 예산으로 SFT 연장 vs RL(PPO+value network) 분기. **결과: Rule OOD에서 RL +3.5pt(11.5→15.0), SFT -8.1pt(11.5→3.4); Visual OOD(GP-VL)에서 RL +17.6pt(23.6→41.2), SFT -9.9pt(23.6→13.7).** RL은 outcome 지향 최적화가 시각 인코더 자체를 개선(인식 정확도와 전체 성능 강한 상관); SFT는 사고 토큰 패턴에 과적합해 시각 토큰 학습을 소홀히 함. SFT 없는 end-to-end RL은 완전 실패(출력 비구조화로 보상 계산 불가). 추가 발견: **검증 반복 횟수가 많을수록 일반화 향상(10회 +5.99% vs 1회 +0.48%)** — 사고 시 컴퓨트 스케일링이 RL 일반화의 핵심.

## 7.7 RLHF: 인간 선호에서 보상 모델로
**InstructGPT (Ouyang et al. 2022) 3단계 파이프라인**: ① SFT ② Reward Model (RM) 훈련 — 같은 프롬프트에 다수 응답 생성, 인간이 pairwise 비교, Bradley-Terry 모델로 학습: L_RM = −log σ(r(x,y_w) − r(x,y_l)). 절대 점수가 아니라 비교를 모으는 이유: "A vs B 중 뭐가 낫나" 판단이 훨씬 일관적. ③ RM 점수를 보상으로 PPO.

**KL Penalty**: r = r_RM − β·KL(π_θ ‖ π_ref). 4가지 질문에 대한 답:
1. KL은 per-token으로 계산되어 보상에 혼합(per-token KL), 별도 loss term이 아님. β = kl_coef.
2. 방향이 current→reference인 것은 **reverse KL**: "π_θ가 높은 확률을 두는데 π_ref가 ~0인 곳"을 처벌 = 참조 모델(SFT, 안전 영역)이 가지 말라는 곳에 가는 것을 처벌. forward KL이면 참조의 모든 표현 스타일 커버를 강제 — RLHF 목표 아님.
3. Reverse KL이 **mode-seeking**인 이유가 RLHF 안정성의 핵심: RM이 인정하는 고득점 응답 스타일 1-2개에 집중.
4. KL이 없으면: RM은 참조 정책 근처 분포에서 학습됐으므로 정책이 멀어지면 점수가 근거 없는 외삽 → **reward hacking**과 **distribution collapse**(반복, 깨진 출력) 방지가 목적. DAPO, Open-Reasoner-Zero 등 일부는 KL을 의도적으로 제거(단 DeepSeek-R1-Zero의 GRPO는 KL 항 명시 포함).

**Reward Model Over-Optimization** (Gao, Schulman, Hilton, OpenAI 2023, "Scaling Laws for Reward Model Overoptimization"): RL 진행에 따라 proxy reward(RM 점수)는 단조 증가하지만 진짜 품질(인간 평가)은 상승 후 하락. Goodhart's Law. 모델은 더 잘 답하는 게 아니라 RM이 고득점 주게 만드는 법(장황, 아부, 그럴듯한 공허한 말)을 학습. 완화: KL penalty, early stopping.

**DPO (Direct Preference Optimization, Rafailov et al. 2023)**: 명시적 RM 생략, 선호 쌍을 implicit reward의 분류 loss로 직접 변환. SFT만큼 간단(온라인 샘플링·가치 네트워크·별도 RM 불필요). 비용: 완전 오프라인 — 선호 데이터 밖의 신행동 탐색 불가, 천장은 선호 데이터의 품질·커버리지.

**RLHF vs RLVR**: 차이는 보상의 출처. RLHF는 학습된 RM(인간 선호 데이터), RLVR은 규칙 기반 검증기(테스트 통과 여부, 정답 여부 — deterministic 코드로 퇴화한 "보상 모델"). Agent 태스크는 대부분 검증 가능 → 이 장이 RLVR 중심인 이유. 실제 배포 모델은 둘을 조합: RLHF가 대화 품질·안전 정렬, RLVR이 추론·Agent 능력.

## 7.8 RL 알고리즘 비교 — 선택 지도
엄밀 용어: **On-Policy**는 같은 정책의 신규 샘플만으로 업데이트, **Off-Policy**는 다른/이전 정책 데이터도 활용. 매핑: SFT는 off-policy 모방학습, PPO/GRPO 표준형은 on-policy(현재 모델의 신규 rollout 사용), DPO는 오프라인 선호 최적화.

공통 기반은 **policy gradient** (REINFORCE): ∇J(θ) = E[∇ log π_θ(a|s) · G]. 전체 궤적 return G를 가중치로 쓰면 unbiased하지만 고분산 → baseline b 도입, **advantage Â = G − b**.

## 7.9 데이터와 환경이 알고리즘보다 중요하다 (Thread Two 정면 서술)
### 7.9.1 환경: 모델의 훈련장
RL의 본질은 시행착오 학습, 시행착오에는 훈련장이 필요. **환경의 충실도(fidelity)가 학습된 정책의 실사용 가능 여부를 직접 결정.**
- "왜곡된 환경 = 죽은 정책": 시뮬레이션 고객센터가 고정 스크립트로만 답하면 모델은 시뮬레이션에서만 통하는 수험 전략을 배워 배포 즉시 붕괴. RL 프로젝트의 가장 흔한 사인은 알고리즘이 아니라 "연습장이 시험장이 아니었던 것".
- 고충실도 환경 구축은 종종 훈련 자첫보다 어렵고 비쌈. 실제 API는 rate limit, 계정 차단, 부작용이 있어 직접 훈련 불가 → 안정적·통제 가능·재생 가능한 "그림자 세계" 필요 (AWorld의 MCP 샌드박스, ReTool의 코드 인터프리터 샌드박스).
- 환경의 절반은 보상 함수: "세계가 어떻게 변하는가"의 시뮬레이션 + "행동이 좋았는가"의 판정.

### 7.9.2 환경을 못 만들면? 모델이 환경 역할을 하게 하라
1단계: **모델이 툴 호출 반환값을 합성.** ZeroSearch (2025, arXiv:2505.04588): LLM이 검색 엔진 역할. 커리큘럼 설계 — 초기엔 고품질 문서 반환, 점차 노이즈 섞어 품질 하락 → 실제 검색의 불완전한 반환에서 유용 정보 추출 학습. 실제 검색 엔진을 한 번도 안 본 모델이 실검색 연결 시 양호한 성능.
2단계: **모델이 환경 전체 동역학을 시뮬레이션.** DreamGym (2025, arXiv:2511.01824): 환경 동역학을 추론식 "경험 모델"로 증류, 상태+행동 → 상태 전이와 피드백을 단계별 추론으로 생성, 실환경 없이 대량 rollout. 고객센터/영업 Agent 훈련의 user simulator, τ-bench 계열 평가도 같은 아이디어.
리스크: **시뮬레이터의 세계 지식이 훈련의 천장, 시뮬레이터의 체계적 편향이 정책에 통째로 흡수.** RL은 시뮬레이터의 허점을 적극 찾아 reward hacking. 건전한 공학 관행은 **혼합(mixing)**: 모델 시뮬레이션이 상호작용 볼륨 대부분 담당 + 실환경 상호작용 보충 + 실환경으로 시뮬레이터 편향 주기적 보정.

### 7.9.3 데이터: 가장 결정적 연결고리, 품질이 모든 것을 이긴다
**Data quality trumps algorithms.** SFT는 노이즈·편향을 파라미터에 그대로 굽고, RL은 편향된 보상을 향해 끝없이 최적화(reward hacking의 온상). Garbage in, garbage out.

핵심 통찰: **많은 시나리오에서 SFT 데이터가 충분히 좋으면 RL이 아예 필요 없다.** RL이 진짜 대체 불가한 경우는 제한적: 배포 분포가 체계적으로 drift, 데모 자체가 차선, 어노테이션 고비용. Anthropic 사례: 2025년 전 post-training 레시피는 대량 고품질 SFT + RLAIF(Constitutional AI, Bai et al. 2022 — "헌법"으로 모델이 자기 응답 채점) 중심, RLVR 적게 의존했는데도 코딩 모델 우수 — 데이터 품질을 극한까지 밀어붙인 결과. "Data decides how far you can go; RL decides how much higher." (2025년부터 Anthropic도 RL 대규모 투자 — 좋은 데이터 위에서 RL이 천장을 더 높임)

데이터 품질의 3차원: **Coverage**(배포 상황, 특히 long-tail/엣지 커버?), **Diversity**(화자·스타일·풀이 다양? 아니면 단일 mode 붕괴), **Annotation Accuracy**(데모 답 자체가 정확? CoT 증류에서 오류 사고 과정은 학생이 모방).

**Rejection sampling 운영 파이프라인**: 프롬프트당 k개 샘플(실무 4-16) → 규칙 검증기/단위 테스트/참조 답으로 판정(자동 검증 불가면 RM이나 강한 모델 채점) → 통과 궤적만 유지, 중복 제거, 프롬프트당 유지 수 상한(쉬운 문제로 붕괴 방지) → SFT. 모델이 강해지면 재샘플링·재필터 반복 = STaR/RFT의 핵심 루프.

**Agentic 데이터 생성**: Autodata의 Agentic Self-Instruct (Kulikov et al. 2026, arXiv:2606.25996) — 메인 Agent가 4개 역할(challenger가 태스크 생성, 약/강 solver 시도, verifier 판정)을 조율해 "강한 모델은 풀고 약한 모델은 아직 못 풀며 평가자는 판정 가능한" 현재 능력 경계의 태스크를 탐색, 추론 컴퓨트를 신규 훈련 데이터로 전환. dynamic sampling(기존 풀 내 예산 재배분)과 달리 **태스크 분포 자체를 변경**. 단 "self-improvement" 용어 주의: 약한 solver만 훈련하면 적응형 증류에 가까움; 태스크 생성 Agent 자체가 하류 결과로 최적화돼야 완전한 메타 루프(아직 프론티어 연구).

9장으로의 연결: 음성 인식에서 모델이 사용자 발화 종료를 망설이는 문제의 근본 원인은 아키텍처가 아니라 "신의 시점(God's-eye view)"으로 라벨링된 훈련 데이터 — 결정 시점에 이용 가능한 정볼만으로 재라벨링하면 문제 소멸. **"Often, data is more critical than architecture."**

### 7.9.4 그럼 알고리즘은 언제?
투입 순서: **강한 베이스 모델 선택 → 환경과 데이터 연마 → 그제야 알고리즘/하이퍼파라미터의 한계 이득.** 환경이 현실적이고 데이터가 좋고 베이스가 강할 때만 알고리즘 차이가 드러난다.

## 7.10 Multi-turn: Credit Assignment과 보상 설계
### 7.10.1 핵심 도전
멀티턴 = 1, 4장의 ReAct 루프(Think→Act→Observe 반복). 도전: ① **Credit Assignment** — 지연 보상 하에서 어느 스텝이 최종 결과에 기여했는가(10턴 대화 성공이 2턴의 정확한 질문 때문인가 7턴의 인내 설명 때문인가) ② **Partial Observability** — 완전한 상태를 못 보고 이력에서 암묵적 상태 표현 구축 ③ **long-range dependency** — 초기 결정(서브골, 툴 선택)의 영향이 수십 스텝 후에 드러남.

### 7.10.2 보상 신호의 밀도와 형태
두 설계 차원: **Density**(피드백 빈도: binary/sparse/process) × **Representation**(scalar/vector/generative).

평가 환경→훈련 환경 전환 사례: SWE-bench → SWE-Gym(문제 설명 입력, patch 지도 신호, 테스트 케이스 보상) — 단 훈련 데이터는 신규 구축 태스크셋이고 OpenAI 수작업 500문제 **SWE-Bench Verified는 훈련 데이터와 엄격 분리**(섞이면 평가 무의미 — Thought Question 10의 긴장). τ²-bench의 완전 궤적(대화, 툴콜, 상태 변화)은 모방학습 데이터(성공=양성, 주석된 실패=음성). AndroidWorld의 파라미터화 템플릿은 변형 대량 생성으로 커리큘럼 학습 지원.

**보상 밀도 스펙트럼**: binary (GAIA exact match 0/1, SWE-bench 테스트 통과 0/1 — 10스텝 중 어느 스텝이 실패 원인?) → milestone (τ²-bench 다차원 검증: DB 상태 ✓ +0.4, 키워드 확인 ✓ +0.3, 프로세스 준수 ✓ +0.3) → process (스텝별 즉시 피드백) → dense continuous (AndroidWorld 부분 점수: 정답 클릭 +0.05, 필드 입력 +0.1, 최종 상태 +0.5).

**Pine AI 사례 (희소 보상의 딜레마)**: Xfinity 요금제 변경 전화 Agent를 binary 보상으로 훈련하면 계좌번호 까먹음(0) → 카드 끝 4자리 까먹음(0) → 청구 주소 누락(0)… 100번 시도 후 우연히 성공. 근본 원인(Silver & Sutton, "Welcome to the Era of Experience", 2025): 현 RL 방법은 최종 성패만으로 학습하고 **환경의 풍부한 피드백에서 배우지 못함** — 상담원이 "카드 끝 4자리가 필요합니다"라고 명시핮도 RL은 "실패"만 보고 이유를 모름. 10스텝 중 9개가 완벽핮도 10번째 실패면 "전체 실패" 신호뿐.

**보상 패러다임의 진화** (DeepSeek, Liu et al. 2025 + 이 책이 vector 차원 추가): Scalar(7.2점 — 진단 불가) → Semi-scalar(강점/약점 분석 후 6.5점) → Vector(차원별: 정보 조회 정확도 9/10, 정보 수집 완전성 6/10, … 건강검진 리포트처럼 문제 정확히 위치) → **Generative**(자연어 상세 분석, 같은 실행을 여러 번 샘플링해 다각도 분석 — 한 번의 실패에서 개선 방향 학습, 수백 번 맹목 시행착오 불필요). DeepSeek 논문 결론: 생성형 보상 모델은 inference-time scaling(다수 평가 샘플링 후 집계)으로 평가 품질 지속 개선, 모델 크기만 키우는 scalar 방식을 여러 RM 벤치마크에서 능가. Bradley-Terry 판별형 RM(스칼라 점수)의 진화로 볼 수 있음 — 생성형 RM은 "왜 좋고 왜 나쁜가"를 추론과 함께 생성, 규칙으로 커버 어려운 개방형 태스크로 확장 쉬움.

보상 함수 선택: 코드 자동 검증 가능 → binary; 독립 품질 차원 다수 → vector; 고도로 개방형 → generative.

**Generative RM 훈련 3단계** (DeepSeek): ① 모델이 태스크별 평가 원칙 자동 생성 ② 원칙별로 실행 과정 평가 ③ 시스템이 평가의 정확성 자동 검증(모델이 "정확히 전달"이라 했지만 궤적상 틀리면 부정 피드백). 장점: 일반화("기준 설정과 평가"라는 메타 능력 학습), 투명성(편향 검토 용이 — "긴 답변=강점" 같은 오류 발견), 보상 모델과 정책 모델의 공진화.

### 7.10.3 Process Reward vs Outcome Reward
**PRM (Process Reward Model)**: 중간 스텝마다 채점. 대표작 OpenAI "Let's Verify Step by Step" (Lightman et al. 2023) — 스텝별 인간 주석으로 훈련된 PRM이 최종 답만 보는 지도보다 유의하게 우수. **ORM (Outcome Reward Model)**: 최종 결과만. RLVR의 규칙 검증기는 ORM의 특수 케이스.

Credit assignment 공학: **discount factor γ는 멀티턴 LLM RL에서 보통 1**(몇~수십 턴, 최종 성패가 목표라 할인 불필요). PPO는 GAE(가치 네트워크로 스텝별 "기대 대비 얼마나 나은가" 추정, bias-variance 가중 trade-off). GRPO는 극단: 전체 응답을 단일 행동으로 보고 궤적 수준 advantage를 모든 토큰에 균등 배분 — 2턴의 정확한 질문과 7턴의 무의미한 인사말이 동일 credit. 단기 단일턴에서는 문제 적지만 장궤적 멀티턴에서는 학습 신호 희석 → PPO+가치 네트워크가 멀티턴에서 여전히 가치 있는 이유. 중간 절충: **turn-level credit assignment**(턴 단위 advantage, 토큰 수준보다 싸고 궤적 수준보다 세밀).

- **실험 7-12 V-IRL** (Yang et al. 2024, PPO+value network): 실도시 스트리트뷰 시각 낸비게이션. 훈련 뉴욕 1000 경로, 테스트 9개 도시 18 경로. Rule 변형: 절대 방향 훈련 → 상대 방향 테스트. **Rule OOD: RL +11.0pt(V-IRL-L), SFT -79.5pt; V-IRL-VL에서 RL +9.3pt, SFT -33.2pt. Visual OOD: RL 16.7%→77.8%(+61.1pt)** — 오픈소스 모델의 end-to-end RL이 closed-source 강 모델의 정교 프롬프트 엔지니어링 baseline을 추월. Process reward(정답 +1, 오답 -1, 랜드마크 오인식 추가 -1.5)가 장시퀀스 credit 난이도 감소의 핵심. verify_iter=2 재시도로 샘플 효율·안정성 향상. SFT 과훈련 시 RL도 OOD 회복 불가 — **SFT는 "포맷 안정 + 기본 능력"까지만, 머물지 말 것**.
- **실험 7-13 SimpleVLA-RL** (GRPO, outcome reward): 로봇 VLA. 탐색 강화 3책: Dynamic Sampling(전성공/전실패 그룹 필터), Higher Clipping Bounds [0.8, 1.28], Higher Temperature 1.6 → 300 스텝 내 성능 ~30% 개선. LIBERO 벤치마크 97.6%. Cold-start: 태스크당 궤적 1개 SFT 17.3% → +RL 91.7% (+74.4pt, 상대 ~430%). **"pushcut" 출현** — 데모(접근→파지→수직 상승→수평 이동→해제) 대신 "접근→파지→낮게 유지→수평 푸시→완료"를 자기 발명. 상승 단계 제거로 속도↑ 정밀도 요구↓. RL이 모방학습을 넘어 인간 미고안 우수 전략 발견의 강력 증거. 비교: outcome reward는 탐색 자유 최대(pushcut 가능) / process reward는 수렴 가속이나 데모 공간 이탈 제약. **중간 스텝 정오 판정 쉬우면 process, 최적 경로 미지면 outcome.**

### 7.10.4 RLVP: Reward the Outcome, Penalize the Path (Li & Shi, 2026, arXiv:2607.07435)
문제: **outcome reward는 "과정이 규칙을 따라야 한다"를 표현 못 하고 오히려 위반을 유도.** Outcome-neutral constraints(성공과 무관한 규칙: 거부한 사용자 재전화 금지, 근무시간 외 자율행동 금지, 신원확인 생략 금지, rm -rf 금지, 테스트 파일 수정 금지, 안 읽은 파일 덮어쓰기 금지)는 위반하면 겉 성공률이 올라간다(지름길이 이득). Outcome-only 훈련 Agent는 거의 매 에피소드 선을 넘음.

핵심 통찰: **실환경은 "비대칭 검증기"** — 나쁜 행동 판정(파괴 명령 실행 등)은 명확·결정적이라 쉽고, 의미 있는 진전 판정은 태스크 풀기만큼 어려움. 환경이 신뢰성 있게 줄 수 있는 dense 신호는 본질적으로 "경로상 처벌"이지 "진전 보상"이 아님.

방법: R = O + β·Φ. O는 outcome reward(희소, 진짜 목표). Φ는 **결정적 규칙 엔진**이 행동별 부여하는 path signal(학습된 judge 모델이 아니라 행동+직전 상태의 순수 함수). Φ의 두 용도: **Penalty(−λ)**(기계 검증 가능 위반 행동마다 감점) + **Compliance Reward / Partial Credit(+μ)**(전제 조건 충족, 서브골 달성, 통과 테스트 증가 등 검증 가능한 좋은 행동마다 가점). 각각 별도 정규화 후 결합. PPO/GRPO 루프에 그대로 삽입(알고리즘 불변, 보상만 재형성).

**작동 원리 — 그룹 내 분산(within-group variance)**: GRPO는 그룹 G개 rollout의 상대적 위치가 advantage. 수학적 사실: **GRPO의 advantage는 본질적으로 그룹 내 분산 — 그룹 전원이 동일 보상이면 분산 0, advantage 0, gradient 없음**(그룹 전체 샘플 허공). Outcome-only에서 이 "zero-variance deadlock"은 훈련 초반(전실패 그룹: O 전부 0)과 후반(전성공 그룹: O 전부 1) 양극에서 필연 발생. 커뮤니티의 기존 답은 zero-variance 그룹 폐기(DAPO dynamic sampling). RLVP의 반전: **버리지 말고 빠진 분산을 복원할 dense 신호가 뭔가?** → 검증 가능 처벌은 항상 분산 복원(전원 실패핮도 실패 양상이 다름 — 파괴 명령 여부) = "항상 도달 가능한 절반". 진전 보상(Partial Credit)은 진전 도달 가능할 때만 분산 복원 = "도달 가능성 게이트 절반"(정리 증명의 "남은 goal 수 감소"는 도달 가능, 소프트웨어 수정의 "테스트 통과"는 종종 도달 불가).

**Use Case 1: 배포 가능성을 위한 경로 처벌 — 4대 설계 원칙**:
1. **검증 가능한 "행동"만 처벌, "진전 부족"은 절대 처벌 금지** — "진전 없음" 처벌은 "아무것도 안 하기"가 회피 최적해가 되므로 Agent에 무행동을 가르침.
2. **Outcome reward가 항상 주동력, 처벌 단독 최적화 불가** — 처벌만 있으면 최적 전략이 "무행동"(위반 0, 성공 0). 애블레이션: 순수 처벌은 모든 시드에서 성공률 0으로 붕괴.
3. **각 처벌(−λ)에 대응하는 compliance reward(+μ) 페어링** — "테스트 파일 수정" 감점 + "진짜 버그 고쳐 자연 통과" 가점. 봉쇄만이 아니라 출구를. +μ 제거 시 준수 행동 학습이 유의하게 느려지고 불안정.
4. **준수 경로 도달 가능 + 처벌 대상 게임 불가** — 소수의 스크립트 데모로 규칙 준수 방법을 먼저 보여주고, 위반 판정은 결정적 검사로(학습된 "준수 점수" judge면 게이밍 문제가 judge로 이동).

**Use Case 2: Partial Credit으로 샘플 효율** — 전실패 그룹에서 진전 도달 가능하면 +μ가 zero-gradient deadlock을 유용 gradient로. miniF2F(정리 증명) vs 소프트웨어 수정 비교: **핵심 변수는 신호 밀도가 아니라 도달 가능성(reachability)**. 훈련 전 베이스 모델 소수 rollout의 그룹 내 분산으로 도달 가능성 사전 진단 가능.

**RLVR vs RLVP**: 한 글자 차이가 상보성을 드러냄 — RLVR은 outcome 검증, RLVP는 process 추가 검증. 결합하면 "일을 끝내는 것"과 "제대로 하는 것" 모두.

**실험 7-14 결과**: Terminal-Bench (Qwen3-4B, 5 시드): 에피소드당 위반 3.71 → 0.66 (약 6배 감소), 태스크 성공률은 노이즈 범위 유지 — 준수가 거의 공짜, Agent는 행동을 줄인 게 아니라 **유효 행동을 더 많이** 함. miniF2F 대수: 0.9 성공률 도달 반복 7.0→4.4 (4B), 30B는 8.5→5.4(순수 outcome은 일부 시드 발산). 연쇄 파일 작업: 전실패 그룹 비율 65%→8%. 반례: 소프트웨어 수정(진전 도달 불가)에서는 이득 없음 확인.

## 7.11 툴 호출 RL
3단계 도전: Level 1 단일 툴 숙달(언제+어떻게+오류 처리) → Level 2 다중 툴 선택(수십 개 중 검색/코드/문서 선택) → Level 3 툴 체인 오케스트레이션(의존성 관리 + 상호 배타 제약 + 비용 최적화). 두 연구 라인: 검색 증강(Search-R1, Jin et al. 2025 — 고정 RAG 파이프라인이 아니라 RL로 검색 시점 자율 결정)과 소프트웨어 공학(SWE-Gym 등 실제 코드베이스 멀티턴 RL). 공통 도전: 장궤적 credit assignment + 환경 공학.

**Loss masking for environment feedback tokens** (핵심 엔지니어링 디테일): 툴콜 궤적에는 모델 생성 토큰(사고, 툴콜 파라미터)과 환경 반환 토큰(인터프리터 출력, 검색 결과)이 섞임. 후자는 정책이 생성한 게 아니므로 policy gradient에 포함하면 "샌드박스 출력 예측" 훈련이 돼 목표 이탈·불안정. 표준 관행: **환경 피드백 토큰은 loss 계산 시 마스킹**(ReTool의 interpreter 태그 난부 마스킹, Search-R1의 "masking retrieved tokens"). veRL, AWorld 등 주요 프레임워크 내장.

- **실험 7-15 ReTool**: 코드 인터프리터를 RL 사고 루프에 통합. SFT warm-up ~1시간(텍스트 추론 데이터→코드 보강 궤적) + RL(개조 veRL PPO, DAPO-Math-17k, 400스텝 ~9일). 스텝당 512 응답(32문제×16후보), 응답당 평균 7-9회 상호작용. AIME 2024: SFT baseline 25% → 110스텝 52% (Best-of-30 85%) → 400스텝 67.0%; 순수 텍스트 RL baseline은 1080스텝에도 40.0%. 출현 능력: 코드 자기 수정, 툴 사용이 후반 검증→초반 탐색으로 이동, 사고 효율(길이 -40%에 정확도↑). 110스텝 3단계 동역학: 초기(0-20) 툴 사용 급속 학습(스텝당 +0.5%) → 중기(20-70) 진동 탐색(길이 2500→4700 토큰) → 후기(70-110) 안정 수렴(4400으로 하락). SFT/RL 시간 차이의 근본: 정보 밀도(SFT는 토큰마다 지도, RL은 에피소드당 성패 하나).
  **DAPO (Yu et al. 2025) 4개선** (PPO 대비, 단일 전략 조기 수렴 방지): Clip-Higher(탐색 상한 완화 — 더 나은 경로 발견 시 과감 조정), Token-Level Policy Gradient Loss(샘플 수준 평균 제거, 배치 전체 토큰 균등 정규화 — 긴 고품질 CoT의 보상 희석/장황 반복의 처벌 희석 해소), Dynamic Sampling(성공률 20-80% "학습 가능 범위" 문제에 샘플링 집중), Overlong Reward Shaping(과도 장문 응답 소프트 페널티).
- **실험 7-16 AWorld-train**: MCP 서버 샌드박스(26 서버, 126 툴 함수: 웹 상호작용, 문서 처리, 멀티미디어, 코드 실행, Excel 29개 연산, 지식 검색). GAIA 벤치마크(대형 모델도 ~32%). Qwen3-4B로 완전한 "실전 학습" 파이프라인 종단 실행이 목표(기록 경신 아님). 분산 rollout 14.6배 가속(7일→12시간). 다중 툴의 질적 도약: "언제/어떻게" + "어느 툴/어떤 조합" — 조합 폭발, 전제 의존(검색 후 페이지 브라우징), 상호 배타, 비용 차이 하의 전체 계획.

## 7.12 샘플 효율 개선의 최전선
RL의 낮은 샘플 효율 근본 원인 중 하나: **주류 policy gradient의 model-free 성격** — 환경 동역학(world model)을 모델링하지 않고, 단일 피드백의 풍부한 정보(오류 이유, 누락 필드, 절차 힌트)를 대부분 낭비. 두 공격 경로: ① 환경 피드백의 낭비 정보를 명시적 기계 검증 신호로 보상 함수에 기록(RLVP) ② 매 스텝 신호를 dense하게 → **On-Policy Distillation**.

### 7.12.1 On-Policy Distillation (Thinking Machines Lab, 2025)
- SFT의 약점: **Learner-Sampler Mismatch** — 훈련 데이터는 샘플러(선생)가 생성, 학생은 정답 경로만 수동 모방. 학생이 스스로 실수해 off-distribution 상태에 들어가면 복구를 몰라 소오류가 누적(covariate shift).
- RL의 약점: **신호 희소** — on-policy로 분포 불일치는 해결하지만 궤적 끝 성패 스칼라 하나.
- On-Policy Distillation = **학생이 자기 궤적 생성(On-Policy) + 강한 선생이 학생 생성 토큰마다 dense 신호 제공(Dense)**. 한 줄 비교: SFT는 "off-policy + dense", RL은 "on-policy + sparse", On-Policy Distillation은 "on-policy + dense" — 양쪽 약점 해소.
- 메커니즘: 선생이 현재 위치의 다음 토큰 **완전한 확률 분포** 제공, 학생은 자기 예측 분포를 선생 분포에 근접(KL divergence 최소화). 최종 성패 이진 신호 대비 토큰 수준 분포 정렬이 한 자릿수 이상 dense.
- 결과: 수학 등 태스크에서 순수 RL 성능에 **약 1/10의 훈련 스텝**으로 도달. 장쇄 추론에서 가장 두드러짐. 과적합 완화(매번 다른 궤적 + 궤적 특정 피드백 → 특정 답이 아닌 일반 전략 학습, 데이터 재사용 훨씬 가능). 멀티턴 Agent 시나리오(성패 신호가 끝에 희소·지연)에서 특히 가치. 전제: 학생이 자유 탐색할 충분히 현실적인 시뮬레이션 환경(학생이 선생도 못 본 off-distribution에 들어가면 선생의 목표 분포도 신뢰 불가).
- 저자 실험(Agent의 시간 감각 훈련, Li & Shi 2026): DPO + 4개 RL 레시피가 각기 다른 실패 모드(희소성, 목표 불일치, rollout 형태 불일치, 훈련 붕괴)로 전부 SFT 천장을 못 넘음 → On-Policy Distillation(동결 Qwen3-32B 선생)은 매끄럽게 수렴, 4개 조건 모두 SFT baseline 대비 통과율 +23~47pt. **"post-training을 멈추게 하는 것은 보통 영리하지 못한 보상 함수가 아니라 밀도 부족한 신호다."**

### 7.12.2 On-Policy Self-Distillation (OPSD)
선생 없을 때: **같은 모델이 선생과 학생을 겸하되 컨텍스트만 다르게** (Zhao et al. 2026, arXiv:2601.18734). 선생 버전은 privileged information(정답, 검증된 풀이)를 보고 학생의 스텝을 토큰 단위로 rationalize한 목표 분포 생성. "답을 들고 설명하기"가 "독립 풀기"보다 훨씬 쉬움 — RLVR의 verification-generation asymmetry와 동형이지만 dense 신호 생산에 사용. RLVR 대비 장점: ① 검증 가능 보상 불필요(privileged 정보 소스가 넓음: 정답, 풍부한 시스템 프롬프트, 인간 데모, 도메인 문서) ② 신호 밀도. 경계: 선생 천장 = 학생 자신 → 이득 크기는 "privileged 정보가 가져오는 추가 능력"에 의존; naive OPSD 실패 모드(사고 스타일 상실 — Purified OPSD, Shen et al. 2026, arXiv:2607.02234).

## 7.13 전체 지형과 실전 팁
**상승 패러다임**: "형 선행, 신 후속" — SFT는 "포맷 안정 + 기본 능력"까지, 그 위에 RL로 전략. 단 SFT 과훈련은 훈련 분포 붕괴로 RL 최적화 공간 제한.

**흔한 함정 8가지**:
1. Post-training으로 사실 암기 시도 — 사실 지식은 RAG로(동적 갱신, 출처 추적, 훈련 손실 없음). Post-training은 "지식 사용법"에 집중.
2. 포맷 안정 전 RL 도입 — JSON 파싱 실패율 >20%면 RL 완전 실패. SFT 먼저.
3. 보상 함수 설계 불량 → reward hacking(길이만 본 보상 → 길고 무의미한 텍스트). 최종 목표를 평가할 것, 중간 지표 아님.
4. 시뮬레이션 충실도 무시 — 고충실도 환경 비용이 훈련 비용을 넘을 수 있음을 인지.
5. 과훈련으로 일반화 하락 — SFT 특히 취약, early stopping 중요.
6. 가치 함수 붕괴 + 탐색 부족 — PPO 가치 추정 부정확 시 advantage 편향, 곡선 진동; 온도 너무 낮으면 국소 최적.
7. RL 컴퓨트 비용 과소평가 — SFT로 잘 되는 태스크를 RL로 바꾸면 10-100배 시간. 테스트 분포가 훈련과 고도로 일치하면 SFT로 충분할 수 있음.
8. 저품질 훈련 데이터 — SFT는 노이즈·편향을 그대로 고착; RL도 보상 모델에 체계적 편향 있으면 잘못된 방향으로.
**핵심 원칙: 대규모 투입 전 소규모 실험으로 핵심 가정 검증. Better to fail fast than to fail at scale.**

**RAG/ICL/프로그램/Post-training 시너지**: ICL은 파라미터 변경 0으로 즉시 적응(컨텍스트 증가에 지연·비용↑). RAG는 동적 갱신·추적 가능한 외부 지식. Post-training은 고차원 지각·생성 스타일·암묵 의사결정 정책을 파라미터에. 선택 기준은 태스크 안정성만이 아니라 **그 능력이 외부 기호로 충분히 표현 가능한가**. 견고한 시스템은 조합: RAG가 사실·증거, ICL이 언어 표현 가능 전략의 신속 실험, 프로그램이 결정적 절차·하드 제약, post-training이 명시 표현 어려운 광일반화 능력.

## 7.14 챕터 요약 (저자 서술)
Post-training의 본질은 상호작용 전략을 파라미터에 쓰는 것. SFT와 RL은 경쟁 대안이 아니라 순차 단계. 기억할 두 판단: ① 데이터와 환경이 알고리즘보다 중요(환경 불가 시 모델 시뮬레이션 경로도 있으나 시뮬레이터 편향이 천장; 태스크 분포 자첫도 최적화 대상; SFT 데이터 충분 시 RL 불필요) ② RL의 현 주요 병목은 샘플 효율 — 유망한 두 방향은 On-Policy Distillation(신호 밀도화)과 RLVP(낭비되던 환경 피드백의 학습 신호화), 공통점은 "순수 outcome reward가 낭비하던, 환경과 데이터에 이미 존재하는 정보를 학습 가능한 것으로 되돌리기".

# Chapter 8. Continual Evolution of Agents — 지속 진화의 공학

## 8.0 문제 설정: 보존 ≠ 학습
오늘의 Agent는 미지의 복잡 태스크를 zero-shot으로 풀면서도, 비슷한 태스크를 만 번 처리한 뒤에도 첫날의 실수를 반복한다. 배포된 모델은 추론 후 파라미터가 자동 변하지 않고, 2장의 in-context 적응·압축은 태스크 내에서만 유효하며 컨텍스트가 끝나면 다음 태스크로 이어지지 않는다.

핵심 구분: **preserving experience is not the same as learning from it.** 궤적 100개를 긴 컨텍스트나 벡터 스토어에 넣으면 사례 검색은 되지만, 시스템이 능동적으로 평가·비교·일반화·검증하기 전에는 학습이 일어나지 않는다. 3장의 user memory가 "사용자와 세계가 어떤가"를 담는다면, 8장의 경험 학습은 "어떤 조건에서 무엇을 해야 하는가"를 담는다 — 전자는 더 많이 기억하게, 후자는 더 능숙하게 만든다.

매 태스크 후 직접 훈련하지 않는 이유: 프로덕션은 깨끗한 학습 신호를 거의 주지 않는다(사용자 만족 ≠ 준수, 테스트 통과 = 실패 케이스 삭제일 수 있음). 검증 안 된 피드백으로 실행 중인 모델이 스스로 수정하면 오류 경험과 prompt injection이 고착·증폭. 그래서 **모델 주위에 "학습"을 자율 시스템으로 구축**: 운영 증거 기록 → 결과·과정 검증 → 다수 궤적에서 공통 패턴 추출 → 지식/지시/프로그램/파라미터 중 어디를 갱신할지 결정 → 모든 수정은 candidate version이 되어 회귀 테스트·안전 검사 통과 후에만 다음 운영에 반영. 2장(태스크 내 상태), 3장(지식 인프라), 5장(툴 생성·시스템 수정 메타 능력), 6장(평가·검증), 7장(파라미터 갱신)을 조직하는 것이 8장.

## 8.1 운영 궤적에서 학습 신호 도출
지속 진화의 출발점은 "요약"이 아니라 **"평가"**. 태스크 완료 여부와 어느 스텝이 성패를 불렀는지 모륵는데 LLM이 생성한 반성은 추측일 뿐. 잘못된 평가가 장기 지식·시스템 프롬프트·훈련 데이터에 들어가면 효과가 누적된다.

**3층 검증 구조 (Figure 8-2)**: 하층 outcome verifier(테스트 결과, DB 상태, 툴 반환 → "태스크가 실제 완료됐는가") / 중층 process verifier(비즈니스 규칙, 권한, 행동 순서 → "허용된 방식으로 완료했는가") / 상층 quality verifier(Rubric 기반 언어·전략 평가 → "적절히 처리했는가"). 하층일수록 코드·환경 ground truth에, 형식화 어려운 것만 LLM에.

**정답이 없는 태스크**: LLM-as-a-Judge를 쓰되 모호한 총점이 아니라 **사전 정의된 Rubric으로 항목별 채점 + 궤적 증거 인용 + 증거 부족 시 불확실 명시**. 고객센터 Agent Rubric (Table 8-1): 태스크 결과 / 규칙 준수 / 프라이버시 경계 / 사실 신뢰성 / **promise-action consistency**(약속-행동 일치 — "환불 접수했습니다"라는 텍스트가 아니라 환불 툴 실호출·성공·주문 상태 변경을 대조; Agent 시나리오에 특히 적합) / 표현 품질 / **compliant alternatives**(원안 불가 시 허용된 대안 탐색 — 규칙 무시가 아니라 사용자의 진짜 목표 이해). 검증 결과는 스칼라가 아닌 **구조화 진단**(부분 성공 + 규칙 통과 + 근거 없는 진술 1건 + 허위 약속 1건 + 정책 설명 3회 반복)이어야 하류 모듈이 어느 부분을 고칠지 결정 가능.

LLM verifier도 캘리브레이션 필요: 전문가 주석 궤적 소수 세트로 차원별 일관성 점검, 고위험/저신뢰는 제2 모델 또는 인간 검토, 모델 버전 변경 시 캘리브레이션 세트 재실행. **평가자(verifier)와 수정 결정자(진화 모듈)를 분리** — 같은 모델이 심판이면서 규칙을 직접 고치는 것 방지.

**실험 8-1 (trajectory-verifier)**: 고객센터 궤적 → 구조화 진단. 정상 환불/허위 약속/프라이버시 노출/과잉 거절 4종 전문가 라벨. baseline(총점만) vs 실험(차원별 pass/fail/uncertain + 증거 + 신뢰도). 수용 기준: 치명 위반·허위 약속·과잉 거절의 안정 검출, 높은 총점이 프라이버시/정책 실패를 가리지 않을 것, 저신뢰/고위험은 자동 학습 신호화 금지.

## 8.2 지속 진화의 4가지 갱신 방법
선택 기준은 경험이 얼마나 오래됐나가 아니라 **목표 능력이 어떤 매체로 자연스럽게 표현되는가** (Table 8-2):
| 갱신 방법 | 적합한 내용 | 주요 장점 | 주요 한계 |
|---|---|---|---|
| 경험 지식 베이스 | 사실, 경험 패턴, 예외, 출처 | 빠른 갱신, 추적성, 온디맨드 검색 | 검색과 모델의 올바른 적용에 의존 |
| Prompt와 Skill | 언어로 명확히 표현 가능한 판단 원칙·운영 절차 | 해석 가능, 범위 통제 | 팽창, 충돌, 무시되기 쉬움 |
| 프로그램과 Harness | 결정적 절차, 툴, 하드 제약 | 테스트 가능, 안정 실행, 저비용 | 개발·유지 비용 |
| 모델 파라미터 | 고차원 지각, 생성 스타일, 암묵 전략 | 강한 일반화, 추론 오버헤드 낮음 | 갱신·회귀 비용 높음 |
상호 배타 아님: 의료 영상 Agent는 파라미터로 병변 식별 + 지식 베이스로 최신 가이드라인 + 코드로 위험 지표 계산.

### 8.2.1 경험을 지식으로 (Experience Knowledge Base)
3장과 저장·인덱싱·검색 기술 공유, 지식 출처와 검증 목적이 다름: "이 항공사는 특별식 24시간 전 예약 필수"는 도메인 지식, "예약 전 특별식 마감 확인 — 결제 후 불가 발견 방지"는 행동 경험.

**3층 데이터 구조**: 불변 원시 궤적(감사용) / 실행당 분석(결과와 후보 교훈) / 유사 궤적 간 비교·클스터링·귀납으로 만든 미래 지향 Markdown 지식 문서(적용 시나리오, 권장 전략, 금지 관행, 예외, 증거 출처, 최신 검증 시각 명시 — 단일 태스크 경과의 재서술 아님). 3장 User-as-Code와 같은 2단계 원칙: **증거 먼저 보존, 가변 지식은 오프라인 생성** — 단일 우연 성공이나 네트워크 장애가 즉시 Agent를 바꾸는 것 방지.

지식 증류 파이프라인 5단계: ① 불변 궤적+환경 결과 보존 ② 실행당 구조화 분석(태스크 유형, 필요 능력, 관찰 전략, 오류, 예외) ③ 태스크 패밀리별 집계, 후보 패털별 지지/반박 증거표 ④ 지지 임계 통과 후복만 정식 문서화 ⑤ 증류에 안 쓴 신규 태스크로 전이 평가. GAIA+AWorld 사례: 성공 궤적은 후보 전략, 실패는 배제 지식, 부분 성공은 어느 구간이 됐고 어느 구간이 아직 실패인지를 제공. Reflexion(Shinn et al. 2023, arXiv:2303.11366)의 자연어 반성은 후보 교훈 생성에 도움되지만 **반성 자체는 증거가 아님** — 환경 결과와 정합 + 궤적 간 지지 + 신규 태스크 양의 전이를 보인 것만 정식 문서로.

**실험 8-2 (gaia-experience)**: 궤적+environment_score 저장 → 최소 학습 레코드(task_family, applies_when, 전략, 오류, 예외, 출처 ID) → 같은 태스크 패밀리 내 경로 비교. 권장 전략은 **최소 2개 비실패 궤적의 지지** 필요. 3개 대조: 경험 없음 / 가장 유사한 단일 궤적 요약 / 다중 궤적 지지 지식 문서. 학습·전이 세트 분리 필수. 지표: 전이 태스크 성공률, 평균 검색 문자/토큰, negative-transfer rate, 모든 정식 결론의 출처 궤적 인용.

### 8.2.2 경험을 지시로 (Prompt & Skill)
경험 지식 베이스는 참고 자료, Prompt/Skill은 처방적(prescriptive). 다수 궤적에서 같은 전략 오류가 반복 + 자연어로 명확 표현 가능 → "참고할 경험"에서 "반드시 따라야 할 규칙"으로 승격. 거의 모든 태스크 적용 → 시스템 프롬프트; 특정 도메인/프로젝트/툴의 복잡 절차 → 온디맨드 Skill.

**Karpathy의 System Prompt Learning** (2025년 5월 X 포스트): pretraining은 지식, fine-tuning은 습관적 행동을 배우고, 인간에게는 문제 풀고 미래의 자신에게 명시적 노트("다음엔 이 방법부터")를 남기는 또 다른 학습이 있다 — 이런 노트북 없는 LLM을 영화 Memento 주인공에 비유. System Prompt Learning과 RL은 둘 다 경험으로 행동을 개선하지만 갱신 알고리즘이 다름(전자는 텍스트 편집, 후자는 경사하강). 예: "strawberry에 r이 몇 개?" 처리를 위한 Claude의 ~17,000단어 시스템 프롬프트의 단어/글자 수 세기 지시. Karpathy: 지식 유도 리뷰는 스칼라 보상보다 고차원 피드백 채널 → 데이터 효율 잠재력. 단 더 풍부한 정보가 자동으로 정확한 건 아님(한 사용자 피드백이 그 고객/구 정책에만 해당 가능) → 클러스터링, 범위 분석, 회귀 테스트 여전히 필요.

**자동 프롬프트 최적화 기존 방법**: DSPy (Khattab et al. 2023, arXiv:2310.03714 — 다중 LLM 호출 프로그램을 최적화 대상으로, 개발 세트에서 지시·예시 탐색), OPRO (Yang et al. 2023, arXiv:2309.03409 — 프롬프트·점수 이력에서 LLM이 신후보 제안), GEPA (Agrawal et al. 2025, arXiv:2507.19457 — 실패 궤적의 자연어 반성으로 상보적 후보 프롬프트 생성·선택). 이들은 오프라인 평가 세트의 배치 최적화; **프로덕션 minimal diff는 지속 유지보수** — 새로 관찰된 경계 사례로 트리거, provenance·감사·신속 롤백 설계. 실무: 오프라인 탐색으로 강한 초기 버전 → 롱테일 규칙은 건건이 패치.

신뢰할 개정 방식: 유사 실패 그룹에서 **minimal diff** 생성, 규칙 범위 명시, 기존 규칙과 충돌 검사, 실패 유발 경계 사례 + 구 태스크 유지(retention) 세트 양쪽 평가. 예: 항공 고객센터 Agent의 조기 에스컬레이션 → "정책 설명 → 사용자 실제 목표 파악 → 허용 대안 탐색 → 명시 요청 또는 권한 초과 시에만 에스컬레이션" 후보 패치. 안전 사고까지 계속 처리하면 회귀 실패.

**Skill 학습**: 후보 Skill은 최소한 로드 시점, 전제, 운영 절차, 알려진 함정, 검증 방법, 출처 궤적을 명시. 기존 Skill 라이브러리 먼저 검색해 같은 프로세스면 **local patch**, 정말 독립 능력일 때만 신규 디렉터리 — 이름만 다른 중복 매뉴얼 방지. Anthropic Skill Creator의 draft–test–evaluate–revise 루프가 "어떻게 만들고 개선하는가"를 다룸; 더 어려운 질문은 어떤 운영 증거가 생성을 트리거할 만한가, 충돌 해결, 도메인·구 태스크 회귀 통과 여부.

**실험 8-3 (prompt-auto-optimization)**: 릴리즈 게이트 4조건 — 비어있지 않은 패치, 추적 가능 provenance, 경계 세트 측정 가능 개선, retention 세트 무퇴화. 통과핮도 release_to_canary(안정 프롬프트 직접 덮어쓰기 절대 아님), 하나라도 실패면 reject_candidate.

### 8.2.3 경험을 프로그램으로
안정·반복·검증 가능한 작업은 모델이 매번 문서를 다시 읽고 추론하게 하는 것이 비효율 → **워크플로, 툴, Harness 코드로 컴파일**(일회 탐색을 반복 실행 가능 프로그램으로). 수정 대상: 운영 계층(브라우저 궤적→파라미터화 워크플로, API 어댑터), 제어 계층(툴 라우팅, 재시도, 서킷 브레이커, 컨텍스트 압축 전략), 검증 계층(파라미터 검사, 상태 검증기, 회귀 테스트), 아키텍처 계층(Reviewer Agent 추가, 계획-실행 정보 흐름 변경).

**브라우저 워크플로 라이프사이클 6단계**: ① 궤적 캡처(행동 파라미터 + URL + 요소 로케이터 증거 XPath/CSS/id/role/aria-label/data-testid — 로케이터 증거는 요소 재발견용이지 태스크 완료 증명 아님) ② 파라미터화(리터럴→템플릿 변수 {recipient}, {subject} …) ③ 상태 검사 정의(행동 전/후 검사 + 워크플로 전체 최종 상태 검사 — "발송 목록에 새 메시지 존재" 같은 실제 페이지/백엔드 상태) ④ 후보 검증(첫 성공은 candidate일 뿐 — 샌드박스 리셋 후 독립 초기 상태에서 전체 리플레이, 모든 검사 통과 시에만 validated; 부작용 태스크는 안전 리셋 없으면 프로덕션 반복 검증 금지) ⑤ 매칭·리플레이(의도·키워드로 검색, 파라미터 추출, Playwright 직행 — 단계별 LLM 호출 없음, 단 요소 대기와 모든 상태 검사는 수행) ⑥ 무효화·재학습(요소 못 찾음, 상태 검사 실패, API 스키마 변경, 최종 상태 오류 → 즉시 중단, 구버전은 invalid 영역으로, full Agent 신규 탐색 폴 백).

**PreAct (Li, 2026, arXiv:2606.17929)**: 반복 태스크에서 8.5-13배 종단 속도 향상, 리플레이 중 단계별 LLM 호출 불필요. 핵심: **before-action 검증 + after-action 검증 + 독립 사전 저장 검증** 없으면 위험한 환상 — 리플레이 커버리지 100%, 모든 버튼 클릭됨, 그러나 한 필드가 비어 태스크 미완료.

**Agent가 자기 코드를 수정** = 실행 프로세스가 직접 자신을 덮어쓰는 게 아니라: 안정 버전에서 candidate branch 생성 → Coding Agent가 minimal patch → 정적 검사, 단위 테스트, 보안 스캔, 실패 궤적 리플레이, 구 태스크 회귀 순차 통과 → canary 자격. 5장과의 경계: 5장은 시스템 수정 능력, 8장은 경험 트리거 + 검증 루프 제약의 자기 수정 방법.

**Falsifiable change contract** (Agentic Harness Engineering, Lin et al. 2026, arXiv:2604.25850): 각 수정 요청이 실패 증거, 추론 근본 원인, 책임 Harness 컴포넌트, 후보 변경, 개선 예상 행동, 퇴화 가능 기존 행동, 양쪽 테스트를 기록. 컴포넌트-경험-결정 수준 관측성: 모든 편집 가능 컴포넌트의 파일 수준 표현, 궤적 대량의 증거 증류, 편집 전 영향 예측 선언 후 다음 라운드 결과로 검증. **Self-Harness (Zhang et al. 2026, arXiv:2606.09498)**: 후보 생성기에 실패 사례만이 아니라 유지해야 할 성공 행동 + 이전 기각 수정 기록도 제공 — 전자는 "부수면 안 되는 것", 후자는 "같은 실패 아이디어의 다른 말 재제출" 방지.

**Alita (Qiu et al. 2025, arXiv:2505.20286)**: YouTube 360 VR 영상에서 골룸 성우 낭독 중 공룡 최초 언급 직후 숫자 → 자막 능력 부재 인식 → youtube-transcript-api 발견·테스트 → 새 자막 툴 래핑 → 정답 100000000 추출. 새 툴은 안전 스캔, 기능 테스트, 후속 태스크 재사용 성공 후에야 능력 라이브러리 입성. 4장(기존 툴 선택), 5장(툴 작성법), 8장(어떤 운영 증거가 생성을 트리거하고 새 툴이 검증된 장기 능력이 되는가).

**실험 8-5 (self-modifying-agent)**: retryable=false 오류 반복 호출 궤적 → 근본 원인을 retry/circuit-breaker 코드로 국소화. "프롬프트에 '반복 호출 금지' 한 줄 추가"는 잘못된 수정 계층의 개념 사례 — 결정적 강제 가능한 재시도 제약은 코드에. 패치 생성 Agent는 안정 코드, 검증기, 감사 로그, 자기 릴리즈 승인 게이트를 수정 못 함. 전부 통과핮도 release_to_canary만.

### 8.2.4 경험을 파라미터로
지식/지시/프로그램은 "목표 능력이 외부 기호로 비교적 완전히 표현 가능"이라는 전제 위에 있다. 의료 영상 이해, 자연스러운 억양, "AI 느낌" 제거, 장기 계획 같은 능력은 몇 개 규칙이나 워크플로로 압축 어려움 → 파라미터. **파라미터화 여부는 태스크 안정성만이 아니라 능력의 표현 본성이 결정** — 오래 안정적인 이체 승인 규칙도 파라미터 기억에만 의존 말고 서버 코드로 결정적 보장. 지속 진화 관점의 핵심은 **평가된 프로덕션 궤적을 훈련 데이터로 전환**: 고품질 데모→SFT, 명시 선호→쌍 데이터, 신뢰 환경 보상→RL. 훈련 전 개인정보 제거, 오류 궤적 필터, 독립 회귀 세트 유지; 훈련 후 일반 능력·안전 정렬 망각 점검.

### 8.2.5 갱신물에서 "갱신 방법"의 갱신으로 (Lilian Weng, "Harness Engineering for Self-Improvement", Lil'Log 2026)
직교 축: 산출물 내용 최적화 vs 산출물 생산·관리·검증 **방법** 최적화. 최적화 대상 확장: 개별 규칙/메모리 → 구조화 컨텍스트 → 워크플로 → Harness 코드 → 후보 생성 옵티마이저 코드. 5개 신규 매체가 아니라 5개 탐색 스케일.
- 가장 안쪽: 산출물 내용만 변경(실패 궤적 후 시스템 프롬프트에 지역 규칙) — blast radius 작고 귀인·롤백 쉬워 기본값. 모델에 매번 전체 재작성 시키면 "점점 간결하게" 쓰면서 희귀하지만 중요한 디테일 소실 → **ACE (Agentic Context Engineering, Zhang et al., ICLR 2026, arXiv:2510.04618)**: 컨텍스트를 안정 식별자 가진 엔트리 컬렉션으로 유지, generation/reflection/curation 모듈이 증분 업데이트 제안, 결정적 로직이 병합·중복 제거.
- 다음 층: 컨텍스트 내용이 아니라 **컨텍스트 구성 방법**. **MCE (Meta Context Engineering, Ye et al. 2026, arXiv:2601.21557)**: 난부 루프(주어진 관리 방법 하에 현 태스크 컨텍스트 최적화) + 외부 루프(다수 실행·검증 결과로 검색/선택/필터/포맷 같은 컨텍스트 연산 자체 수정).
- 워크플로·Harness: **AFlow** (Zhang et al., ICLR 2025, arXiv:2410.10762 — 다중 LLM 호출 워크플로를 코드 그래프로, 실행 피드백으로 노드·제어 흐름 조합 탐색), **Meta-Harness** (Lee et al. 2026, arXiv:2603.28052 — Coding Agent가 후보 Harness 소스, 점수, 궤적으로 정보 저장·검색·제시 코드 탐색). 코드+평가 이력이 일회 산출물이 아니라 지속 탐색 대상.
- **높은 층이 자동으로 더 좋지 않다**: 로컬 규칙 탐색은 엣지 케이스 몇 개, 워크플로/Harness 탐색은 거대 후보 공간·높은 평가 비용·어려운 귀인. 명확하고 반복되는 단일 컴포넌트 결함은 감사 가능 로컬 패치가 먼저. 로컬 변경이 교차 컴포넌트 문제에 반복 실패하거나 관리 방법 자체가 병목일 때만 외층으로. 모든 층에서 **평가자, 권한 경계, held-out 테스트는 편집 범위 밖** — 탐색 공간이 클수록 이 trusted root가 중요.

## 8.3 장기 운영의 지속 진화 폐쇄 루프
### 이중 루프 아키텍처 (Figure 8-5)
**온라인 실행 루프**는 태스크 완료와 증거 기록만(프로덕션 Agent 직접 재작성 안 함); **오프라인 진화 루프**가 궤적 집계, 근본 원인 진단, 후보 수정 생성, 검증 게이트 통과 후 신버전 릴리즈. 버전 관리된 경험 저장소와 평가 세트로 연결.

**Voyager (Wang et al. 2023, arXiv:2305.16291)** 완결 사례 (Minecraft): ① automatic curriculum(현재 인벤토리·환경·습득 스킬에서 적절 도전의 다음 목표 제안) ② skill library(성공 검증 프로그램을 검색·조합 가능 코드로 저장, 고급 스킬이 기초 스킬 호출) ③ iterative prompting(환경 관찰, 실행 오류, 자기 검증 결과를 다음 코드 생성에 피드백). 셋 모두 필수: 스킬 라이브러리 있으나 커리큘럼 없으면 다음에 뭘 배울지 모름; 자기 반성 있으나 환경 검증 없으면 스킬 라이브러리에 오류 누적; 탐색 있으나 지속성 없으면 매번 처음부터. 결과: 고유 아이템 3.3배, 이동 거리 2.3배, 기술 트리 마일스톤 최대 15.3배 빠름, 신규 월드로 스킬 라이브러리 전이. 이 지표들은 고정 Agent의 단일 시험이 아니라 **경험에 따른 능력 성장**을 측정.

### 8.3.1 진단 → 경험 고착
같은 표면 문제도 수정 형태가 다르다: 고객센터 Agent의 사실 날조는 지식 베이스 정보 부재일 수도, 프롬프트의 인용 요구 부재일 수도; 허위 약속은 지시로 고칠 수도, Harness가 응답-툴 상태 일치를 강제할 수도. **근본 원인 먼저, 가장 작고 검증·롤백 쉬운 수정 대상 선택.** 증거 불충분한 산발 실패는 즉시 학습 트리거 말고 사례 계속 수집. 경험 누적에 따라 매체 승격: 신규 전략은 경험 문서로 → 반복 검증 후 지식으로 → 자연어 명확 규칙은 Skill로 → 언어 이해 불필요 안정 절차는 툴 코드로 → 광범위 암묵 의사결정은 post-training으로.

### 8.3.2 검증, 릴리즈, 롤백
모든 수정은 프로덕션 덮어쓰기 아닌 **candidate**. 지식 문서는 신규 태스크 검색 개선 테스트; 프롬프트/Skill은 경계 사례 + 구 태스크 회귀; 프로그램은 샌드박스·리셋 환경; 파라미터는 망각·안전·OOD 평가. 검증 후에도 점진 릴리즈 + 실트래픽 모니터링 + 핵심 지표 악화 시 안전 버전 자동 롤백.

**Harness updating ≠ Harness benefit** (Lin et al. 2026, arXiv:2605.30621): updating은 궤적에서 가치 있는 지속 변경을 생산하는 능력, benefit은 태스크 Agent가 그 변경을 나중에 찾아·활성화·올바르게 사용하는 능력. Skill이 올바륵도 약한 태스크 모델이 적재를 못 하거나 장궤적에서 못 따륵면 최종 점수는 "진화 없음"처럼 보임 → 종단 성능만으로 updater 진단 불가. 층별 평가 지표 (Table 8-3): **candidate-change validity**(독립 검증 수용률·이득) / **artifact activation rate**(올바른 상황에서 신규 Skill/메모리/툴 로드?) / **successful adherence rate**(활성화 후 실제 준수?) / **held-out task gain**(진화에 안 쓴 태스크 개선?). **양방향 모델 스왑 진단**: 후보 Harness 고정 + 태스크 모델 교체(강한 모델만 이득 → 검색/라우팅 병목; 둘 다 활성화하나 강한 모델만 정확 실행 → 지시 수행/장기 계획 병목; 전원 퇴화 → 변경 자체 의심), 태스크 모델 고정 + updater 교체(updater 품질 직접 비교).

장기 평가 5종 관찰: **Regression**(신경험이 기존 경험과 충돌, 과거 성공 사례 실패화), **Generalization**(미커버 시나리오 개선), **Token efficiency**, **Safety**(규칙·프라이버시·거절 경계 drift), **장기 공학 품질**(유지보수 복잡성, 아키텍처 일관성, 소유 경계, 하위 호환, 마이그레이션·디버깅 비용). 현재 실패 케이스만 고치고 다른 곳을 망가뜨리면 성공적 지속 학습 아님.

### 8.3.3 검증 가능 루프의 경계: "완료" ≠ "진전"
이 루프는 코딩, 툴 사용, 비즈니스 상태 변경(테스트·환경 상태·결정적 규칙의 빠른 피드백)에서 가장 자연스럽다. 개방형 연구, 전략 기획, 복잡 제품 설계는 피드백 지연·정답 부재·가장 중요한 목표(연구 취향, 장기 가치, 유지보수성)가 즉시 점수화 곤란 → Harness가 프로세스를 완벽 실행하면서 결과처럼 보이는 것만 생산 가능.

**자율 연구 스트레스 테스트** (Trehan & Chopra, 2026, arXiv:2601.03315): 연구 아이디어→논문 종단 시도 4건 중 3건 실패. 실패 3군: ① **implementation drift**(제안 방법이 어려워지면 훈련 분포의 익숙한 구현으로 후퇴, 원래 가설 검증 안 됨) ② **epistemic over-optimism**(신호가 노이즈인데 설명·패치·발견 선언, 실패·음성 결과 무시) ③ **missing tacit judgment**(어느 baseline이 중요한지, 어느 이상치를 파고들지, 언제 가설을 버릴지 모름). 필요한 변화: **주장과 증거 분리**(인용·수치·방법·결론의 provenance 별도 기록 — ScientistOne Chain-of-Evidence, Meng et al. 2026, arXiv:2605.26340), **음성 결과 보존**(실패 실험·기각 후보·중단 사유를 성공과 동등한 검색 지위의 불변 로그로 — 아니면 진화 모듈이 생존자만 보고 반증된 경로 재방문), **탐색 다양성 보존**(최고점 체인만이 아니라 메커니즘·코드 신규성·가설 유형상 의미 있게 다른 저득점 분기 유지), **인간 개입 상향**(문제 정의, 평가 기준 검토, 이상 결과 해석, 중단 결정 — 모호 피드백 하에서 개별 실행 인수보다 자동화 어렵고 가치 큼). 일반 소프트웨어 공학도 마찬가지: 단위 테스트 전부 통과는 현재 관찰 가능 행동이 테스트를 만족한다는 것뿐, 수개월 후 유지보수성 증명 아님. **지속 진화의 천장은 시스템이 실제로 관심 있는 것을 평가할 수 있는가 — 측정 가장 쉬운 proxy가 아니라.**

### 8.3.4 안전 경계 3가지
자기 진화 능력은 단일 오류를 장기 리스크로 바꾼다: 웹·이메일·툴 출력의 prompt injection이 경험으로 요약되면 세션을 넘어 반복 발효; 자동 검색으로 찾은 악성 패키지가 툴로 래핑되면 영향 확산; 결함 verifier가 퇴화 후보를 계속 승인 가능.
1. **증거와 지시의 분리**: 원시 웹페이지·툴 출력은 신뢰 불가 증거 — Skill 등에 직접 기록 금지, LLM 요약 선행. 쓰기는 버전 관리 + PR 제출, 다른 출처의 reviewer LLM 검토 후 머지.
2. **후보 능력과 프로덕션 능력의 분리**: 신규 지식/프롬프트/Skill/프로그램/파라미터는 실트래픽 불가 후보 영역에. 신규 코드·외부 의존성은 샌드박스 실행, 권한 검토, 서플라이체인 스캔, 행동 테스트 등 보안 검사 + 회귀 통과 후에만 프로덕션.
3. **안전 메커니즘은 자기 수정 불가**: 비즈니스 Agent는 프롬프트/Skill/지식 베이스/툴 수정 가능하지만 자기 갱신을 승인하는 검증기, 테스트 케이스, 릴리즈 임계, 감사 로그, 안정 버전 백업은 수정 불가 — 아니면 테스트 임계 인하나 실패 케이스 삭제로 퇴화를 진전으로 위장.

### 8.3.5 Sleep Learning: 고착, 망각, 능력 유지
인지 과학적 비유(밤에 실행할 필요 없음). 온라인 Agent는 태스크 완료와 불변 증거 추가가 본분; 백그라운드 학습 프로세스가 유휴/게이팅 조건 시 신규 경험 배치를 읽고 신구 결론 비교, 중복 병합, 충돌 해소, 후보 갱신 제안, 회귀 실행. 수집과 조직의 분리로 우연 성공·네트워크 장애·악성 입력의 즉시 장기 능력 재작성 방지, 더 큰 배치와 싼 모델 사용 가능.

**Sleep learning 사이클 5단계**: ① Trigger(경과 시간/신규 궤적 수/스토리지/오류 빈도 임계 + 고우선 온라인 태스크 부재 확인) ② Orient(프로덕션 지식·프롬프트·Skill 디렉터리와 버전 읽어 기존 능력·불변 경계 파악) ③ Collect & consolidate(최근 평가 궤적의 신신호, 중복 병합, 충돌·적용 조건 표시, 로컬 패치 우선) ④ Validate & approve(전이·유지·안전 세트 평가, 고위험 쓰기는 인간 승인 대기) ⑤ Prune & index(검색 인덱스 갱신, 장기 미사용·신증거 반박 능력을 만료/아카이브/삭제 — provenance와 롤백 버전 유지).

실제 사례: **Claude Code auto memory** (Anthropic 문서 2026) — 프로젝트별 MEMORY.md 인덱스 + 주제별 상세 파일. 세션 시작 시 인덱스의 유계 접두어만 로드, 나머지 온디맨드. 인덱스 한계 접근 시 병합/이동 지시. 평문 메모리도 용량 제한, 층별 로딩, 능동 조직 필요. **Hermes** (Nous Research 문서 2026) — 유계 MEMORY.md/USER.md, SQLite/FTS5 세션 검색(요약 아닌 원문 반환으로 검색·생성 분리, 감사 가능), 온디맨드 Skill, 외부 메모리 프로바이더(Honcho) 옵션. 다수 툴콜, 오류/막다름 복구, 사용자 정정, 비자명 워크플로 발견 시 백그라운드 리뷰가 Skill 생성/지역 개정; 메모리·Skill 쓰기는 승인 게이트 가능. 별도 Curator가 Skill 사용량·노후·아카이브 상태 추적, 유휴 시 결정적 정리, 스냅샷 선행으로 오류 고착 롤백 가능. "기록–고착–검증–정리"의 운영 가능 능력 수명주기화.

**주기적 오프라인 고착**(2장의 context corruption이 장기 스케일로 재현 — 경험 문서 상충, 프롬프트 경계 규칙 과적, Skill 라이브러리 중복 누적, 반복 파인튜닝의 catastrophic forgetting): 중복 경험 병합(provenance·버전 유지), 지역 규칙을 글로벌 프롬프트에서 도메인 Skill로 이동, 프롬프트·Skill을 "신입 사원 핸드북"처럼 구조 유지("99개 철칙" 열거 금지), 장기 미사용 툴 재검증, 신증거로 무효화된 지식 삭제, LoRA는 원본 베이스에서 재훈련.

**실험 8-6 (self-evolution-eval)**: 세 장기 행동 구분 — 피드백 하나 저장 / 영원히 append만 / 진짜 갱신·전이·유지. 4단계 태스크 스트림: 학습(잠재 패턴 공유 태스크) → 전이(표현·사용자·환경 변경) → 규칙 변경(수하물 20kg→23kg, 구식 지식 교체/퇴역 요구) → 유지(불변 능력 재시험, 망각 측정). 대조군 static / append_only(첫 버전만 기억, 충돌 해소·퇴역 불가) / evolving(버전 저장, 신증거로 구 규칙 교체). 지표: 단계별 정확도·학습 곡선, 전이 정확도, 신규칙 회복 태스크 수, 구능력 유지, negative-transfer rate, 안전 Rubric 통과율, 토큰·지연·스토리지 비용 + candidate-change validity, artifact activation rate, successful adherence rate. 최종 정확도 높아도 퇴역 규칙 인용, 불안전 지름길 성공, 갱신 후 기존 능력 망각이면 지속 진화 아님.

## 8.4 챕터 요약
지속 학습은 Agent의 가장 중요한 능력 중 하나가 되고 있으나 오늘의 모델은 스스로 신뢰성 있게 수행 불가. 추론 중 컨텍스트 적응은 자동 지속되지 않고, 검증 없는 온라인 파라미터 갱신은 노이즈·공격·능력 drift 증폭. 현재 실용 경로는 **모델 주위에 검증 가능 학습 시스템 구축**: 상호작용·평가에서 학습 신호 획득 → 능력 표현 방식에 따라 지식/프롬프트/Skill/프로그램/파라미터 갱신 → 산출물 관리·생성 방법 자첫도 최적화 가능하나 귀인·검증·가역 가능 로컬 변경 우선 → 온라인 실행과 오프라인 학습 분리(온라인 증거 기록, 오프라인 후보 생성·검증, 점진 릴리즈·고착·롤백). 이 루프는 결과 자동 검증 가능할 때 가장 신뢰성 높고, 목표 모호·피드백 지연 개방형 태스크는 문제 정의와 평가 기준 설계에 사람 참여 필요.

### 실무 함의 (Agent 스킬/자동화 빌더 관점, Ch8)
- "저장 ≠ 학습": Aside 메모리/스킬 시스템도 로그 축적과 "평가→비교→일반화→검증→승격" 파이프라인을 분리해야 진짜 진화. 다중 궤적 지지(최소 2건) 임계 같은 승격 규칙을 명시하라.
- 프롬프트/Skill 개정은 전체 재작성이 아니라 minimal diff + provenance + retention 회귀 — 스킬 라이브러리 운영의 릴리즈 게이트로 직접 적용 가능(canary, reject_candidate).
- 반복 브라우저 작업은 PreAct식 워크플로 컴파일(파라미터화 + before/after/final 상태 검사 + 무효화 폴 백)로 8.5-13배 가속 — 단 상태 검사 없는 리플레이는 "클릭은 됐지만 태스크 미완료" 환상을 만든다.
- 능력의 매체 배분(지식/Skill/코드/파라미터)이 아키텍처 핵심 결정 — 규칙성 제약은 코드로 강제하고, 프롬프트 한 줄 추가는 잘못된 수정 계층인 경우가 많다.
- 안전 경계 3종(증거/지시 분리, 후보/프로덕션 분리, 안전 메커니즘 자기 수정 불가)은 자기 진화 시스템 설계의 최소 요건 — 검증기와 릴리즈 게이트는 절대 편집 범위 밖.
