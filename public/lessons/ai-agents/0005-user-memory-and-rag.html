Lesson 0005 · AI Agents in Depth

유저 메모리와 지식 베이스

메모리는 대화 전사(transcript)가 아니다. 반복 상호작용에서 사용자에 대한 간결한 예측 모델을 능동적으로 구축하는 과정이고, RAG는 그 지식을 꺼내 오는 파이프라인이다.

오늘의 한 줄 답: 세션을 넘는 지능은 두 층으로 만든다. 컨텍스트에 상주하는 소수의 구조화된 핵심 사실(개요)과 온디맨드로 정밀 검색하는 방대한 원본(디테일). 이 Two-Tier Memory Architecture가 Level 3 "능동적 서비스"의 유일한 실현 경로다.

1. User Memory vs Knowledge Base, 그리고 3단계 평가 프레임워크

Ch2가 단일 세션의 컨텍스트 관리였다면, Ch3는 세션을 넘나드는 영속 지식이다. 책은 이를 두 스케일로 나눈다. User Memory는 "나를 아는 개인 비서"(사용자별 선호·습관·제약), Knowledge Base는 모든 사용자가 공유하는 "도메인 전문가"(규제, 사내 절차, 전문 문서)다. 둘은 같은 기술(벡터 검색, 압축)과 같은 실패 모드(정보 충돌, 낡은 지식)를 공유한다.

메모리 능력은 무작정 쌓는다고 생기지 않는다. 책은 LoCoMo 벤치마크(평균 ~300턴 초장문 대화)를 바탕으로 에이전트용 3단계 평가 프레임워크를 제시한다.

Level 1 · Basic Recall
사용자가 직접 말한 명확한 정보의 저장·검색. "내 멤버십 번호는 12345."
Level 2 · Multi-Session Retrieval
다른 시점·세션에 흩어진 정보를 연결. 차가 두 대면 "내 차 정비"는 추측이 아니라 되묻기다.
Level 3 · Proactive Service
어시스턴트급의 리트머스. 국제선 예약 때 몇 달 전 저장된 여권 만료 임박을 먼저 경고한다.

좋은 메모리 추출의 3가지 특성: Selectivity("검색 결과 3개" 같은 일시 정보는 버림), Abstraction("창가 좌석"을 일반 선호로 정제), Structure(preference/restriction 같은 타입 태그).

실무 번역: Aside의 USER.md(안정 프로필)와 MEMORY.md(운영 디폴트) 계층은 이미 Selectivity·Abstraction이 적용된 메모리다. 질문은 이것이다: 지금 내 메모리 시스템의 목표 레벨은 몇 단계인가? Level 1이면 단순 노트로 충분하고, Level 2부터는 검색과 구조화가, Level 3는 Two-Tier가 필요하다. 목표 레벨을 먼저 정하는 것이 포맷 선택보다 앞선다.

2. 어디에 · 어떻게 · 무엇을: 계층과 4가지 저장 포맷

메모리 설계는 3개 독립 차원으로 분해한다. 저장 위치는 Trajectory(단일 실행의 append-only 완전 기록, "로그"), User Long-Term Memory(세션을 넘는 영속 저장소, "아카이브"), Business State(개발자 정의 태스크 단계)의 3층이다. 인지과학의 working memory ≈ trajectory, long-term memory ≈ LTM에 대응한다.

저장 포맷은 단순함과 표현력의 트레이드오프 위에서 4단계로 진화한다.

Simple Notes
원자적 사실 하나씩. O(1) 연산, 최소 비용. 단점: 사실 간 연관 상실 — 종합 질의에서 흩어진 낱알을 다시 조립해야 한다.
Enhanced Notes
완전한 문단으로 저장. 뉘앙스에 강하나 저장 중복, 갱신 복잡, 긴 문단은 임베딩 품질 저하.
JSON Cards
Category→Subcategory→Key-Value 중첩. 부분 갱신 쉬움. 단점: 경직된 분류가 차원을 소실시킴.
Advanced JSON Cards
사실 + backstory + person + relationship + timestamp. "Dr. Zhang"이 내 치과의사인지 아버지 심장내과인지 구별 — 엔티티 모호성 해결.

실무 선택 기준은 하이브리드다: 핵심·저빈도 데이터(선호, 핵심 인간관계)는 Advanced JSON Cards로, 대량·비핵심 사실은 Simple Notes로. 책의 실험(Exp 3-2)에서 Simple Notes는 기본 회상을 최저 비용으로 통과하지만 Level 2·3에서 실점했고, Advanced JSON Cards는 최고 성적이나 유지 호출 비용이 훨씬 컸다.

User as Code: 집계는 LLM 암산에 맡기지 않는다

텍스트 메모리의 근본 한계는 "저장"과 "사용"의 분리다. "올해 국제선 몇 번 탔지?" 같은 집계, 모순 탐지, 제약 강제가 전부 LLM의 암산에 달린다. User as Code(저자 논문)는 사용자 상태를 typed Python 객체(dataclass)로, 제약 규칙을 일반 함수로 인코딩한다. 검색 기반 메모리의 집계 정확도가 6–43%인 데 비해 코드는 거의 99%다 — sum(1 for t in trips if t.is_international) 한 줄이면 끝이기 때문이다. 갱신은 append-only fact log(memory phase) + 주기적 재구조화(structuring phase)의 2단계로, DB의 WAL + checkpoint 패턴이다.

실무 번역: 규제 준수(RISELAB의 PIF/CPNP 대상 수량)나 주문 관리(에바스코스메틱 발주 집계)처럼 집계·모순 감지·제약 강제가 필요한 도메인에서는 텍스트 메모리를 믿지 말 것. 6–43% vs 99%는 "느낌"의 차이가 아니라 쓸 수 있는가 없는가의 차이다.

3. RAG 스택: 청킹에서 리랭킹까지

RAG = retriever(관련 단편 검색) + generator(단편을 컨텍스트로 답변 생성). 리트리버 품질이 전체 효과를 결정한다. 스택은 다섯 층이다.

  1. 청킹(Chunking): Fixed-size(512토큰+오버랩), Recursive/Structure-Aware(자연 경계 재귀 분할, 프로덕션 기본값), Semantic(유사도 급락 지점 분할) 3전략. 출발점은 청크당 256–1024토큰, 오버랩 10–20%. 근본 결함은 단편이 원래 맥락에서 단절된다는 것.
  2. Dense Embedding: 의미 유사도를 벡터 거리로. Word2Vec(정적, 다의어 불가) → BERT(context-aware) → BGE-M3(다국어·장문)로 진화. ANN 인덱스는 ANNOY(빌드 빠름, 증분 갱신 불가) vs HNSW(증분 지원, 정확도 극상)로 갈린다.
  3. Sparse (BM25): 정확 일치에 탁월. k1은 TF 포화(20회 등장이 10회의 2배 관련은 아님), b는 문서 길이 정규화. "HTTP-403" 같은 식별자는 이쪽이 잡는다. 단, 동의어 이해 불가.
  4. Hybrid Fusion: 두 경로 병렬 recall 후 융합. 점수 분포가 달라(cosine 0–1 vs BM25 0–수십) RRF(Reciprocal Rank Fusion) — 원점수 버리고 순위만 score=Σ1/(k+rank)으로 합산하는 게 간단·견고하다.
  5. Cross-Encoder Reranking: 쿼리+문서를 하나로 연결해 심층 매칭. 느리지만 정확 — 상위 50개만 재채점. 서류 스크리닝(bi-encoder) 후 심층 면접(cross-encoder)이다.

측정 지표 3종: recall@k(top-k 안에 정답이 있는가 — RAG의 핵심 요건), MRR(첫 관련 문서 순위의 역수), nDCG(순위·관련도 모두 고려). "retrieval failure rate"는 top-20 미스율 ≈ 1−recall@20.

4. Naive RAG는 왜 구조적으로 실패하는가

책의 두 사례가 핵심이다. 흑묘백묘 문제: 100개 독립 사례(흑묘 90/백묘 10)에서 "비율은?"을 물으면 top-k 절단으로 대부분이 검색되지 않는다. 검색의 본질은 "가장 관련된 몇 개"인데 통계 질문은 "전체 카운팅"이기 때문이다. Xfinity 할인 문제: 퇴역군인 성공/의사 성공/교사 거절 3개 사례뿐일 때 간호사 문의는 "간호사-의사" 의미 유사도로 의사 사례만 검색되어 오추론한다. 핵결은 같다: 인덱싱 단계에 LLM 컴퓨트를 투입해 사전에 요약·규칙을 추출해 두어야 한다("전체 100마리: 흑묘 90", "할인은 퇴역군인·의사만").

RAPTOR (트리)
청크를 클러스터링→LLM 요약→재귀, 디테일(잎)→일반화(뿌리) 지식 트리. "거시 개념 → 드릴다운" 탐색에 강하다.
GraphRAG (그래프)
entity-relationship 트리플의 지식 그래프. multi-hop 추론("내 의사의 병원 주소는?")과 엔티티 구별에 강하다. 단, 트리플 변환 시 조건·시간 의존성이 소실된다.
Filesystem Paradigm
OpenViking: 모든 지식을 디렉터리/파일 URI로. L0(~100토큰 요약)/L1(~2000토큰 개요)/L2(전문) 3층 온디맨드 로딩 — 대부분 쿼리는 L1에서 해결.

Filesystem paradigm의 숨은 전제: 파일 간 링크와 인덱스 페이지다. 강한 모델도 자발적으로는 고립 파일만 append하기 쉬우므로, 지식 작성 프롬프트에 "신규 엔트리 추가 시 기존 관련 엔트리를 검색·링크하고 인덱스를 갱신하라"를 명시해야 지식 네트워크가 형성된다. 거버넌스 원칙 하나 더: 멀티유저 환경에서 권한 필터링은 리콜 후 심사가 아니라 검색 레이어에서 — 민감 콘텐츠가 일단 LLM 컨텍스트에 들어가면 유출을 보장할 방법이 없다.

5. Agentic RAG와 Contextual Retrieval, 그리고 Two-Tier

Agentic RAG는 검색을 에이전트가 언제든 호출하는 툴로 캡슐화하고, ReAct 루프로 분해→검색→평가→재검색을 주도한다. 책의 실험(Exp 3-9, 중국 사법 QA)에서 단순 질문은 전통 RAG와 동등하지만, 복합 질문("만취+과실치상+절도 전과의 양형은?")에서는 Agentic이 2차 정밀 쿼리("누범", "수죄 병합")를 스스로 발사해 격차를 벌렸다. 가치는 "질의응답"이 아니라 "문제 해결"에서 나온다.

Contextual Retrieval(Anthropic)은 청킹의 맥락 단절을 원천 수리한다: 벡터화 전에 LLM이 짧은 접두사 요약("[ACME 2025 Q2 재무 보고서 핵심 지표 섹션 발췌]")을 붙인다. BM25에는 정확 매칭 키워드를, dense에는 의미 배경을 동시 공급. Anthropic 데이터로 retrieval failure rate가 BM25 결합 시 49% 감소, reranker 결합 시 67% 감소. 비용은 인덱싱 시 LLM 호출이나 prompt caching으로 토큰당 약 $1 수준.

이 모든 것이 Two-Tier Memory Architecture로 수렴한다: Advanced JSON Cards(핵심 사실 소수, 컨텍스트 상주 = "개요") + Contextual Retrieval(원본 대화에서 온디맨드 정밀 조회 = "디테일"). 상주만으로는 용량 한계로 디테일을 잃고, 검색만으로는 전역 시야가 없어 교차 세션 연결을 놓친다. Level 3의 실제 절차: ①JSON 카드 팩트 리뷰(도쿄 여행+여권) → ②연관 추론(출발 1월 vs 만료 2월) → ③원본 대화 검색으로 검증 → ④능동 제안.

실무 번역: Aside의 메모리 파일들(USER.md, MEMORY.md, 프로젝트별 md)은 Two-Tier의 "상주 층"이고, memory_search가 "온디맨드 층"이다. 이 구조를 의식적으로 유지할 것 — 상주 층이 비대해지면 컨텍스트를 먹고, 온디맨드 층에 링크·인덱스가 없으면 검색이 고립 파일 더미를 헤맨다.
