Lesson 0009 · AI Agents in Depth

포스트트레이닝과 에이전트의 지속 진화

대부분의 에이전트 문제는 모델 문제가 아니라 하네스 문제다. 그래도 모델을 건드려야 할 때가 온다 — 그때 SFT는 "형"을 잡고 RL은 "신"을 넣는다. 그리고 진짜 진화는 저장이 아니라 검증된 승격 루프다.

오늘의 한 줄 답: 포스트트레이닝의 선택 기준은 단 하나의 프레임워크로 수렴한다 — 언어로 표현 가능한 판단은 프롬프트/스킬에, 결정적 절차는 코드에, 표현 불가능한 암묵 능력만 파라미터에. 그리고 어떤 매체를 고치든 "평가 → 후보 생성 → 검증 게이트 → 점진 릴리즈" 루프 없는 갱신은 진화가 아니라 drift다.

1. 두 개의 대원칙

7장 전체는 두 문장으로 압축된다. 첫째, "SFT memorizes, RL generalizes" — 같은 예산에서 SFT는 데모의 답을 암기해 환경이 바뀌면 물너지고, RL은 전이 가능한 전략을 배운다. 둘째, "Data and environment matter more than algorithms" — 성패를 가르는 것은 PPO냐 GRPO냐가 아니라 ① 베이스 모델(prior) ② 환경 충실도 ③ 데이터 품질이다. 우선순위는 prior > environment > algorithm.

첫째 원칙은 슬로건이 아니라 통제 실험이다. GeneralPoints 실험(Chu et al., 2025)에서 24점 카드 게임의 규칙을 바꿔 테스트(훈련 J/Q/K=10 → 테스트 11/12/13)하자, SFT를 이어간 모델은 -8.1pt(11.5→3.4)로 붕괴한 반면 RL로 전환한 모델은 +3.5pt(11.5→15.0)로 상승했다. 시각 변형(검정 수트 → 빨강 수트)에서는 격차가 더 벌어져 RL +17.6pt vs SFT -9.9pt. arXiv:2501.17161

SFT (Supervised Fine-Tuning)
"표준 답을 통째로 외우기" (mass-covering). 포맷·스타일·프로토콜 고착에 강하다. 샘플 효율 높음(수천 개). 천장은 시연자의 수준.
RL (Reinforcement Learning)
"보상이 가리키는 최적 mode에 집중" (mode-seeking). 전이 가능한 전략 학습. 샘플 효율 낮음(SFT의 10-100배 비용). 천장이 태스크 자체.
왜 RL의 천장이 더 높은가
① online이라 데모에 없는 전략 발견 가능 ② 검증이 생성보다 쉬움(verification-generation asymmetry) ③ 자기 궤적 위에서 훈련해 실수 복구를 배움.

2. 선택 프레임워크: 언제 무엇을 하는가

책이 제시하는 실무 결정 순서는 냉정하다:

  1. Post-training이 정말 필요한가? 하네스 엔지니어링(프롬프트, 도구 설계, 컨텍스트 관리)으로 풀리면 학습 불필요. 대부분의 에이전트 애플리케이션이 여기 해당한다.
  2. 필요하면 SFT 먼저. 출력 포맷·프로토콜·스타일을 파라미터에 고착한다. JSON 파싱 실패율이 20%를 넘는 상태에서 RL을 돌리면 보상 함수가 성패조차 판별 못 해 완전 실패한다 — 이것이 "형 선행, 신 후속(SFT first, then RL)"의 이유.
  3. SFT로 부족하면 RL 추가. 실용 테스트: "데모를 더 추가핮도 신규 시나리오 성능이 안 오륨녀 RL 전환 시점" — 근본 원인이 데모 수가 아니라 SFT의 최적화 목표 자체이기 때문이다.

주의할 대칭 사실: SFT 데이터가 충분히 좋으면 RL이 아예 필요 없는 경우도 많다. RL은 SFT의 10-100배 비용이다. Anthropic이 2025년까지 대량 고품질 SFT + RLAIF 중심으로 코딩 모델을 만들었던 것이 증거다. "Data decides how far you can go; RL decides how much higher."

실무 번역: Aside 스킬을 만들고 있다면 당신은 이미 "파라미터 대신 프롬프트/스킬 매체를 택한" 것이다. 스킬 설명을 아무리 다듬어도 모델이 특정 판단을 못 한다면, 그 능력이 "언어로 완전히 표현 가능한가"를 먼저 물어라. 표현 가능한데 안 따라오면 스킬 문제, 표현 자체가 불가능하면(미묘한 문체, 고차원 지각) 그때가 파인튜닝 검토 시점이다.

3. 보상 설계: RL의 진짜 어려움

알고리즘 지도는 간단하다 — PPO(가치 네트워크로 세밀한 credit, 장궤적 멀티턴에 유리), GRPO(같은 문제 N개 응답을 그룹 내 상대 비교, 가치 네트워크 불필요, 단일턴에 유리), DPO(선호 쌍을 직접 분류 loss로, 극도로 간단하나 오프라인이라 탐색 불가). 책의 조언: "아무거나 핮도 됨 — 알고리즘에 먼저 매달리지 말 것."

진짜 어려움은 보상이다. 세 가지 함정:

  • Reward model over-optimization (Gao, Schulman, Hilton 2023): RL이 진행되면 RM 점수는 계속 오르지만 진짜 품질은 상승 후 하락한다. 모델은 더 잘 답하는 법이 아니라 RM이 고득점을 주게 만드는 법(장황함, 아부)을 배운다. Goodhart's Law. 완화책은 KL penalty와 early stopping.
  • PRM vs ORM: 중간 스텝마다 채점하는 Process Reward(OpenAI "Let's Verify Step by Step")가 최종 결과만 보는 Outcome Reward보다 credit assignment에 유리하지만, 중간 스텝의 정오를 판정하기 어려운 태스크(최적 경로를 모르는)에서는 outcome이 탐색 자유를 준다. SimpleVLA-RL 로봇 실험에서 outcome reward로 훈련한 모델이 인간 데모에 없던 "pushcut" 동작을 자기 발명했다.
  • Outcome-only는 규칙 위반을 유도한다: 성공과 무관한 제약(거부한 사용자 재전화 금지, rm -rf 금지)은 위반하는 쪽이 지름길이라 겉 성공률이 오른다. 책의 RLVP 처방: "Reward the outcome, penalize the path" — 결정적 규칙 엔진으로 검증 가능한 위반 행동마다 감점 + 준수 행동마다 가점. 4원칙: ① 검증 가능한 "행동"만 처벌("진전 부족" 처벌은 무행동을 가르침) ② outcome reward가 항상 주동력 ③ 처벌마다 대응하는 준수 가점 페어링 ④ 준수 경로가 도달 가능해야.

엔지니어링 디테일 하나: 툴콜 궤적 훈련 때 환경 피드백 토큰은 loss masking한다. 인터프리터 출력은 모델이 생성한 게 아니므로 policy gradient에 넣으면 "샌드박스 출력 예측"이라는 이상한 목표를 학습하게 된다.

4. On-Policy Distillation: 두 세계의 장점 결합

SFT
off-policy + dense. 선생 궤적만 모방해 자기 실수에서 복구를 모름(covariate shift).
RL
on-policy + sparse. 자기 궤적에서 배우지만 신호가 궤적 끝 성패 스칼라 하나.
On-Policy Distillation
on-policy + dense. 학생이 자기 궤적을 생성하고, 선생이 학생이 생성한 토큰마다 목표 확률 분포를 제공. 순수 RL 성능에 약 1/10 스텝으로 도달.

저자의 시간 감각 에이전트 실험에서 DPO + 4개 RL 레시피가 각기 다른 실패 모드로 SFT 천장을 못 넘은 반면, On-Policy Distillation은 매끄럽게 수렴해 통과율 +23~47pt를 기록했다. 책의 결론: "post-training을 멈추게 하는 것은 보통 영리하지 못한 보상 함수가 아니라 밀도 부족한 신호다."

5. 8장: 보존 ≠ 학습 — 지속 진화의 공학

오늘의 에이전트는 비슷한 태스크를 만 번 처리하고도 첫날의 실수를 반복한다. 궤적 100개를 벡터 스토어에 넣으면 검색은 되지만, 시스템이 능동적으로 평가·비교·일반화·검증하기 전에는 학습이 일어나지 않는다. 3장의 user memory가 "사용자와 세계가 어떤가"를 담는다면, 8장의 경험 학습은 "어떤 조건에서 무엇을 해야 하는가"를 담는다 — 전자는 더 많이 기억하게, 후자는 더 능숙하게 만든다.

학습 신호의 출발점은 "요약"이 아니라 "평가"다. 3층 검증 구조: 하층 outcome verifier(테스트 결과, DB 상태 → "완료됐는가"), 중층 process verifier(비즈니스 규칙, 권한 → "허용된 방식인가"), 상층 quality verifier(rubric → "적절했는가"). 그리고 평가자(verifier)와 수정 결정자(진화 모듈)를 분리한다 — 같은 모델이 심판이면서 규칙을 고치는 것을 막기 위해.

6. 4대 갱신 매체와 승격 사다리

경험 지식 베이스
사실, 경험 패턴, 예외. 빠른 갱신·추적성. 단 검색과 올바른 적용에 의존. 권장 전략은 최소 2개 비실패 궤적의 지지 필요.
Prompt & Skill
언어로 명확히 표현 가능한 판단 원칙·운영 절차. 해석 가능하나 팽창·충돌·무시되기 쉬움. Karpathy의 "System Prompt Learning".
프로그램 & Harness
결정적 절차, 도구, 하드 제약. 테스트 가능·저비용 실행. PreAct식 워크플로 컴파일은 반복 태스크를 8.5-13배 가속.
모델 파라미터
고차원 지각, 생성 스타일, 암묵 전략. 강한 일반화·낮은 추론 오버헤드. 갱신·회귀 비용 최고.

선택 기준은 "경험이 얼마나 오래됐나"가 아니라 "목표 능력이 어떤 매체로 자연스럽게 표현되는가"다. 매체 간 승격 사다리: 신규 전략은 경험 문서로 → 반복 검증 후 지식으로 → 명확한 규칙은 스킬로 → 안정 절차는 코드로 → 광범위 암묵 의사결정만 post-training으로. "프롬프트에 '반복 호출 금지' 한 줄 추가"는 잘못된 수정 계층의 전형이다 — 재시도 제약처럼 결정적 강제가 가능한 것은 코드에 둬야 한다.

개정 방식도 정해져 있다: 전체 재작성이 아니라 유사 실패 그룹에서 minimal diff를 생성하고, provenance를 남기고, 기존 규칙과 충돌 검사를 하고, 경계 사례 세트(개선 확인)와 retention 세트(퇴화 확인) 양쪽을 평가한다. 통과핮도 안정 버전을 덮어쓰지 않고 release_to_canary. Voyager(Minecraft)는 이 루프의 완결 사례다 — 자동 커리큘럼 + 스킬 라이브러리 + 환경 검증 피드백으로 신규 월드에서도 스킬이 전이됐다. arXiv:2305.16291

7. 이중 루프와 안전 경계

장기 운영의 구조는 이중 루프다: 온라인 실행 루프는 태스크 완료와 증거 기록만 하고(프로덕션 에이전트를 직접 재작성하지 않음), 오프라인 진화 루프("sleep learning")가 유휴 시간에 궤적을 집계해 후보 수정을 만들고 검증 게이트를 통과시킨다. 수집과 조직의 분리가 우연한 성공·네트워크 장애·악성 입력이 즉시 장기 능력을 재작성하는 것을 막는다. Claude Code의 auto memory, Hermes의 Curator가 이 패턴의 제품화다.

  • 증거와 지시의 분리: 원시 웹페이지·도구 출력은 신뢰 불가 증거 — 스킬에 직접 기록 금지, LLM 요약 선행.
  • 후보와 프로덕션의 분리: 신규 지식/스킬/코드는 샌드박스 검증과 회귀 통과 전까지 실트래픽 불가.
  • 안전 메커니즘은 자기 수정 불가: 검증기, 테스트 케이스, 릴리즈 임계, 감사 로그는 편집 범위 밖. 아니면 테스트 임계 인하로 퇴화를 진전으로 위장한다.
실무 번역: 당신의 Aside daily routine들은 이미 "온라인 실행 루프 + 루틴 메모리"를 갖고 있다. 여기에 빠진 것은 8장식 승격 규칙이다 — 루틴 메모리에 뭔가가 쌓일 때 "최소 N건의 지지 증거 + 검증 통과 전에는 행동 규칙으로 승격하지 않는다"는 임계를 프롬프트에 명시하라. 그리고 매주 한 번의 "sleep learning" 점검(중복 병합, 무효화된 지식 퇴역)이 append-only 축적과 진짜 진화를 가른다.

9. 미니 실습 (10분)

당신이 운영 중인 워크플로 하나를 골라(예: daily 영상 제작 루틴, 판매현황 동기화) 최근에 "개선하고 싶었던 동작" 하나를 떠올리고, 아래 표를 채워 보자.

  1. 그 개선이 어떤 매체에 속하는가: 지식 / 프롬프트·스킬 / 프로그램·코드 / 파라미터 — 선택 근거 한 줄 ("이 능력은 ___로 완전히 표현 가능/불가능하기 때문에")
  2. 지금 그 개선의 "학습 신호"는 어디서 오는가 — 검증된 평가인가, 그냥 느낌인가
  3. 승격 임계를 하나 정하라 (예: "같은 실패가 3번 관찰되고, 수정 후보가 회귀 체크를 통과하면 스킬에 반영")

막히면 에이전트에게 이 레슨의 4대 갱신 매체 표를 기준으로 같이 분류해 달라고 하면 된다.
