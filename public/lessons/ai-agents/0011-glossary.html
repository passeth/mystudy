Reference 0001 · AI Agents in Depth

용어 글로서리

전 10챕터의 핵심 용어를 EN-KR로 압축. 레슨을 읽다 막히는 용어가 나오면 여기부터. 모든 레슨은 이 정의를 따른다.

Ch1-2 · 에이전트와 컨텍스트 기초

Agent
LLM + Context + Tools의 조합으로 목표를 향해 자율 행동하는 시스템. 모델이 아니라 '모델을 감싼 루프'가 본체.
Harness (하네스)
모델 바깥에서 모델을 Constrain/Verify/Correct하는 모든 엔지니어링 계층. Prompt ⊂ Context ⊂ Harness ⊂ Loop 중첩 구조의 최상위 실천.
ReAct loop
Reasoning + Acting. 생각( thought ) → 도구 호출( action ) → 관찰( observation )을 반복하는 에이전트의 기본 루프.
Context engineering
모델에 들어가는 working set 전체(시스템 프롬프트, 도구 정의, 메모리, trajectory)를 설계하는 일. 에이전트 능력의 천장.
Message roles (4종)
system / user / assistant / tool. API는 stateless — 매 턴 전체 대화를 다시 본내는 구조.
KV cache
이전 토큰의 Key/Value를 재사용하는 추론 캐시. prefix가 바뀌면 무효 → 컨텍스트 앞부분을 안정적으로 유지해야 비용·지연이 줄는다.
Prompt cache
API 제공자 레벨의 캐시(캐시 히트 시 입력 토큰 ~1/10 가격). 아키텍처 제약으로 취급해야 한다.
Chat template
API 메시지 배열이 모델 토큰 시퀀스로 변환되는 형식. 캐시 경계를 이해하는 단위.
Agent Skills
도메인 능력의 조합 가능 단위. progressive disclosure(메타데이터 → 본문 → 리소스) 3계층으로 로드. description은 라우팅 규칙.
Progressive disclosure
필요할 때 필요한 만큼만 컨텍스트에 올리는 설계 원칙. 스킬, τ-bench, 도구 발견에 공통 적용.
Agent status bar
진행 상황·환경·시간 같은 메타정보를 코드가 유지해 컨텍스트에 주입하는 장치. false authority 주의.
Context compression
길어진 trajectory를 요약·계층화해 working set에 넣는 전략. 6전략 비교와 5계층 hierarchical compression이 책의 핵심.
Sub-agent isolation
압축 대신 컨텍스트를 분리: 하위 작업을 별도 컨텍스트의 서브에이전트에 위임하고 결과만 가져온다.

Ch3 · 메모리와 RAG

User memory vs Knowledge base
개인 비서(사용자 모델링) vs 도메인 전문가(사실 검색). 기술 스택과 실패 모드를 공유한다.
메모리 3단계 평가
Basic Recall → Multi-Session Retrieval → Proactive Service. LoCoMo 벤치마크로 측정.
Episodic / Semantic / Procedural
인지과학의 메모리 3분류. 사건 / 사실 / 절차. 에이전트 메모리 설계의 분류 기준.
Mem0
대화에서 ADD/UPDATE/DELETE/NOOP 연산으로 메모리를 갱신하는 프레임워크.
Chunking
문서를 검색 단위로 나누는 전략(고정 길이/구조 기반/의미 기반). RAG 품질의 1차 변수.
Dense vs Sparse embedding
의미 유사도(BGE-M3 등) vs 키워드 정합(BM25). 하이브리드가 실무 기본값.
RRF + Reranking
Reciprocal Rank Fusion으로 dense+sparse를 합치고, cross-encoder reranker로 정밀 재순위화.
recall@k / MRR / nDCG
검색 품질 지표 3종. 재현율 / 첫 정답 순위 / 순위 가중 적합도.
RAPTOR / GraphRAG
계층 요약 트리 / 지식 그래프 기반 structured indexing. naive flat RAG의 실패를 넘는 두 경로.
Agentic RAG
검색 자체를 ReAct 루프의 도구로 둔 패러다임. 쿼리 작성·재검색·근거 검증을 에이전트가 수행.
Contextual Retrieval
Anthropic 기법. 청크에 문맥 문장을 붙여 임베딩 — 실패율 49%(+rerank 67%) 절감 보고.

Ch4-5 · 도구와 코딩 에이전트

ACI (Agent-Computer Interface)
도구 설명·파라미터·반환 형식의 인터페이스 설계. '설명의 기술'만으로 성공률 72%→90% 사례.
MCP (Model Context Protocol)
도구 연결 표준 프로토콜. 생태계 이점 vs 컨텍스트 오버헤드(수만 토큰)·보안 리스크.
Lethal Triad
비신뢰 입력 + 민감 데이터 접근 + 외부 통신 능력이 겹칠 때 prompt injection이 치명적이 되는 조합.
Idempotency (멱등성)
같은 호출을 반복핀데도 부작용이 한 번만 생기는 성질. 재시도 가능한 도구의 전제.
Event-driven agent
Cron/Heartbeat/Webhook 등 트리거로 깨어나는 비동기 에이전트. 처리 전략과 'Never Stop Thinking' 원칙.
Proactive tool discovery
수천 개 도구 중 필요한 것만 동적으로 찾아 올리는 기법(MCP-Zero 등, 토큰 ~98% 절감).
Coding agent
파일 읽기/편집/검색/실행 등 7 코어 툴을 갖춘 에이전트. 범용 에이전트 = 코딩 에이전트 + 파일시스템.
회로차단기 (Circuit breaker)
같은 실패 N회(예: 3회) 반복 시 루프를 끊고 에스컬레이션. death spiral 방어.
Proposer-Reviewer
생성자와 검토자를 분리하는 협업 패턴. 위치 특정 피드백으로 반복 개선.
Bootstrapping
에이전트가 자기 환경을 진단(doctor)하고 도구/예제를 스스로 만들어 능력을 확장하는 것.

Ch6 · 평가

평가 3계층
환경(environment) / 방법(method) / 결정(decision). 벤치마크 숫자 하나가 아니라 인프라 전체가 평가다.
Verifier
결과를 기계적으로 판정하는 장치 4종(규칙/단위테스트/모델 판정/인간). RL과 평가의 공통 부품.
Pass@k vs Pass^k
k번 중 한 번이라도 성공 vs k번 모두 성공. 일회성 태스크와 신뢰성 태스크의 지표가 다르다.
LLM-as-judge
모델로 출력을 채점. rubric 4원칙, veto 조건, length bias·position bias 방어가 필요.
Goodhart's law
지표가 목표가 되면 지표가 망가진다. multi-source judging과 지표 로테이션으로 방어.
Elo / Bradley-Terry
상대 평가를 점수화하는 모델. 페어와이즈 비교의 통계 엔진.
SE / McNemar
표본오차 √(p(1-p)/n) / 같은 태스크 쌍의 승패를 비교하는 paired 검정. '차이처럼 보이는 것'의 대부분은 노이즈.
Observability
OpenTelemetry/LangSmith 같은 궤적 수집. 운영 데이터를 평가 자산으로 증류하는 출발점.

Ch7-8 · 포스트트레이닝과 진화

SFT memorizes, RL generalizes
책의 제1원칙. 형식·스타일은 SFT, 새 상황 일반화는 RL. 선택 기준: '데모를 추가핀데도 안 오륨녀 RL'.
Data & environment > algorithms
제2원칙. 우선순위는 prior > environment > algorithm. 알고리즘 교첸는 마지막 수단.
RLHF / Reward model
인간 선호 → 보상 모델 → 정책 최적화. over-optimization(Goodhart)에 취약.
PPO / GRPO / DPO
정책 경사 / 그룹 상대 우위 / 선호 직접 최적화. 실무 선택은 인프라 성숙도와 데이터 형태가 결정.
Credit assignment
멀티턴 궤적에서 어느 행동이 결과를 만들었는지 보상을 배분하는 문제. 보상 밀도 스펙트럼으로 설계.
PRM vs ORM
과정 보상 모델 vs 결과 보상 모델. 과정 피드백이 밀도를 올리지만 비용·해킹 리스크.
On-policy distillation
강한 교사의 궤적으로 학생을 학습시키되 학생 분포에서. 오프폴리시 SFT보다 스텝 ~1/10.
4대 갱신 매체
지식(파일) / 프롬프트·스킬 / 프로그램(도구) / 파라미터(가중치). 지속 진화는 이 중 어디를 고칠지의 선택.
보존 ≠ 학습
궤적을 저장하는 것과 그것으로 능력이 나아지는 것은 다르다. 3층 검증 구조가 필요.
Sleep learning
운영 중 쌓인 궤적을 비동기로 정리·증류·검증·반영하는 5단계 오프라인 루프.

Ch9-10 · 멀티모달과 멀티에이전트

Cascaded pipeline
ASR → LLM → TTS 직렬 음성 아키텍처. 단순하지만 지연·정보 손실(비언어 신호 소실).
End-to-end Omni
음성을 직접 이해하고 생성하는 단일 모델. 병목이 '어떤 정보를 담는가'로 E2E vs cascade를 판별.
Full-duplex
듣기와 말하기를 동시에 — 끊기·맞장구 가능(Moshi ~200ms). VAD 기반 턴테이킹의 대체.
Fast-slow thinking
빠른 반사 경로와 느린 추론 경로의 분리/통합 문제. 음성·GUI·로봇을 관통하는 주제.
Computer use
스크린샷 → 좌표 액션으로 GUI를 조작하는 에이전트. 설계 3차원: action space / visual grounding / 관찰 인터페이스.
SoM (Set-of-Mark)
스크린샷의 요소에 번호 마커를 오버레이해 grounding하는 기법. DOM/좌표 예측과의 트레이드오프.
Shared vs non-shared context
멀티에이전트 분류의 1축. 같은 컨텍스트를 보는가, 메시지로만 소통하는가.
신규 정보 도입 기준
멀티에이전트가 싱글보다 나은 조건: 다른 에이전트가 '새 정보'(실행 결과, 다른 시각)를 가져올 때. 같은 정보로 debate만 하면 무효.
MAST
Multi-Agent System Failure Taxonomy. 멀티에이전트 실패 모드 분류표.
Premature termination
검증 없이 조기 종료하는 실패 3형태. 병목은 generator가 아니라 verifier.

Meta · 학습

ZPD (Zone of Proximal Development)
근접 발달 영역. 혼자선 못 하지만 scaffolding으로 가능한 지점 — 레슨 난이도의 기준.
Retrieval practice
답을 다시 보기 전에 머리에서 꺼내는 연습. 저장 강도(storage strength)를 키우는 핵심.
Fluency vs Storage strength
지금 막 이해한 느낌 vs 나중에도 꺼낼 수 있는 힘. 이 코스의 퀴즈·실습은 후자를 겨냥.

코스 홈 · 모르는 용어의 뉘앙스가 헷갈리면 에이전트에게 예시를 달라고 하면 된다.
