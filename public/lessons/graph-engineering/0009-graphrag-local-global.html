Lesson 0009 · Graph Engineering v2

RAG가 찾는 것, GraphRAG가 연결하는 것

일반 RAG는 질문과 비슷한 텍스트 조각을 찾는다. GraphRAG는 그 조각들이 서로 어떻게 연결되는지도 찾는다. 다만 "18% 더 정확하고 85% 더 싸다"는 X 글의 수치는 GraphRAG 일반의 결과가 아니라, 산업 도면(P&ID) 한 논문의 특정 비교였다.

오늘의 한 줄 답: GraphRAG는 엔티티·관계를 추출해 그래프를 만들고, 촘촘히 연결된 노드 묶음(커뮤니티)마다 요약 리포트를 미리 만들어 둔다. 그래서 특정 대상을 묻는 local 질문과 전체 패턴을 묻는 global 질문을 서로 다른 전략으로 답할 수 있다 — 이것이 GraphRAG가 평범한 RAG를 이기는 지점이지, 아무 수치나 항상 이긴다는 뜻은 아니다.

1. 일반 RAG가 막히는 지점

Sprytix의 X 글은 이렇게 대비한다: 일반 RAG는 "질문 → 문서에서 매칭 텍스트 검색 → 관련 청크 반환 → 모델이 청크로 답 생성" 순서로 동작한다. "3월에 매출이 왜 떨어졌나?"라고 물으면, 일반 RAG는 "매출"과 "3월"이 들어간 문서 조각을 찾아줄 뿐이다.

원문이 든 예시(원인의 연쇄를 답하는 장면)는 수치·출처 없는 예시적 설명이다. 실제로 검증된 것은 구조 자체다: GraphRAG는 명시적 엔티티-관계 그래프를 갖고 있어서, 여러 문서에 흩어진 사실을 연결한 "관계 사슬"을 물을 수 있는 가능성을 연다는 것.

2. GraphRAG의 공식 파이프라인

Microsoft GraphRAG 공식 아키텍처 문서 기준 순서는 다음과 같다.

1) TextUnits

문서를 청크(TextUnit) 단위로 분할.

2) 추출

각 청크에서 엔티티·관계·핵심 클레임(claim)을 LLM으로 추출.

3) 그래프 구축

추출된 엔티티·관계로 지식 그래프를 조립.

4) Leiden 커뮤니티 탐지

그래프 안에서 촘촘히 연결된 노드 묶음(커뮤니티)을 계층적으로 발견.

5) 커뮤니티 리포트

각 커뮤니티를 LLM이 요약한 리포트를 미리 생성해 둔다.

6) Local / Global Search

질문 유형에 따라 특정 노드 주변을 보거나(local), 리포트들을 map-reduce로 종합한다(global).

3. Local 질문과 Global 질문, 무엇이 다른가

구분질문 예시검색 방식강한 상황
Local Search"공급업체 X에게 3월에 무슨 일이 있었나?"특정 엔티티 + 이웃 노드로 확장구체적 대상이 이미 정해진 질문
Global Search"전체 공급업체 관계에서 반복되는 위험 패턴은?"커뮤니티 리포트를 map 단계로 훑고 reduce로 종합데이터셋 전체를 관통하는 주제·패턴 질문(sensemaking)

공식 문서: GraphRAG Global Search, GraphRAG README(Local Search).

4. 교정: "정확도 +18%, 비용 -85%"는 GraphRAG 일반 수치가 아니다

과장 교정: Sprytix의 X 글은 이 수치를 "Microsoft, Stanford, Anthropic이 독립적으로 발견한 결론"처럼 제시하지만, 원문이 스스로 인용한 출처(arXiv:2603.22528, ChatP&ID 논문)를 확인하면 이것은 산업용 배관·계장 다이어그램(P&ID) 도메인에서 그래프 표현이 원본 이미지 입력 대비 정확도 +18%, P&ID 파일 직접 ingest 대비 토큰 비용 -85%를 보인 결과다. 대조군 자체가 서로 다르고, Microsoft GraphRAG의 보편 성능 수치가 아니다.

Microsoft의 원 GraphRAG 논문(arXiv:2404.16130)이 실제로 보인 것은 약 100만 토큰 규모 코퍼스의 global sensemaking·QFS(query-focused summarization) 질문에서 comprehensiveness(포괄성)와 diversity(다양성)의 개선이다. "모든 질문에서 더 정확하다"는 범용 주장은 원 논문에 없다.

5. GraphRAG가 항상 이기지는 않는다

그래프 인덱싱 자체에 비용이 든다. Microsoft Research 공식 실험(50개 global 질문 기준)에서 Dynamic Global Search는 static level 1 대비 평균 77% 토큰 비용을 줄였지만, level 3 dynamic 설정은 오히려 평균 +34% 더 비쌌다 — community level과 비용의 관계는 단순하지 않다.

반대로 LazyGraphRAG는 공식 발표에서 인덱싱 비용이 full GraphRAG의 0.1%, 동등한 global 품질 기준에서 쿼리 비용이 최대 700배 낮았다고 보고한다 — "그래프는 항상 비싸다"의 최신 반례지만, 이 역시 같은 평가 세팅 내부 결과로 한정해야 한다.

공식: GraphRAG Dynamic Community Selection, LazyGraphRAG.

실무 번역: mystudy의 memory_search는 사실상 vector/local 검색에 가깝다 — "이 프로젝트에서 이 결정을 왜 했지?" 같은 국지적 질문에는 강하지만, "내가 반복적으로 만드는 실수 유형은?" 같은 전체를 관통하는 global 질문에는 별도의 요약·커뮤니티 리포트 단계 없이는 약하다. Trade Intel의 거래처 관계망도 마찬가지: "이 거래처의 최근 주문"은 local, "전체 거래처 중 반복되는 클레임 패턴"은 global 질문이다.
