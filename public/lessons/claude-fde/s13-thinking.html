S13. 확장 사고 (thinking)

20분노트 초안

공식 경로에서 해당하는 부분: Teaching your Agent: What is thinking?

오늘의 목표

  • 사고(thinking)가 무엇이고 어떤 일에 도움이 되는지 설명할 수 있다.
  • API에서 사고를 요청하고, effort로 깊이를 조절하고, 비용이 어떻게 청구되는지 말할 수 있다.
  • 도구 사용 루프에서 thinking 블록을 어떻게 다뤄야 하는지 말할 수 있다.

핵심 정리

답하기 전의 연습장

시험에서 암산으로 바로 답을 쓰는 것과, 연습장에 풀어 보고 답을 쓰는 것의 차이예요. 사고(thinking)는 Claude가 답하기 전에 문제를 자기 말로 풀어 보는 단계예요. 접근을 시도하고, 중간 결과를 확인하고, 안 되는 길은 버려요. 응답에서는 thinking 블록이 text 블록보다 앞에 와요. 수학, 코딩, 분석, 긴 에이전트 작업처럼 중간 과정이 답의 품질을 좌우하는 일에서 효과가 커요. 간단한 사실 질문이라면 Claude가 생각을 건너뛰기도 해요.

이름 정리: 확장 사고와 적응형 사고

  • 확장 사고(extended thinking)는 thinking: {type: "enabled", budget_tokens: N}처럼 생각에 쓸 토큰 예산을 직접 정하는 수동 방식이에요. 지금 공식 문서는 이 방식을 레거시로 분류하고, Claude 4.7 이후 모델은 이 설정을 400 에러로 거절해요.
  • 적응형 사고(adaptive thinking)는 thinking: {type: "adaptive"}예요. 요청마다 생각할지, 얼마나 할지를 Claude가 정해요. Claude 5 이후 모델은 설정 없이도 기본으로 켜져 있고, Claude Opus 5.5처럼 아예 끌 수 없는 모델도 있어요.
  • 깊이는 S09에서 본 effort로 조절해요. API에서는 output_config.effort에 low·medium·high·xhigh·max 중 하나를 넣어요. effort는 부드러운 안내이고, 엄격한 상한은 max_tokens예요.

보이는 것과 청구되는 것

생각의 원문은 어떤 설정으로도 돌려받지 못해요. display: "summarized"면 요약을 받고, "omitted"면 thinking 필드가 빈 문자열로 와요. 최신 모델은 "omitted"가 기본값이에요.

사고 토큰은 출력 토큰으로 청구되고 max_tokens에도 포함돼요. 요약만 받든 아예 안 받든 실제로 생각한 만큼 청구돼요. "omitted"가 줄여 주는 건 비용이 아니라 첫 글자가 나오기까지의 시간이에요.

도구와 함께 쓸 때

S11의 에이전트 루프에서 Claude는 도구 호출 사이사이에도 생각해요(interleaved thinking). 적응형 사고에서는 자동이에요. 지킬 규칙은 하나예요. 도구 결과를 돌려보낼 때, 받은 assistant 메시지의 thinking 블록을 고치지 말고 그대로 함께 보내요. S11에서 하던 대로 response.content를 통째로 붙이면 돼요. 블록을 수정하면 400 에러가 나요. 그리고 도구 루프 전체가 assistant 턴 하나라서, 루프 중간에 thinking 설정을 바꾸지 않아요.

import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic(); // ANTHROPIC_API_KEY 환경 변수를 읽어요

const response = await client.messages.create({
  model: "claude-opus-5-5",
  max_tokens: 16000,
  thinking: { type: "adaptive", display: "summarized" }, // 생각 요약을 받아 보기
  output_config: { effort: "medium" },                    // 얼마나 깊이 일할지
  messages: [{ role: "user", content: "1071과 462의 최대공약수를 구해 줘." }],
});

for (const block of response.content) {
  if (block.type === "thinking") console.log("[생각 요약]", block.thinking);
  if (block.type === "text") console.log("[답]", block.text);
}
console.log(response.usage); // output_tokens에 생각 토큰이 포함돼요

예시 모델은 공식 문서 예시와 같은 claude-opus-5-5예요. 허용되는 thinking 설정은 모델마다 달라요. 다른 모델로 바꿀 때는 Thinking 문서의 모델별 표를 확인하세요.

직접 해 보기 (5분)

  1. 위 코드를 S10에서 만든 프로젝트에 thinking.ts로 저장하고 npx tsx thinking.ts로 실행하세요. 그다음 effort만 "low"와 "high"로 바꿔 두 번 더 실행하고, usage.output_tokens와 걸린 시간을 비교해 보세요.
  2. 질문을 "대한민국의 수도는?"으로 바꿔 보세요. thinking 블록이 나오나요? 적응형 사고는 쉬운 질문에서 생각을 건너뛸 수 있어요. "모든 응답은 thinking 블록으로 시작한다"고 가정하고 코드를 짜면 안 되는 이유예요.

확인 문제

  1. 사고 토큰의 청구 방식으로 맞는 것은?
    • (a) 입력 토큰으로 청구되고 max_tokens와는 무관하다
    • (b) 출력 토큰으로 청구되고 max_tokens에 포함된다
    • (c) display: "omitted"로 숨기면 청구되지 않는다
    정답과 해설 보기
    (b). 사고 토큰은 출력 토큰으로 청구되고 max_tokens에 포함돼요. 숨겨도 청구는 같아요.
  2. 지금 권장되는 사고 요청 방식은?
    • (a) thinking: {type: "enabled", budget_tokens: N}으로 예산을 직접 정한다
    • (b) 프롬프트에 "단계별로 생각해"라고만 적는다
    • (c) 적응형 사고에 맡기고, 깊이는 output_config.effort로 조절한다
    정답과 해설 보기
    (c). 적응형 사고가 현재 방식이고 깊이는 effort로 조절해요. (a)는 레거시 방식이라 최신 모델에서는 400 에러가 나요.
  3. 도구 사용 루프에서 thinking 블록을 다루는 올바른 방법은?
    • (a) 토큰을 아끼려고 thinking 블록을 지우고 도구 결과만 보낸다
    • (b) 받은 assistant 메시지의 thinking 블록을 수정 없이 그대로 다시 보낸다
    • (c) thinking 블록을 요약해서 user 메시지에 넣는다
    정답과 해설 보기
    (b). thinking 블록은 수정 없이 그대로 돌려보내야 해요. 수정하면 400 에러가 나고, 지우면 Claude가 앞선 추론을 이어 가지 못해요.
  4. (서술형) effort와 max_tokens는 둘 다 "얼마나 쓸지"와 관련이 있어요. 둘의 차이를 두세 문장으로 설명해 보세요.
    정답과 해설 보기
    예시 답: effort는 Claude가 응답 전체에 얼마나 공을 들일지 알려 주는 부드러운 안내라서, 낮춰도 어려운 문제에서는 여전히 생각한다. max_tokens는 생각과 답을 합친 출력의 엄격한 상한이라서, 넘으면 거기서 잘린다. 그래서 비용과 속도는 effort로 조절하고, 절대 넘으면 안 되는 한도는 max_tokens로 건다.
  5. (상황형) 고객사 팀장이 말해요. "답은 좋아졌는데 전보다 느리고 청구액이 늘었어요. 그리고 감사 때문에 AI가 생각한 과정을 전부 저장하고 싶어요." 어떻게 설명하고 무엇을 제안할까요?
    정답과 해설 보기
    예시 답: "답하기 전에 생각하는 단계가 켜져 있어서 품질이 올랐고, 그 생각이 출력 토큰으로 청구되고 시간도 걸려요"라고 설명한다. 제안은 (1) 업무 표본을 effort 단계별로 돌려 품질·시간·비용을 비교하고 업무마다 단계를 정한다. (2) 생각의 원문은 API가 돌려주지 않으니, 감사용으로는 생각 요약(display: "summarized"), 도구 호출 기록, 최종 답과 근거를 저장한다. (3) 성공 지표를 "기준을 통과한 건당 비용"으로 합의한다.

FDE 관점

파일럿에서 사고는 "품질을 얼마에 살 것인가"의 문제로 나타나요. 어려운 판단이 들어가는 업무는 effort를 올릴 가치가 있고, 분류나 짧은 응답처럼 양이 많은 업무는 낮은 effort로도 충분한 경우가 많아요. 그래서 FDE는 감으로 정하지 않고, 실제 업무 표본을 effort 단계별로 돌려서 품질·시간·비용을 같이 재요. 이 결과가 파일럿의 기준선과 성공 지표가 돼요. "요청당 비용"이 아니라 "기준을 통과한 건당 비용"으로 합의해 두면 좋아요. 또 생각의 원문은 받을 수 없다는 점을 미리 알려야 해요. 감사 기록이 필요하면 요약, 도구 호출 기록, 최종 답과 근거를 남기는 쪽으로 설계해요.

복습 카드

사고(thinking)란?
Claude가 답하기 전에 문제를 풀어 보는 단계. 응답에서 thinking 블록이 text 블록 앞에 온다.
확장 사고와 적응형 사고의 차이는?
확장 사고는 budget_tokens로 예산을 직접 정하는 레거시 방식, 적응형 사고는 Claude가 요청마다 생각할지와 깊이를 정하는 현재 방식.
사고의 깊이를 조절하는 파라미터는?
output_config.effort (low, medium, high, xhigh, max).
사고 토큰은 어떻게 청구되나?
출력 토큰으로 청구되고 max_tokens에 포함된다. 숨겨도(omitted) 청구된다.
도구 루프에서 thinking 블록 규칙은?
받은 그대로, 수정 없이 다시 보낸다.

영상 대본

영상 대본 펼치기 · 장면별 화면과 내레이션

장면 1 · 오늘의 질문 (약 25초)

화면: 시험지 두 장이 나란히 놓임. 왼쪽은 답만 적힌 시험지, 오른쪽은 옆에 연습장 풀이가 붙은 시험지. 아래에 제목 "답하기 전에 생각하게 하려면?"
내레이션: 어려운 문제를 암산으로 바로 답하면 틀리기 쉽죠. 연습장에 풀어 보면 달라져요. 오늘은 클로드에게 연습장을 주는 기능, 사고를 알아볼게요.

장면 2 · 사고란 (약 35초)

화면: 질문 말풍선에서 화살표가 나와 "생각" 상자를 지나 "답" 상자로 이어짐. 생각 상자 안에서 작은 줄 세 개가 차례로 나타남: "다시 정리", "시도", "확인". 한 줄에는 취소선이 그어짐.
내레이션: 사고는 답하기 전에 문제를 풀어 보는 단계예요. 무엇을 묻는지 정리하고, 방법을 시도하고, 중간 결과를 확인해요. 안 되는 길은 버리고요.

장면 3 · 언제 도움이 되나 (약 35초)

화면: 저울 그림. 왼쪽 접시에 "수학", "코딩", "분석", "긴 에이전트 작업" 카드가 올라가 무겁게 내려감. 오른쪽 접시에 "수도 묻기", "인사" 카드가 가볍게 떠 있음.
내레이션: 중간 과정이 답의 질을 좌우하는 일에서 효과가 커요. 수학, 코딩, 분석, 긴 에이전트 작업이 그래요. 쉬운 질문에는 생각을 건너뛰기도 해요.

장면 4 · 두 가지 이름 (약 40초)

화면: 왼쪽 카드 "확장 사고: 예산을 내가 정함"에 "레거시" 딱지가 붙음. 오른쪽 카드 "적응형 사고: 클로드가 정함"에 "현재" 딱지가 붙고 밝게 강조됨.
내레이션: 이름이 둘이에요. 확장 사고는 생각에 쓸 토큰 예산을 직접 정하는 옛 방식이에요. 지금은 적응형 사고가 기본이에요. 생각할지, 얼마나 할지를 클로드가 정해요.

장면 5 · 깊이 조절 (약 35초)

화면: 다섯 칸짜리 다이얼: 낮음, 중간, 높음, 아주 높음, 최대. 바늘이 낮음에서 높음으로 움직이면 옆의 "생각" 상자가 점점 커지고, 시계와 동전 아이콘도 함께 커짐.
내레이션: 깊이는 에포트라는 다이얼로 조절해요. 높이면 더 꼼꼼히 생각하지만 시간과 비용도 늘어요. 낮추면 빠르고 싸져요. 일에 맞게 고르면 돼요.

장면 6 · 보이는 것과 내는 것 (약 40초)

화면: 생각 상자 위에 반투명 덮개가 내려옴. 덮개에 "요약만 보임" 또는 "안 보임" 글자가 번갈아 나타남. 아래 영수증에는 두 경우 모두 "출력 토큰: 생각 + 답"이 똑같이 찍힘.
내레이션: 생각의 원문은 받을 수 없어요. 요약을 받거나, 아예 안 받거나예요. 그런데 비용은 같아요. 생각한 만큼 출력 토큰으로 청구돼요. 숨긴다고 싸지지 않아요.

장면 7 · 도구와 함께 (약 40초)

화면: S11의 루프 그림이 다시 등장. 도구 호출과 도구 결과 사이마다 작은 "생각" 블록이 끼어 있음. 블록에 자물쇠 아이콘이 붙고 "그대로 돌려보내기" 화살표가 한 바퀴 돎.
내레이션: 에이전트 루프에서는 도구를 쓰는 사이사이에도 생각해요. 규칙은 하나예요. 받은 생각 블록을 고치지 말고 그대로 다시 보내요. 응답을 통째로 붙이면 돼요.

장면 8 · 코드로 보면 (약 35초)

화면: 요청 상자에 세 줄이 강조됨: "사고 방식: 적응형", "표시: 요약", "깊이: 중간". 응답 상자에는 "생각 요약" 블록, "답" 블록, 사용량 표가 차례로 나타남.
내레이션: 요청에는 사고 방식과 깊이를 적어요. 응답에는 생각 요약과 답이 따로 와요. 사용량의 출력 토큰에는 생각에 쓴 토큰이 들어 있어요.

장면 9 · 고객 앞에서 (약 35초)

화면: 회의실 그림. 고객 말풍선 "느려지고 비싸졌어요." FDE 말풍선 옆에 표가 펼쳐짐: 깊이 단계별로 품질, 시간, 비용 세 칸. 한 줄에 동그라미.
내레이션: 고객이 느리고 비싸졌다고 하면 이렇게 해요. 실제 업무 표본을 깊이 단계별로 돌려요. 품질과 시간, 비용을 같이 재고 업무마다 알맞은 단계를 정해요.

장면 10 · 요약과 예고 (약 25초)

화면: 세 줄 요약이 한 줄씩 나타남: "1. 사고는 답하기 전의 연습장 2. 깊이는 에포트로, 비용은 출력 토큰으로 3. 생각 블록은 그대로 돌려보낸다". 아래에 "다음: S14 내장 도구와 스킬".
