S23. 작업 조종: plan mode, 압축(compaction), 되감기(rewind)

22분노트 초안

공식 경로에서 해당하는 부분: Steer the Work

오늘의 목표

  • plan mode로 작업 범위를 먼저 합의하고, 계획 승인 화면의 선택지를 구분해 고를 수 있다.
  • 압축(compaction) 뒤에 무엇이 남고 무엇이 사라지는지 말하고, 요약이 중요한 것을 지키도록 지시할 수 있다.
  • 되감기(rewind) 메뉴의 동작을 상황에 맞게 고르고, 체크포인트가 되돌리지 못하는 것을 말할 수 있다.

핵심 정리

긴 세션은 장거리 운전과 같아요. 출발 전에 경로를 정하고(plan mode), 가는 동안 짐을 정리하고(압축), 길을 잘못 들면 갈림길로 돌아가요(되감기). 코스 7은 이렇게 "오래, 손을 떼고" 돌리는 세션을 믿을 수 있게 만드는 법을 다뤄요. 오늘은 그 첫 단계인 조종이에요.

출발 전: plan mode로 범위 정하기

S19에서 본 Plan Mode를 긴 작업에서는 "범위를 합의하는 도구"로 써요. plan mode에서 Claude는 파일을 읽고 탐색용 명령을 실행해 계획을 쓰지만 소스는 고치지 않아요. 들어가는 방법은 세 가지예요: Shift+Tab으로 모드를 돌리기, 프롬프트 앞에 /plan 붙이기, 시작할 때 claude --permission-mode plan.

계획이 나오면 승인 화면에서 골라요.

  • Yes, and use auto mode: 승인하고 auto mode로 실행해요. auto mode를 쓸 수 없는 세션에서는 이 자리가 "Yes, auto-accept edits"로 보여요.
  • Yes, manually approve edits: 승인하되 편집마다 직접 확인해요.
  • No, keep planning: plan mode에 남아 무엇을 바꿀지 말해요.

여기서 Ctrl+G를 누르면 계획이 텍스트 에디터에서 열려요. 범위 밖 항목은 이때 직접 지워요. 무엇을 만들지부터 흐릿하다면, 공식 문서는 계획보다 먼저 "스펙을 쓸 수 있을 때까지 나를 인터뷰하고 SPEC.md에 써 줘"라고 시킨 뒤 새 세션에서 그 파일로 시작하라고 권해요.

주의할 점이 하나 있어요. bypass permissions를 켜고 시작한 대화형 터미널 세션에서는 plan mode의 차단에 기대면 안 된다고 문서가 경고해요. 계획 중에 시도한 편집이나 명령이 묻지 않고 실행될 수 있어요.

가는 동안: 압축이 지킬 것을 정해 주기

세션이 길어지면 Claude Code는 대화를 자동으로 요약해요. 이게 S20에서 본 /compact가 하는 일과 같은 압축이에요. 요약은 요청과 핵심 코드 조각은 남기지만, 대화 초반에 말로만 준 자세한 지시는 사라질 수 있어요.

압축 뒤어떻게 되나
프로젝트 루트의 CLAUDE.md, 경로 조건이 없는 rules디스크에서 다시 주입
plan mode에서 쓴 계획디스크에서 다시 주입
Claude가 읽거나 고친 파일최근에 수정된 순으로 최대 5개를 다시 읽음
호출했던 skill 본문skill당 5,000토큰, 합계 25,000토큰까지 다시 붙임
대화로만 준 지시, hook이 넣었던 컨텍스트나머지 대화와 함께 요약됨

방향을 주는 방법은 세 가지예요.

  1. /compact 뒤에 지시를 붙여요. 예: /compact keep the API changes and the test commands
  2. CLAUDE.md에 "Compact Instructions" 섹션을 둬요.
  3. 끝까지 지켜져야 하는 지시는 대화가 아니라 CLAUDE.md에 써요.

관계없는 새 일로 넘어갈 때는 압축이 아니라 /clear가 맞아요.

길을 잘못 들었을 때: rewind 메뉴

S20에서 한 번 써 본 /rewind를 자세히 봐요. Claude Code는 턴을 시작하는 프롬프트마다 체크포인트(checkpoint)를 만들어요. /rewind(별칭 /undo)를 치거나, 입력창이 빈 상태에서 Esc를 두 번 누르면 rewind 메뉴가 열려요. 돌아갈 프롬프트를 고른 뒤 동작을 골라요.

  • Restore code and conversation: 코드와 대화를 모두 그 시점으로
  • Restore conversation: 코드는 그대로 두고 대화만
  • Restore code: 대화는 그대로 두고 파일만
  • Summarize from here / Summarize up to here: 그 지점 이후만, 또는 이전만 요약(부분 압축)

한계도 분명해요. 체크포인트는 Claude의 파일 편집 도구가 한 변경을 추적해요. Bash 명령으로만 바뀐 파일은 추적하지 않고, 서브에이전트의 편집도 대개 복원하지 못해요. 그래서 문서는 체크포인트를 "세션 안의 빠른 복구"라고 부르고, 버전 관리는 계속 Git으로 하라고 해요.

되감기 전에 쓸 수 있는 더 가벼운 장치도 있어요. 방향이 틀어지는 순간 Esc 한 번으로 멈추고 다시 지시해요.

직접 해 보기 (5분)

연습용 폴더에서만 해요. 끝나면 폴더째 지워도 돼요.

mkdir -p ~/cc-lab/s23 && cd ~/cc-lab/s23 && git init
printf 'def add(a, b):\n    return a + b\n' > calc.py
claude --permission-mode plan
  1. "calc.py에 subtract와 multiply를 추가하고 테스트 파일을 만드는 계획을 세워 줘"라고 해요. 계획이 나오면 Ctrl+G로 열어 multiply 항목을 지우고 저장한 뒤 "Yes, manually approve edits"를 골라요. 관찰: 승인 전에는 다른 터미널의 git status에 변화가 없는지, 지운 항목이 실제로 빠졌는지.
  2. 편집이 끝나면 빈 입력창에서 Esc를 두 번 눌러 첫 프롬프트를 고르고 "Restore code"를 골라요. 관찰: calc.py는 원래대로 돌아가고 대화는 남아 있는지. 이어서 /compact calc.py 변경 내용과 테스트 실행 명령만 남겨 줘를 실행하고 /context로 사용량이 어떻게 바뀌는지 봐요.

확인 문제

  1. plan mode의 계획 승인 화면에서 Ctrl+G를 누르면?
    • (a) 계획을 버리고 plan mode를 끝낸다
    • (b) 제안된 계획이 텍스트 에디터에서 열려 직접 고칠 수 있다
    • (c) 계획을 승인하고 auto mode로 넘어간다
    정답과 해설 보기
    (b). Ctrl+G는 제안된 계획을 기본 텍스트 에디터에서 열어요. 참고로 승인 화면에서 Shift+Tab을 누르면 계획이 승인되니, plan mode에서 나가려면 먼저 Esc를 눌러요.
  2. 압축 뒤에도 디스크에서 다시 주입되는 것은?
    • (a) 세션 초반에 채팅으로 말한 "이 폴더는 건드리지 마"
    • (b) 프로젝트 루트의 CLAUDE.md
    • (c) hook이 대화 중간에 넣어 준 컨텍스트
    정답과 해설 보기
    (b). 프로젝트 루트의 CLAUDE.md는 압축 뒤 디스크에서 다시 읽혀요. (a)와 (c)는 나머지 대화와 함께 요약돼요.
  3. rewind 메뉴의 "Restore code"로 되돌릴 수 없는 것은?
    • (a) Claude가 Edit 도구로 고친 파일
    • (b) Claude가 Write 도구로 새로 만든 파일
    • (c) Claude가 Bash 명령으로만 지우거나 옮긴 파일
    정답과 해설 보기
    (c). 체크포인트는 Claude의 파일 편집 도구가 만든 변경을 추적해요. Bash 명령으로만 바뀐 파일은 Git 같은 버전 관리로 되돌려야 해요.
  4. (서술형) /compact <지시>, rewind 메뉴의 "Summarize from here", /clear를 각각 어떤 상황에서 쓰는지 한 문장씩 써 보세요.
    정답과 해설 보기
    예시 답: /compact <지시>는 같은 작업을 이어 가되 대화가 길어져 남길 것을 직접 정하고 싶을 때 쓴다. "Summarize from here"는 처음 지시는 그대로 두고 중간부터 길어진 디버깅 같은 구간만 줄이고 싶을 때 쓴다. /clear는 관계없는 새 작업으로 넘어가거나, 두 번 고쳐도 틀려서 새 프롬프트로 다시 시작할 때 쓴다.
  5. (상황형) 고객사 엔지니어가 말해요. "처음에 migrations 폴더는 건드리지 말라고 했는데 세션 중반부터 잊은 것 같아요. 그리고 지난 한 시간 동안 파일 열두 개를 엉뚱한 방향으로 고쳤어요." 지금 무엇을 하고, 다음부터 어떻게 바꾸자고 제안할까요?
    정답과 해설 보기
    예시 답: 지금은 Esc로 멈추고 rewind 메뉴에서 방향이 틀어지기 전 프롬프트를 골라 "Restore code and conversation"을 쓴다. Bash 명령으로 바뀐 파일이나 서브에이전트 편집은 복원되지 않으니 git status와 git diff로 남은 변경을 확인해 Git으로 되돌린다. 다음부터는 (1) plan mode로 시작해 계획에서 범위를 합의하고, (2) "migrations는 건드리지 않는다"를 대화가 아니라 CLAUDE.md에 쓰며, 예외가 없어야 하면 deny 규칙이나 hook으로 강제하고(S25), (3) 작업 브랜치에서 시작하자고 제안한다.

FDE 관점

공식 경로는 이 코스를 "고객의 저장소에서 길고 손을 뗀 세션을 돌리고, 권한 모드·hook·검증으로 통제하기"라고 소개해요. 남의 저장소에서는 조종 장치가 곧 안전 장치예요. 큰 작업은 plan mode로 시작해 계획을 고객 엔지니어와 같이 읽고, 범위 밖 항목을 지운 계획을 PR 설명이나 스펙 파일에 남겨요. 이 기록이 파일럿에서 "먼저 출시할 부분"을 합의한 근거가 돼요. 체크포인트는 편의 기능일 뿐이라서 고객 저장소에서는 항상 작업 브랜치에서 시작하고 Git으로 되돌릴 길을 열어 둬요. 말로만 준 경계는 압축에서 사라질 수 있으니, 고객이 "절대 안 됨"이라고 한 것은 CLAUDE.md에 쓰고, 예외가 없어야 하면 S25에서 배울 deny 규칙이나 hook으로 옮겨요.

복습 카드

plan mode에 들어가는 세 가지 방법은?
Shift+Tab으로 모드 순환, 프롬프트 앞에 /plan, 시작할 때 claude --permission-mode plan.
계획 승인 화면에서 계획을 직접 고치는 키는?
Ctrl+G. 계획이 텍스트 에디터에서 열린다.
압축 뒤에도 디스크에서 다시 주입되는 지시는?
프로젝트 루트의 CLAUDE.md와 경로 조건 없는 rules. 대화로만 준 지시는 요약되며 사라질 수 있다.
rewind 메뉴를 여는 두 가지 방법은?
/rewind(별칭 /undo), 또는 입력창이 빈 상태에서 Esc 두 번.
체크포인트가 되돌리지 못하는 대표적인 변경은?
Bash 명령으로만 바뀐 파일과 대부분의 서브에이전트 편집. 그래서 Git을 함께 쓴다.

영상 대본

영상 대본 펼치기 · 장면별 화면과 내레이션

장면 1 · 오늘의 질문 (약 25초)

화면: 어두운 화면에 터미널 창 하나. "로그인 버그 고쳐 줘"라는 한 줄 아래로 수정된 파일 목록이 빠르게 늘어나 12개가 됨. 그 위에 큰 글자 "맡긴 일이 엉뚱한 데로 갈 때, 어떻게 조종할까?"
내레이션: 긴 작업을 맡기고 돌아왔더니 엉뚱한 파일까지 고쳐져 있어요. 오래 맡길수록 조종이 필요해요. 오늘은 조종 장치 세 가지를 배워요.

장면 2 · 세 가지 조종 장치 (약 30초)

화면: 길 그림 하나. 출발점에 지도 아이콘 "계획", 길 중간에 가방 아이콘 "압축", 갈림길에 되돌아가는 화살표 "되감기". 세 아이콘이 차례로 켜짐.
내레이션: 장거리 운전을 떠올려 보세요. 출발 전에 경로를 정하고, 가는 동안 짐을 정리하고, 길을 잘못 들면 갈림길로 돌아가요. 클로드 코드에서는 플랜 모드, 압축, 되감기가 그 역할을 해요.

장면 3 · 플랜 모드는 읽기만 한다 (약 35초)

화면: 왼쪽에 파일 아이콘 여러 개, 가운데 클로드 상자. 상자에서 파일로 "읽기" 화살표만 나가고 "쓰기" 화살표에는 자물쇠. 오른쪽에 번호가 붙은 계획 문서가 한 줄씩 채워짐.
내레이션: 플랜 모드에서 클로드는 파일을 읽고 살펴보기만 해요. 소스는 고치지 않아요. 그 대신 무엇을 어떻게 바꿀지 계획을 써서 보여 줘요. 고치기 전에 범위를 먼저 합의하는 거예요.

장면 4 · 계획을 승인하거나 고친다 (약 40초)

화면: 계획 문서 아래에 버튼 세 개: "승인하고 자동으로", "승인하고 하나씩 확인", "계속 계획". 그 옆에 연필 아이콘이 계획의 네 번째 줄에 줄을 그어 지움.
내레이션: 계획이 나오면 세 가지 중에 골라요. 승인하고 자동으로 진행하기, 승인하되 편집마다 확인하기, 계획을 더 다듬기예요. 계획을 에디터로 열어 직접 고칠 수도 있어요. 범위 밖 항목은 여기서 지워요.

장면 5 · 압축이 하는 일 (약 35초)

화면: 길게 늘어선 대화 말풍선들이 한 장의 "요약" 카드로 접힘. 카드 옆에 남는 것 세 가지가 다시 붙음: "CLAUDE.md", "계획", "최근 파일 5개". 흐려지며 사라지는 말풍선 하나: "말로만 한 지시".
내레이션: 세션이 길어지면 대화가 요약으로 줄어요. 이걸 압축이라고 해요. 클로드 엠디와 계획은 다시 들어오고 최근 파일도 몇 개 다시 읽어요. 하지만 말로만 한 지시는 사라질 수 있어요.

장면 6 · 요약에 방향 주기 (약 35초)

화면: 요약 카드로 접히는 깔때기 위에 메모 한 장이 끼워짐: "남길 것: API 변경, 테스트 명령". 아래에 세 줄: "1. 압축할 때 지시 붙이기 2. CLAUDE.md에 압축 지침 3. 꼭 지킬 지시는 파일에".
내레이션: 그래서 요약에 방향을 줘요. 압축할 때 무엇을 남길지 한 줄 붙이면 돼요. 클로드 엠디에 압축 지침을 적어 둘 수도 있어요. 끝까지 지켜져야 하는 지시는 대화가 아니라 파일에 써요.

장면 7 · 되감기 메뉴 (약 40초)

화면: 세로 타임라인에 프롬프트 다섯 개, 각 옆에 깃발 "체크포인트". 세 번째 깃발을 고르면 메뉴가 펼쳐짐: "코드와 대화 복원", "대화만", "코드만", "여기부터 요약", "여기까지 요약".
내레이션: 클로드 코드는 프롬프트를 보낼 때마다 체크포인트를 남겨요. 되감기 메뉴를 열어 돌아갈 지점을 고르면 돼요. 코드와 대화를 함께 돌릴 수도, 하나만 돌릴 수도 있어요. 그 지점부터만 요약할 수도 있어요.

장면 8 · 되감기의 한계 (약 35초)

화면: 파일 두 개. 왼쪽 "편집 도구로 고침"에는 되돌리기 화살표와 체크 표시. 오른쪽 "터미널 명령으로 삭제"에는 되돌리기 화살표에 엑스 표시. 아래에 Git 로고와 "오래 남는 기록은 여기".
내레이션: 한계도 있어요. 체크포인트는 클로드가 편집 도구로 고친 파일을 따라가요. 터미널 명령으로만 지우거나 옮긴 파일은 되돌리지 못해요. 그래서 되감기는 빠른 복구용이고, 오래 남는 기록은 깃에 맡겨요.

장면 9 · 고객 저장소에서 (약 35초)

화면: 회의실 그림. 화면에 계획 문서가 떠 있고 FDE와 고객 엔지니어가 같이 보며 한 항목에 "범위 밖" 표시. 아래에 체크리스트: "작업 브랜치에서 시작", "계획을 기록으로", "금지 사항은 파일에".
내레이션: 고객의 저장소에서는 조종 장치가 안전 장치예요. 계획을 고객 엔지니어와 같이 읽고 범위를 정해요. 작업 브랜치에서 시작해 깃으로 돌아갈 길을 열어 둬요. 고객이 금지한 것은 말이 아니라 파일에 적어요.

장면 10 · 요약과 예고 (약 25초)

화면: 세 줄 요약이 한 줄씩 나타남: "1. plan mode로 범위를 먼저 합의 2. 압축에 남길 것을 지시 3. 되감기는 빠른 복구, 기록은 Git". 아래에 "다음: S24 설정 — 간결한 CLAUDE.md와 지시의 자리".
내레이션: 정리할게요. 플랜 모드로 범위를 먼저 합의하고, 압축에는 남길 것을 지시하고, 되감기는 빠른 복구로 써요. 다음 시간에는 클로드가 실제로 따르는 설정을 만들어요. 간결한 클로드 엠디부터 시작해요.
