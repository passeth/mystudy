## 핵심 정리

네 장만 기억해요

01

직접 차린 주방과 맡긴 주방

S11~S15에서는 주방을 직접 차렸어요. 루프를 돌리고, 도구를 실행하고, 컨텍스트를 관리하는 코드가 전부 내 서버에 있었어요. Claude Managed Agents는 그 주방을 Anthropic이 운영해 주는 방식이에요. 공식 문서는 "관리형 인프라에서 돌아가는, 미리 만들어진 설정형 에이전트 하네스(harness)"라고 해요. 하네스는 에이전트 루프와 도구 실행을 맡는 틀이에요.

02

네 가지 개념

  • Agent: 모델, 시스템 프롬프트, 도구, MCP 서버, skill을 묶은 설정이에요. 한 번 만들고 ID로 재사용해요. 고칠 때마다 버전이 올라가요.
  • Environment: 세션이 돌아갈 곳의 설정이에요. Anthropic이 관리하는 클라우드 샌드박스이거나, 내 인프라의 셀프호스팅 샌드박스예요. 네트워크 접근 범위도 여기서 정해요.
  • Session: 한 환경 안에서 실제로 일하는 에이전트 인스턴스예요. 세션마다 자기 샌드박스를 받아요.
  • Events: 내 앱과 에이전트가 주고받는 메시지예요. 사용자 메시지, 도구 결과, 상태 변화가 모두 이벤트예요.

순서는 Agent 만들기(한 번) → Environment 만들기 → Session 시작 → 이벤트 보내고 스트림으로 받기 → 필요하면 방향을 바꾸거나 중단하기예요.

내장 도구는 agent_toolset_20260401 한 줄로 켜요. bash, 파일 읽기·쓰기·편집, glob, grep, 웹 검색, 웹 페치가 들어 있고 필요 없는 건 꺼요. 내 시스템에서 실행할 일은 커스텀 도구로 정의하고, 호출이 오면 결과를 이벤트로 돌려줘요.

03

세션 상태와 과금

세션 상태는 네 가지예요. running(일하는 중), idle(멈춰서 입력을 기다림), rescheduling(오류 뒤 재시도 대기), terminated(끝남). 에이전트가 멈추면 session.status_idle 이벤트가 오고 stop_reason이 이유를 알려 줘요. end_turn은 차례가 끝난 것, requires_action은 내 답(커스텀 도구 결과나 도구 승인)을 기다리는 거예요.

과금은 두 갈래예요. 토큰은 모델 요금 그대로이고, 세션 실행 시간이 세션-시간당 0.08달러로 더해져요. 실행 시간은 running 상태일 때만 쌓여요.

아직 베타예요. 모든 요청에 managed-agents-2026-04-01 베타 헤더가 필요한데 SDK가 자동으로 붙여요. 세션이 기록을 서버에 보관하는 구조라서 Zero Data Retention과 HIPAA BAA 대상이 아니에요(셀프호스팅 Managed Agents의 Zero Data Retention은 예외).

04

첫 managed agent

import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic();

// 1) 에이전트: 한 번 만들고 ID를 저장해 두고 재사용해요
const agent = await client.beta.agents.create({
  name: "Coding Assistant",
  model: "claude-opus-5-5",
  system: "You are a helpful coding assistant. Write clean, well-documented code.",
  tools: [
    {
      type: "agent_toolset_20260401",
      configs: [
        { name: "web_search", enabled: false },
        { name: "web_fetch", enabled: false },
      ],
    },
  ],
});

// 2) 환경: 세션이 돌아갈 샌드박스 설정
const environment = await client.beta.environments.create({
  name: "quickstart-env",
  config: { type: "cloud", networking: { type: "limited", allow_package_managers: true } },
});

// 3) 세션: 에이전트 + 환경으로 실행 한 번
const session = await client.beta.sessions.create({
  agent: agent.id,
  environment_id: environment.id,
  title: "Quickstart session",
});

// 4) 스트림을 먼저 열고, 사용자 메시지를 이벤트로 보내요
const stream = await client.beta.sessions.events.stream(session.id);
await client.beta.sessions.events.send(session.id, {
  events: [
    {
      type: "user.message",
      content: [{ type: "text", text: "피보나치 수 20개를 만드는 파이썬 스크립트를 쓰고 fibonacci.txt로 저장해 줘." }],
    },
  ],
});

loop: for await (const event of stream) {
  switch (event.type) {
    case "agent.message":
      for (const block of event.content) {
        if (block.type === "text") process.stdout.write(block.text);
      }
      break;
    case "agent.tool_use":
      console.log(`\n[도구 사용: ${event.name}]`);
      break;
    case "session.status_idle":
      console.log("\n\n에이전트가 일을 마쳤어요.");
      break loop;
  }
}

S11과 비교해 보세요. while 루프도, 도구 실행 코드도, 대화 기록 배열도 없어요. 이 스크립트는 연습용이라 실행할 때마다 에이전트와 환경을 새로 만들어요. 실제 서비스에서는 둘을 한 번만 만들어 ID를 저장하고, 요청이 올 때는 세션만 만들어요.

##확인 문제 고르면 바로 채점

Q1Claude Managed Agents에서 에이전트 루프와 도구 실행은 어디서 돌아가나요?

루프는 Anthropic의 하네스가 돌리고, 도구는 세션마다 주어지는 샌드박스에서 실행돼요.

Q2네 가지 개념 중 "모델, 시스템 프롬프트, 도구를 묶어 한 번 만들고 ID로 재사용하는 것"은?

Agent는 재사용하는 버전 있는 설정이에요. Session은 그 설정으로 실제 일하는 인스턴스예요.

Q3세션 실행 시간 요금이 쌓이는 때는?

실행 시간은 running 상태일 때만 쌓여요. idle, rescheduling, terminated는 세지 않아요.

Q4(서술형) 에이전트(Agent)와 세션(Session)을 왜 따로 만들게 되어 있을까요? 버전과 재사용 관점에서 두세 문장으로 설명해 보세요.

예시 답 보기
에이전트는 "어떻게 일할지"의 설정이라 한 번 만들어 여러 세션이 함께 쓴다. 고칠 때마다 버전이 올라가서, 무엇이 언제 바뀌었는지 추적하고 세션이 어떤 버전으로 돌았는지 알 수 있다. 세션은 "이번 일"이라서 일마다 새로 만들고 각자 샌드박스와 기록을 가진다.

Q5(상황형) 고객사 CTO가 물어요. "우리 팀은 에이전트 인프라를 운영할 사람이 없어요. Managed Agents로 가면 되나요? 그런데 우리는 환자 정보를 다루고, 사내망 시스템에도 붙어야 해요." 무엇을 확인하고 어떻게 답할까요?

예시 답 보기
인프라 운영 부담을 줄이는 데는 맞는 선택이라고 답하되, 두 가지를 확인한다. (1) 환자 정보: Managed Agents는 세션 기록을 서버에 보관하는 구조라 Zero Data Retention과 HIPAA BAA 대상이 아니다. 규제 요건이 있으면 그 데이터를 다루는 부분은 Messages API로 직접 만든 루프 등 다른 구성을 검토하고, 고객의 법무·보안 담당과 Anthropic 계정 팀에 확인한다. (2) 사내망: Anthropic 쪽 클라우드 샌드박스에서 고객 사내망에 바로 닿을 수 있는지는 이 노트에서 확인하지 못했다(확인 필요). 공식 문서가 안내하는, 내 인프라에서 실행하는 방법은 커스텀 도구(실행은 고객 쪽 코드)와 셀프호스팅 샌드박스이니 이 둘을 먼저 검토한다. 파일럿은 민감 정보가 없는 업무부터 시작하자고 제안한다.
## FDE 관점

FDE에게 Managed Agents는 "첫 파일럿을 인프라 없이 띄우는 길"이에요.

고객 팀에 에이전트 루프와 샌드박스를 운영할 사람이 없을 때, 설정 몇 개로 오래 도는 작업을 시연할 수 있어요. 대신 첫 미팅에서 세 가지를 확인해요. 데이터가 Anthropic 쪽 세션에 보관되어도 되는지(Zero Data Retention이나 HIPAA BAA가 필요한 고객이면 대상이 아니에요), 고객이 쓰는 클라우드에서 제공되는지, 에이전트가 닿아야 하는 시스템이 공개 주소인지 사내망인지예요. 사내망이라면 커스텀 도구나 셀프호스팅 샌드박스처럼 고객 인프라에서 실행하는 구성을 따로 검토해요. 네트워크는 limited로 시작해 필요한 호스트만 열고, 되돌리기 어려운 행동은 커스텀 도구나 승인 정책으로 사람 확인을 거치게 해요. 비용 기준선은 토큰과 실행 시간 두 줄로 잡아 두세요.
