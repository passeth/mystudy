1. 채워 넣을 Decision trace (복사해서 사용)

# case-aura-b3-C3-EU.yaml  (형식은 자유, 필드만 유지)
case:
  id: CASE-aura-C3-EU
  product: Aura B3 Serum
  formula_version: v1
  ingredient_focus: Niacinamide 5%
  claim_text: "기미·잡티를 치료하고 미백합니다"
  country: EU
  market_insight_ref: EV-mkt-2026q1  # optional inspired_by
decision:
  status: forbid          # allow | restrict | forbid | needs_human
  because:
    - therapeutic_or_disease_language
    - cosmetic_scope_exceeded
  based_on:
    - RegRef: claims-common-criteria-note
    - Evidence: EV-mkt-2026q1  # 참고일 뿐, allow 근거 아님을 명시
  suggested_fix: null   # forbid면 보통 null 또는 완전 다른 톤 제안
  decided_by: human       # 파일럿 단계 권장
  decided_at: YYYY-MM-DD
outcome:                  # 나중에
  adopted: false
  final_copy: ""
  incident: false

2. 워크시트 (직접 작성)

A. 내가 고른 조합 (C1/C2/C3 × KR/EU/US 중 하나)

B. status

C. because (규칙 2개)

D. based_on (증거/규정 메모 ID)

E. suggested_fix (restrict일 때)

F. 인사이트를 allow 근거로 쓰지 않은 이유 한 줄

3. 자기 채점 (5점)

항목통과 기준Y/N
성분과 클레임 분리농도/INCI와 광고 문장이 다른 필드
시장 분리Country가 명시
인사이트 분리inspired ≠ allowed
규칙 발화because에 기계적 규칙명
다음 재사용다른 사람이 읽고 같은 결론 가능

4. 퀴즈 (최종 회수)

이 케이스 스터디의 최종 산출물은?

파일럿에서 decided_by를 human으로 두는 이유?
