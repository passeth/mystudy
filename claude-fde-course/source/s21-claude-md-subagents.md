# S21. 커스터마이즈 1: CLAUDE.md와 서브에이전트

## 오늘의 목표
- CLAUDE.md가 어떤 문제를 풀고, 파일을 어디에 두면 누구에게 적용되는지 설명할 수 있다.
- CLAUDE.md에 넣을 것과 뺄 것을 가려낼 수 있다.
- 서브에이전트가 컨텍스트를 어떻게 아껴 주는지 설명하고, 간단한 서브에이전트 파일을 읽을 수 있다.

## 핵심 정리

### CLAUDE.md: 매 세션 읽는 인수인계 메모
Claude Code의 세션은 매번 새 컨텍스트로 시작해요. 어제 알려 준 빌드 명령을 오늘은 몰라요. **CLAUDE.md**는 이 틈을 메우는 마크다운 파일이에요. 새로 온 동료에게 건네는 인수인계 메모처럼, Claude Code가 세션을 시작할 때마다 읽어요.

### 어디에 두나
파일의 위치가 적용 범위를 정해요.

| 범위 | 위치 | 누구에게 |
|---|---|---|
| 프로젝트 | `./CLAUDE.md` 또는 `./.claude/CLAUDE.md` | 팀 전체. git에 커밋해 공유 |
| 사용자 | `~/.claude/CLAUDE.md` | 나만, 모든 프로젝트에서 |
| 로컬 | `./CLAUDE.local.md` | 나만, 이 프로젝트에서. `.gitignore`에 추가 |

작업 폴더와 그 위쪽 폴더의 파일은 시작할 때 읽고, 하위 폴더의 파일은 Claude가 그 폴더의 파일을 다룰 때 읽어요. 여러 파일은 서로 덮어쓰지 않고 이어 붙여져요. 저장소에 다른 코딩 에이전트용 `AGENTS.md`만 있고 CLAUDE.md가 없으면, Claude Code는 기본적으로 AGENTS.md를 읽어요(v2.1.277 이상).

### 무엇을 넣나
기준은 하나예요. **Claude가 코드를 읽어서는 알 수 없는 것만** 적어요.

- 확인하는 법: 테스트·타입체크·린트 명령, 테스트 파일 하나만 돌리는 법
- 저장소에 없는 결정: 팀이 정한 규칙, 배포 방식
- 코드가 오해를 부르는 곳: 곳곳에 있지만 새 코드에서는 따라 하면 안 되는 옛 패턴
- 두 번 이상 고쳐 준 것

"코드를 잘 정리해"보다 "들여쓰기는 2칸"처럼 확인할 수 있게 쓰고, 200줄 아래를 목표로 해요. 길어질수록 컨텍스트를 먹고 덜 지켜져요. `/init`은 초안을 만들어 주고, `/memory`는 파일을 열어 편집하게 해 주고, `/context all`의 Memory files 목록에서 실제로 읽혔는지 확인할 수 있어요.

한계도 있어요. CLAUDE.md는 **맥락이지 강제 설정이 아니에요.** Claude는 따르려고 하지만 보장되지는 않아요. 예외 없이 지켜야 하는 규칙은 hook의 몫이에요(S22, S25). 간결하게 쓰는 법은 S24에서 깊게 봐요.

### 서브에이전트: 조사는 맡기고 결론만 받는다
코드베이스를 탐색하면 읽은 파일이 전부 내 컨텍스트에 쌓여요. **서브에이전트**(subagent)는 자기만의 컨텍스트 윈도우에서 일하고 요약만 돌려주는 전문 조수예요. 긴 과정은 그쪽 컨텍스트에 남고, 내 대화에는 결론만 들어와요.

- **내장**: 읽기 전용 탐색을 하는 Explore, Plan 모드에서 조사를 맡는 Plan, 여러 단계 작업을 하는 general-purpose가 있어요. Claude가 필요할 때 알아서 써요.
- **직접 만들기**: YAML 프런트매터가 붙은 마크다운 파일이에요. `.claude/agents/`에 두면 이 프로젝트에서, `~/.claude/agents/`에 두면 내 모든 프로젝트에서 써요. 필수 항목은 `name`과 `description`뿐이고, 본문이 시스템 프롬프트가 돼요.

```markdown
---
name: code-reviewer
description: Reviews code for quality and best practices
tools: Read, Glob, Grep
model: sonnet
---

You are a code reviewer. When invoked, analyze the code and provide
specific, actionable feedback on quality, security, and best practices.
```

Claude는 `description`을 보고 언제 맡길지 정하고, "code-reviewer 서브에이전트로 최근 변경을 봐 줘"처럼 이름을 불러 시킬 수도 있어요. `tools`로 도구를 제한할 수 있어요(위 예는 읽기 전용). 파일은 Claude에게 만들어 달라고 하는 게 가장 쉬워요. 서브에이전트의 요청도 사용량 한도에 함께 잡혀요.

## 직접 해 보기 (5분)
`~/cc-playground`에서 해 보세요.

1. `/init`으로 CLAUDE.md 초안을 만들고, 새 동료에게 굳이 말하지 않을 줄은 지우세요. 그리고 "새 파일 이름은 소문자와 하이픈만 쓴다"를 한 줄 추가하세요. `/exit` 후 `claude`를 다시 실행해 `/context all`에서 Memory files에 파일이 보이는지 확인하고, "회의 메모 파일을 하나 만들어 줘"라고 해 보세요.
   - 관찰: 파일 이름이 규칙을 따랐나요? 따르지 않았다면 그 한 줄을 어떻게 더 구체적으로 쓸 수 있을까요?
2. "이 프로젝트의 .claude/agents/ 에 file-summarizer 서브에이전트를 만들어 줘. 폴더의 파일을 읽고 세 줄로 요약하는 읽기 전용 역할이야."라고 하세요. 만들어진 파일을 열어 `name`, `description`, `tools`를 읽은 뒤 "file-summarizer 서브에이전트로 이 폴더를 요약해 줘"라고 하세요. Claude가 새 서브에이전트를 찾지 못하면 Claude Code를 다시 시작하세요.
   - 관찰: 대화에 서브에이전트 이름이 붙은 도구 호출 줄이 보이나요? 내 대화에는 과정이 들어왔나요, 요약만 들어왔나요?

   - (c) 절대 예외가 없어야 하는 보안 차단 규칙(이것만으로 강제하려는 목적)

5. (상황형) 고객사 개발자가 말해요. "Claude가 매번 우리 테스트 명령을 틀리고, 새 세션마다 같은 설명을 반복해야 해요." 무엇을 제안하고, 어디에 무엇을 적게 할까요?

## FDE 관점
FDE는 언젠가 현장을 떠나요. 그때 저장소에 남는 것이 CLAUDE.md예요. 파일럿 동안 고객 개발자가 Claude를 고쳐 준 내용을 그때그때 프로젝트 CLAUDE.md에 모아 두면, 그 파일이 다음 사용자 그룹의 온보딩 문서가 돼요. 고객 저장소에 이미 AGENTS.md가 있는지 먼저 보고, 개인 취향은 CLAUDE.local.md나 사용자 파일로 보내 팀 파일을 짧게 유지하세요. 서브에이전트도 같은 방식으로 남길 수 있어요. 고객의 리뷰 기준을 담은 읽기 전용 리뷰어를 `.claude/agents/`에 커밋하면 팀 전체가 같은 기준으로 검토받아요. 파일럿 계획서의 "첫 사용자 그룹을 들이는 방법"에 "저장소를 받으면 이 설정이 따라온다"를 한 줄로 적을 수 있어요.

## 영상 대본

### 장면 1 · 오늘의 질문 (약 25초)
**화면:** 달력 두 칸. 어제 칸에는 "테스트는 이렇게 돌려요"라고 설명하는 사람, 오늘 칸에는 같은 설명을 또 하는 사람. 제목 "왜 매번 다시 설명할까?"
**내레이션:** 어제 알려 준 걸 오늘 또 설명해요. 클로드가 잊은 걸까요? 세션이 매번 새로 시작하기 때문이에요. 오늘은 이 틈을 메우는 방법을 볼게요.

### 장면 2 · 인수인계 메모 (약 35초)
**화면:** 새 세션 상자가 열릴 때마다 "CLAUDE.md" 메모지가 먼저 들어감. 세션 세 개가 차례로 열리고, 매번 같은 메모지가 들어감.
**내레이션:** 클로드 엠디는 인수인계 메모예요. 세션이 시작될 때마다 클로드 코드가 이 파일부터 읽어요. 그래서 한 번 적어 두면 다시 설명하지 않아도 돼요.

### 장면 3 · 세 자리 (약 40초)
**화면:** 폴더 그림 세 개: 저장소 루트의 "CLAUDE.md"(사람 여럿 아이콘), 홈 폴더의 "~/.claude/CLAUDE.md"(사람 하나 + 폴더 여럿), 저장소의 "CLAUDE.local.md"(사람 하나 + 자물쇠).
**내레이션:** 두는 자리가 범위를 정해요. 저장소 루트에 두면 팀 전체가 같이 써요. 홈 폴더에 두면 나만, 모든 프로젝트에서 써요. 로컬 파일은 나만, 이 프로젝트에서만 써요.

### 장면 4 · 넣을 것과 뺄 것 (약 40초)
**화면:** 저울. 왼쪽 접시 "넣기": 테스트 명령, 팀이 정한 규칙, 두 번 고쳐 준 것. 오른쪽 접시 "빼기": 코드에서 보이는 것. 아래 눈금자 "200줄 아래".
**내레이션:** 기준은 하나예요. 코드를 읽어서는 알 수 없는 것만 적어요. 테스트 명령, 팀이 정한 규칙, 두 번 고쳐 준 것들이에요. 파일은 짧을수록 잘 지켜져요.

### 장면 5 · 맥락이지 강제가 아니다 (약 35초)
**화면:** 메모지 "CLAUDE.md"는 Claude 머리 옆에 떠 있고("읽고 판단"), 옆의 철문 "hook"은 길을 막고 있음("반드시 실행"). 둘 사이에 "≠".
**내레이션:** 한 가지 한계가 있어요. 이 파일은 맥락이지 강제 설정이 아니에요. 클로드는 따르려고 하지만 보장되지는 않아요. 예외가 없어야 하는 규칙은 다음 시간에 볼 훅의 몫이에요.

### 장면 6 · 조사가 컨텍스트를 채운다 (약 30초)
**화면:** 메인 컨텍스트 통에 "읽은 파일" 블록이 우수수 떨어져 금방 참. 정작 필요한 "결론" 블록은 작게 하나.
**내레이션:** 이제 두 번째 주제예요. 코드를 탐색하면 읽은 파일이 전부 내 컨텍스트에 쌓여요. 정작 필요한 건 결론 한 줄인데요.

### 장면 7 · 서브에이전트 (약 40초)
**화면:** 메인 통 옆에 작은 통이 새로 생김("서브에이전트"). 파일 블록은 작은 통에만 쌓이고, 끝나면 "요약" 블록 하나만 화살표를 타고 메인 통으로 넘어옴.
**내레이션:** 서브에이전트는 자기만의 컨텍스트에서 일하는 조수예요. 긴 조사는 그쪽에서 하고, 내 대화에는 요약만 돌아와요. 과정은 빼고 결론만 받는 거예요.

### 장면 8 · 파일 하나로 만든다 (약 40초)
**화면:** 마크다운 파일이 펼쳐짐. 위쪽 프런트매터에서 "name", "description", "tools: Read, Glob, Grep"이 차례로 강조되고, 아래 본문에 "시스템 프롬프트" 이름표. 파일이 ".claude/agents/" 폴더로 들어감.
**내레이션:** 직접 만들 수도 있어요. 마크다운 파일 하나면 돼요. 이름과 설명을 적고, 쓸 수 있는 도구를 정해요. 클로드는 설명을 보고 언제 맡길지 정해요. 클로드에게 만들어 달라고 하는 게 가장 쉬워요.

### 장면 9 · 고객 앞에서 (약 35초)
**화면:** FDE가 문을 나서고, 저장소에는 "CLAUDE.md"와 ".claude/agents/reviewer.md"가 남음. 새 팀원이 저장소를 받자 두 파일이 함께 따라옴.
**내레이션:** 에프디이는 언젠가 현장을 떠나요. 그때 저장소에 남는 게 이 파일들이에요. 파일럿 동안 고쳐 준 내용을 모아 두면, 다음 사용자의 온보딩 문서가 돼요.

### 장면 10 · 요약과 예고 (약 25초)
**화면:** 세 줄 요약: "1. CLAUDE.md는 매 세션 읽는 메모 2. 코드로 알 수 없는 것만, 짧게 3. 서브에이전트는 요약만 돌려준다". 아래에 "다음: S22 skills, MCP, hooks".
**내레이션:** 정리할게요. 클로드 엠디는 매 세션 읽는 메모예요. 코드로 알 수 없는 것만 짧게 적어요. 서브에이전트는 따로 일하고 요약만 돌려줘요. 다음 시간에는 스킬과 엠씨피, 훅을 볼게요.

## 정답과 해설
1. (b). 프로젝트 루트(또는 `.claude/`)의 CLAUDE.md를 커밋하면 팀이 함께 써요. (a)는 나만 모든 프로젝트에서, (c)는 나만 이 프로젝트에서 쓰는 파일이에요.
2. (b). 코드에서 알 수 있는 것은 빼고, 예외가 없어야 하는 규칙은 CLAUDE.md만으로 강제할 수 없어 hook이나 권한 규칙에 둬요.
3. (b). 서브에이전트는 별도 컨텍스트 윈도우에서 일하고 요약만 돌려줘요. 권한을 건너뛰는 장치가 아니에요.
4. 예시 답: CLAUDE.md의 내용은 Claude가 읽고 따르려고 하는 지침이지, Claude Code가 강제로 실행하는 설정이 아니다. 그래서 대부분은 지켜지지만 매번 보장되지는 않는다. "절대 하면 안 되는 일"이나 "매번 반드시 해야 하는 일"은 hook이나 권한의 deny 규칙처럼 Claude Code가 강제하는 곳에 둔다.
5. 예시 답: 프로젝트 CLAUDE.md를 만들자고 제안한다. `/init`으로 초안을 만든 뒤 코드에서 알 수 있는 줄은 지우고, 정확한 테스트·빌드 명령과 반복해서 설명하던 규칙을 구체적으로 적어 커밋하게 한다. 개인 취향은 CLAUDE.local.md에 두고, 새 세션에서 `/context all`로 파일이 읽혔는지 확인한다. 앞으로 같은 지적을 두 번 하게 되면 그때마다 한 줄씩 추가하는 습관을 권한다.
