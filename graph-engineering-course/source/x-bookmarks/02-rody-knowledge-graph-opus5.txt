  - heading [level=2]: "Why graphs and Opus 5 fit together"
  - text: "A knowledge graph gives your agent memory that survives compaction: entities, relationships, and timestamps it can traverse instead of re-reading. The catch has always been the build cost. Every conversation and document you feed in runs an extraction pass, and at frontier rates that adds up fast.Opus 5 changes the math on exactly that step:"
  - list:
    - listitem: "Cache reads at $0.50 per million, a 90% discount off the $5 base. Graph ingestion re-sends the same schema and instructions on every episode, and that repeated prefix now bills at a tenth of the price"
    - listitem: "Minimum cacheable prefix dropped to 512 tokens, half what Opus 4.8 needed. Short extraction prompts that were too small to cache before now qualify with zero code change"
    - listitem: "Batch API at 50% off, stacking with caching. Backfilling a year of history into a graph is the textbook batch job: not time-sensitive, high volume, perfectly cacheable"
  - text: "The result: the one operation that made graph memory expensive is now the cheapest thing Opus 5 does."
  - region:
    - link [ref=e18]
  - heading [level=2]: "The core split: cheap extraction, careful traversal"
  - text: "Graph engineering has two model-facing jobs, and they want opposite settings. Getting this split right is the whole skill."
  - list:
    - listitem: "Extraction (high volume, low judgment): pulling entities and typed relations out of raw text. Runs on every episode, thousands of times. This wants low effort and a stable cached prefix"
    - listitem: "Traversal reasoning (low volume, high judgment): answering a multi-hop question by walking the graph and synthesizing. Runs rarely, matters a lot. This wants high or max effort"
  - text: "Run extraction at max effort and you burn frontier tokens on mechanical work. Run traversal at low effort and your multi-hop answers get lazy. The bill and the quality both live in this one decision."
  - heading [level=2]: "The extraction config (copy this)"
  - text: "Keep the schema and instructions as an identical prefix on every episode so the cache actually hits:"
  - region:
    - text: "python"
    - button "클립보드에 복사하기" [ref=e19]
    - text: "import  anthropic\n\n client = anthropic.Anthropic()\n\n# Stable prefix: identical every call = $0.50/M cache reads\n EXTRACTION_SYSTEM = \"\"\"Extract a knowledge graph from the text.\nReturn JSON only:\n{\n  \"entities\": [{\"name\", \"type\", \"description\"}],\n  \"edges\": [{\"source\", \"target\", \"relation\", \"valid_from\"}]\n}\nRules:\n- Canonical names only (resolve \"Buzz Aldrin\" = \"Edwin Aldrin\")\n- Every edge needs a valid_from date if the text implies one\n- Never invent relations not stated in the text\n\"\"\"\n\ndef  extract(episode_text, occurred_at):\n    return  client.messages.create(\n        model=\"claude-opus-5\",\n        max_tokens=2000,\n        system=[{\n            \"type\": \"text\",\n            \"text\": EXTRACTION_SYSTEM,\n            \"cache_control\": {\"type\": \"ephemeral\"},   # cache the prefix\n        }],\n        messages=[{\"role\": \"user\", \"content\":\n            f\"reference_time: {occurred_at}\n\n{episode_text}\"}],\n        extra_headers={\"effort\": \"low\"},   # mechanical work, low effort\n    )"
  - text: "Three details that decide the bill:"
  - list:
    - listitem: "cache_control on the system block  is what turns $5 into $0.50 on every repeat. Without it you pay full rate every episode"
    - listitem: "effort: low  because extraction is pattern-matching, not reasoning. Save the thinking budget for traversal"
    - listitem: "The variable part goes last. Episode text and timestamp change every call; the schema never does. Stable-first, variable-last is what keeps the prefix cacheable"
  - heading [level=2]: "The traversal config (the other half)"
  - text: "When the agent answers a real question, flip both settings:"
  - region:
    - text: "markdown"
    - button "클립보드에 복사하기" [ref=e20]
    - text: "## Graph routing (CLAUDE.md)\n\nIngestion (writing to the graph):\n- Model: Opus 5, effort low\n- Always cache the extraction schema prefix\n- Batch historical backfills, never run them synchronously\n\n Traversal (querying the graph):\n- Model: Opus 5, effort high (max for deep multi-hop)\n- Force a retrieval step: pull the relevant subgraph first,\n  then reason only over those facts\n- Every answer cites the specific edges it used\n\n Never:\n- Run extraction at high effort (burns tokens on mechanics)\n- Run traversal at low effort (lazy multi-hop answers)\n- Change effort mid-session (it invalidates your cache)"
  - text: "That last rule is a real trap on Opus 5: effort is part of the prompt-cache key. Flip it mid-conversation and the next turn re-reads your entire context at full uncached price. Set ingestion and traversal as separate sessions, not one session toggling effort."
  - heading [level=2]: "Wiring it into Claude Code"
  - text: "Graphiti ships an MCP server, so Claude Code reads and writes the graph with no glue code. Point extraction at the cheap setting right in the config:"
  - region:
    - text: "json"
    - button "클립보드에 복사하기" [ref=e21]
    - text: "{\n  \"mcpServers\": {\n    \"graphiti\": {\n      \"command\": \"uvx\",\n      \"args\": [\"graphiti-mcp\"],\n      \"env\": {\n        \"NEO4J_URI\": \"bolt://localhost:7687\",\n        \"NEO4J_PASSWORD\": \"${NEO4J_PASSWORD}\",\n        \"MODEL_NAME\": \"claude-opus-5\",\n        \"MODEL_EFFORT\": \"low\"\n      }\n    }\n  }\n}"
  - text: "Neo4j runs in one Docker container for a dev graph. Now Claude Code has memory that survives every compaction, every restart, and every new session, and the extraction feeding it bills at cache-read rates."
  - heading [level=2]: "The bill, worked out"
  - text: "A realistic shape: backfilling 5,000 episodes, each ~800 tokens of text against a ~600-token cached schema prefix."
  - region:
    - button "클립보드에 복사하기" [ref=e22]
    - text: "Naive (full rate, no cache, high effort):\n  5,000 × 1,400 tokens × $5/M  = $35.00 input\n   plus heavy reasoning output at $25/M\n\n Opus 5 done right (cached prefix, low effort, batched):\n  schema:  600 tokens × $0.50/M cache read\n   text:    800 tokens × $2.50/M batch input\n  = roughly $10.30 input, output minimal at low effort"
  - text: "Same graph, built for under a third of the naive cost, and the batch backfill runs while you sleep. Feeding a temporal graph is now cheaper than embedding the same corpus into a vector store."
  - heading [level=2]: "Common mistakes"
  - list:
    - listitem: "Extraction at high effort. The single most expensive habit. Entity extraction is mechanical, low effort handles it, and you save the reasoning budget for the queries that need it"
    - listitem: "No cache_control on the schema. You re-send the same instructions on every episode. Without caching that's full rate every time; with it, a tenth"
    - listitem: "Synchronous backfill. Loading history one blocking call at a time forfeits the 50% batch discount for zero benefit. Nobody's waiting on a backfill"
    - listitem: "Toggling effort mid-session. It's part of the cache key. One flip and your next turn re-reads everything at full price. Separate sessions for ingest and query"
    - listitem: "Skipping reference_time. No timestamps means no temporal graph, just a static ontology that rots. The whole reason to build this over embeddings is the time layer"
  - heading [level=2]: "The 20-minute setup"
  - list:
    - listitem "." [ref=e23]: ". Run Neo4j in Docker and add the Graphiti MCP block, effort low (5 min)"
    - listitem "." [ref=e24]: ". Set the extraction schema as a cached prefix, variable text last (5 min)"
    - listitem "." [ref=e25]: ". Backfill your history through the Batch API, not synchronously (4 min)"
    - listitem "." [ref=e26]: ". Add the traversal routing to CLAUDE.md, high effort for queries (3 min)"
    - listitem "." [ref=e27]: ". Ask one multi-hop question and check it cites real edges (3 min)"
