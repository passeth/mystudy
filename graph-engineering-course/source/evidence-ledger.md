## Executive summary: high-signal vs hype

### High-signal

1. **공식 LangGraph 문서에 근거한 설명**은 신호가 높다. State/Node/Edge, super-step 체크포인트, durable execution, `interrupt()`/`Command(resume=...)`는 실제 기능이다. 다만 노드 중간에서 그대로 이어지는 것이 아니라 체크포인트 이후 노드가 처음부터 재실행될 수 있다는 제약을 반드시 가르쳐야 한다.
2. **Microsoft의 현재 방향은 AutoGen GraphFlow가 아니라 Microsoft Agent Framework(MAF)**다. GraphFlow 기능 자체는 실재하지만 공식 문서상 experimental이고, AutoGen 저장소는 maintenance mode다. MAF 1.0 GA가 후계자다.
3. **Google ADK 2.0 graph workflow**는 2026년 현재 공식 기능이다. 특히 ADK Go 2.0 GA의 nodes/edges/routes/fan-out/fan-in/loops/HITL은 공식 자료로 확인된다. 과거 ADK 1.x의 계층형 workflow-agent 설명과 2.0 graph runtime을 섞지 말아야 한다.
4. **Anthropic의 workflow-vs-agent 구분, 90.2%, 4x/15x**는 실제 Anthropic 1차 출처에 있다. 그러나 90.2%는 일반 벤치마크가 아니라 Opus 4 lead + Sonnet 4 subagents의 **내부 research eval** 결과이고, 4x/15x는 채팅 대비 관측 토큰 사용량이다.
5. **Claude Code dynamic workflows, `agent()`/`parallel()`/`pipeline()`, `/deep-research`, `/workflows`, `ultracode`**는 2026-07-29 현재 공식이다. 이를 전부 조작이라고 단정하는 북마크는 낡았거나 틀렸다. 반대로 2026-05-28 공개 전 게시물이 같은 기능을 주장했다면 당시 시점 검증이 필요하다.
6. **Bun Zig→Rust와 Anthropic 내부 Python→TypeScript 포트**는 공식 사례다. 테스트·컴파일러·diff를 심판으로 둔 implement→adversarial review→fix 루프가 핵심이며, 단순 “프롬프트 한 번으로 변환” 사례가 아니다.
7. **Microsoft GraphRAG의 local/global search와 community reports**는 1차 근거가 강하다. 반면 “정확도 +18%, 비용 -85%”는 Microsoft GraphRAG의 보편 성능 수치가 아니라 2026년 **산업용 P&ID 도면** 논문의 raw-image/smart-P&ID 비교 결과다.
8. **Graphiti**의 시간 인식 사실, validity window, provenance, MCP server는 공식 저장소와 문서로 확인된다.

### Hype / 주의

- **숫자 맥락 삭제:** “멀티에이전트가 90.2% 더 좋다”, “GraphRAG가 18% 더 정확하고 85% 싸다”처럼 데이터셋·대조군·평가자를 삭제한 문장은 과장이다.
- **두 마이그레이션 혼합:** Bun은 **Zig→Rust**이고, Python→TypeScript 165k LOC는 이름이 공개되지 않은 별도 Anthropic 내부 도구다.
- **Bun 비용 표현:** 약 $165k는 공개 API 가격 환산치이지 Anthropic의 외부 현금지출 감사값이 아니다. Python→TypeScript 사례의 비용은 공개되지 않았다.
- **“100% 테스트 통과 = 무결함” 오해:** Bun은 merge 전 기존 CI 테스트 100% 통과 후에도 19개 회귀가 발견됐다.
- **GitHub stars를 품질로 사용:** Graphify 약 97.5k, GitNexus 약 44.7k, Cognee 약 29.5k는 API상 사실이지만 학습성과·정확성의 증거가 아니다. 특히 GitNexus는 PolyForm Noncommercial 1.0.0이라 “오픈소스”보다 **source-available/noncommercial**로 가르치는 편이 정확하다.
- **Issue tree를 실행 그래프로 동일시:** 문제 분해의 시각적 트리/DAG 비유는 유용하지만, 상태·스케줄링·재시도·체크포인트를 가진 workflow runtime과 같은 것은 아니다.

## 과정 설계에 바로 반영할 red flags

1. **Durability의 의미를 정확히:** LangGraph는 node replay, Claude Code workflow는 same-session resume다. 둘을 “중단 지점에서 영구 재개”로 묶지 않는다.
2. **GraphFlow 신규 채택 금지:** 실습은 역사 비교만 하고 신규 Microsoft 파트는 MAF 1.0을 사용한다.
3. **모든 숫자에 denominator를 붙임:** 90.2%는 internal research eval, 4x/15x는 chat 대비 tokens, 18%/85%는 P&ID domain의 서로 다른 comparator다.
4. **마이그레이션 사례를 분리:** Bun Zig→Rust와 비공개 내부 Python→TS를 한 사례처럼 합치지 않는다.
5. **Stars/라이선스 분리:** popularity와 correctness를 분리하고, GitNexus는 PolyForm Noncommercial 제약을 명시한다.
6. **Problem graph와 execution graph 분리:** Issue tree는 decomposition artifact, LangGraph/MAF/ADK는 executable orchestration runtime이다.
