Lesson 0006 · Two Complete Builds

리서치 데스크와 SEO 머신을 그래프로 바꾸기

다이아몬드를 실제 업무로 번역한다. 중요한 건 에이전트 수가 아니라 분기 기준, 반증 검사, 파일 소유권, 사람 승인 위치다.

15분원본 도식 2장복사 가능한 프롬프트
마케팅 문구를 그대로 믿지 말 것. 원문은 프롬프트의 “workflow” 한 단어가 coordinated team을 만든다고 설명하지만, 실제 병렬 실행은 사용 중인 하네스가 subagent·task·병렬 도구를 지원하고 모델이 그 기능을 호출했을 때만 일어난다. 화면이나 로그에서 작업이 정말 fan-out 되었는지 확인해야 한다.

1. Build A: Deep Research Desk

돈이 걸린 질문을 다섯 관점으로 나누고, 각 조사 결과를 skeptic이 반증한 뒤 살아남은 것만 confidence 순으로 합친다. 여기서 제품은 “다섯 조사자”가 아니라 skeptic pass다.

노드입력출력 계약
Planner한 문장 의사결정 질문겹치지 않는 5개 관점
Researchers ×5각 관점주장 + 출처 링크 + 날짜
Skeptic모든 주장반증 시도 + 통과/탈락 이유
Merger통과 주장신뢰도 순 단일 보고서
Human보고서결정 또는 추가 조사
원문 프롬프트 · 질문만 교체

Decision-grade research

I need decision-grade research on: [your question]. Use a workflow: split the question into 5 distinct angles, run one researcher per angle in parallel, every finding needs a source link and a date, then run a skeptic against each finding that tries to disprove it, drop what fails, merge the survivors into one report ranked by confidence, save it as research-report.md and show me the top findings.

실행 전에 덧붙일 운영 계약

- 각 researcher는 자기 파일만 작성: findings/angle-01.md ... angle-05.md
- skeptic은 원본을 수정하지 않고 reviews/에 판정만 작성
- 출처를 열어 확인하지 못한 주장은 unverified로 표시
- 최대 재시도 2회, 최대 researcher 5명
- 최종 보고서는 사람이 승인하기 전 외부 전송 금지
슬기 업무에 연결: Sales Agent의 “새 시장/바이어 우선순위” 조사, RISELAB의 경쟁사 비교, PDP의 포지셔닝 조사에 적합하다. 단, 가격·규제·고객 사실은 실제 데이터 앵커를 별도로 붙인다.

2. Build B: SEO Content Machine

세 조사자가 현재 상위 페이지, 실제 질문, 경쟁 콘텐츠의 빈틈을 동시에 찾는다. 병합된 outline에서 한 writer가 초안을 만들고, fact-checker가 출처 없는 주장을 상단에 모아둔다. 자동 게시하지 않는다.

Top pages
현재 상위 문서가 공통으로 다루는 것.
Real questions
사람들이 실제로 묻는 질문과 표현.
Content gaps
상위 페이지가 놓치는 관점·근거·사례.
원문 프롬프트 · topic만 교체

Ranking-ready draft

I want an article that can rank for: [topic]. Use a workflow: run three research jobs in parallel, one lists what the current top-ranking pages cover, one collects the real questions people ask about this topic, one finds what the top pages skip, merge all three into an outline, write a full draft from the outline, then run a fact-checker that flags every claim without a source, save the draft to drafts/ with the flagged claims listed at the top, never publish anything.

왜 writer는 하나인가

조사는 독립적이지만 완성 글은 톤·논리·중복을 공유한다. 여러 writer가 한 파일을 동시에 쓰면 병합 충돌과 문체 파편화가 생긴다. 따라서 병렬화는 자료 수집에 쓰고, outline 이후에는 단일 writer로 수렴한다.

게시 gate 체크

  • 상단의 flagged claims가 모두 출처 또는 삭제로 해소됐는가?
  • 검색 결과가 현재 날짜 기준인가?
  • 화장품·규제 문구라면 법적 claim 검토를 통과했는가?
  • 브랜드가 직접 아는 경험·숫자가 추가됐는가?
  • 사람이 읽은 뒤에만 publish 되었는가?
