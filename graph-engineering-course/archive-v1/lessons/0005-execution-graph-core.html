Lesson 0005 · Execution Graph

실행 그래프의 핵심: 가짜 엣지, 다이아몬드, 멈춤 규칙

Machina의 풀코스를 그대로 외우지 않고, “언제 병렬화하고 어디서 검증하며 언제 사람이 멈춰 세우는가”라는 설계 판단으로 바꾼다.

12분원본 도식 4장실행 그래프Human gate
먼저 용어를 고정한다. 기존 0001~0002의 Perez식 “개선 루프 그래프”는 목표와 지표를 누가 감시하는가의 문제다. 이번 포스팅의 “실행 그래프”는 어떤 작업을 병렬·순차·검증·승인으로 배선할지의 문제다. 둘은 경쟁 개념이 아니라 다른 층이다.

1. 그래프는 무엇인가

그래프는 AI 작업 계획을 눈에 보이게 만든 것이다. 노드는 한 조수에게 맡길 만한 하나의 일, 엣지는 앞선 결과가 있어야 다음 일이 시작될 수 있다는 의존성, 상태는 발견·결정·남은 일을 운반하는 실행 메모다.

Node
조사, 초안, 사실 확인처럼 독립적인 한 가지 일.
Edge
결과가 실제로 다음 노드에 흘러갈 때만 존재하는 화살표.
State
노드 사이를 이동하는 출처, 결정, 미완료 목록.
Gate
검사나 승인 전에는 다음 단계로 못 가게 하는 문.

2. 첫 번째 진단: 가짜 엣지를 지워라

문장에 “그리고 나서”가 들어간다고 진짜 순서가 되는 것은 아니다. 다음 작업이 앞 작업의 결과를 읽지 않는다면 둘은 병렬 실행 가능하다.

작업진짜 의존?설계
파일 요약 → 그 요약으로 이메일 작성예. 이메일이 요약을 읽음순차 엣지 유지
파일 요약 → 캘린더 확인아니오. 캘린더가 요약을 안 읽음엣지 삭제, 병렬
경쟁사 5곳 조사 → 종합 결론종합이 5개 결과를 읽음5-way fan-out 후 fan-in
30초 실습
현재 AI 업무를 동사로만 쓴다. 각 화살표마다 “오른쪽 노드는 왼쪽 결과를 읽는가?”를 묻는다. 아니오라면 가짜 엣지다.

3. 돈값 하는 기본형: 다이아몬드

심각한 multi-agent 시스템에서 반복되는 모양은 분기 → 병렬 조사 → 별도 검증 → 합류다. 글은 이를 올해 배울 단 하나의 패턴으로 제시한다.

1. PLAN질문을 겹치지 않는 하위 문제로 분해
2. FAN-OUT독립 작업자를 동시에 실행
3. CHECK정확성·최신성·출처를 서로 다른 질문으로 공격
4. FAN-IN살아남은 결과만 하나로 병합
5. GATE사람이 비싼 결정을 승인
같은 에이전트에게 자기 숙제를 채점시키지 않는다. 생성 노드와 검증 노드를 분리하고, 검사자마다 질문도 분리한다. “정확한가?”, “현재도 유효한가?”, “출처가 실제로 존재하는가?”는 서로 다른 검사다.

4. 멈춤 규칙: 그래프는 폭을 사지 판단력을 사지 않는다

팀은 독립 조각으로 나뉘는 일에서는 이기지만, 매 단계가 앞 단계의 전체 맥락을 필요로 하는 일에서는 단일 에이전트보다 비싸고 느릴 수 있다.

그래프가 맞는 일
경쟁사별 조사, 채널별 탐색, 여러 가설의 독립 검증, 서로 다른 관점 수집.
한 에이전트가 맞는 일
긴 맥락을 계속 유지해야 하는 논증, 문장 단위 편집, 이전 판단을 매번 읽어야 하는 설계.
결정 질문은 하나다. “내 일이 어디서 서로의 결과를 읽지 않고 갈라지는가?” 그 지점이 없으면 에이전트를 늘리지 않는다.

5. Human gate와 네 가지 안전 규칙

사람은 모든 노드에 서는 것이 아니라 되돌리기 비싼 엣지 앞에 선다. 전송, 게시, 환불, 청구서 발행, 고객 데이터 변경이 대표적이다. 모든 단계에 승인문을 두면 사람이 병목이고, 아무 데도 두지 않으면 사고가 곧바로 세상에 나간다.

  1. 모든 루프에 최대 반복 횟수를 둔다.
  2. 한 파일에는 한 writer만 쓰게 한다. 병렬 노드는 각자 파일을 만들고 merge 노드가 합친다.
  3. 라우팅은 코드·워크플로가 소유하고, 모델은 노드 내부의 판단과 산출물을 채운다.
  4. spawn 가능한 에이전트 수에 상한을 둔다.
