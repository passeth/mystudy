Lesson 0010 · Graph Engineering v2

어떤 그래프를 언제 써야 하는가

아홉 개 레슨에서 네 가지 그래프를 배웠다. 마지막 질문은 "어느 것을 먼저 쓸 것인가"다. 그리고 가장 중요한 답 하나: 그래프를 아예 쓰지 않는 것도 정답일 수 있다.

오늘의 한 줄 답: 문제가 불명확하면 이슈 트리로 무엇을 풀지 정하고, 반복 경로를 모르면 루프로 먼저 관찰하고, 안정된 경로만 실행 그래프로 공식화하며, 관계·시간 질문에는 지식 그래프를, 지표·감사 충돌에는 개선 거버넌스 그래프를 쓴다. 넷 중 어디에도 해당하지 않으면 그래프를 쓰지 않는 것이 맞는 설계다.

1. 진단 순서: 다섯 가지 질문

① 문제가 불명확한가?

예 → 이슈 트리(Why/What/How + MECE)로 먼저 문제를 분해한다. 이것은 실행되지 않는 정적 다이어그램이다.

② 반복 경로를 아는가?

모른다 → 아직 그래프를 그리지 말고 루프를 돌려 실제 경로를 관찰한다. 조기에 그래프로 굳히면 틀린 추측이 고정된다.

③ 분기·병렬·복구가 필요한가?

예 → 반복 가능하고 안정된 경로만 실행 그래프(노드·엣지·상태)로 공식화한다.

④ 관계·시간 질문인가?

여러 사실을 넘나드는 multi-hop 질문이거나 "그때는 무엇이 참이었나"를 물어야 한다면 지식/시간 그래프가 맞다.

⑤ 지표·목표·감사가 충돌하는가?

측정값을 최적화했더니 진짜 목표에서 멀어지는 징후가 보이면 개선 거버넌스 그래프(pairing/hierarchy/arbitration/audit)를 쓴다.

2. 그래프를 쓰지 말아야 할 다섯 조건

조건이유
한 번뿐인 일judge와 rulebook을 만드는 비용이 실제 작업보다 크다.
단계를 아직 모른다루프가 먼저 경로를 찾아준다. 그래프는 이미 아는 경로를 고정하는 도구다.
기계적 judge가 없다사람의 취향이 매번 필요하면 리뷰어 노드는 연극이 된다.
냅킨에 못 그린다Codez의 원칙: 그릴 수 없을 만큼 복잡하면 설계가 아니라 혼란이다.
공유 컨텍스트 의존성이 높다모든 노드가 서로의 전체 맥락을 다 봐야 하면, 노드로 쪼개는 의미가 없다.

근거: Anthropic, Building effective agents — "가장 단순한 해법에서 시작하고, 필요할 때만 복잡도를 더하라."

3. 7-repo 지도 교정

X의 "seven repos" 스레드는 실행 측과 지식 측을 이미 구분했다. 다만 2026-07-29 기준 공식 문서로 확인하면 두 가지는 교정이 필요하다.

실행 그래프

LangGraph · Microsoft Agent Framework(MAF, AutoGen/Semantic Kernel의 공식 후계) · Temporal(범용 내구성 실행 엔진)

지식/시간 그래프

Graphify · GitNexus · Graphiti · Cognee
교정 1 — AutoGen GraphFlow: 공식 GitHub는 AutoGen을 Maintenance Mode로 표시하고 GraphFlow는 experimental 기능이다. 신규 구축은 MAF 1.0을 기준으로 한다.
교정 2 — GitNexus 라이선스: 공식 LICENSE는 PolyForm Noncommercial 1.0.0이다. "오픈소스"보다 source-available·비영리 제한으로 가르치는 편이 정확하다.

4. 빠진 세 번째 층: 결정/출처 그래프

같은 X 스레드의 댓글(@Truntr_)이 정확한 지적을 한다: "두 그룹 구분은 맞다. 그런데 아무도 만들지 않는 세 번째가 있다 — 작업을 실행하는 그래프, 사실을 저장하는 그래프, 그리고 결정을 저장하는 것은 없다. Graphiti가 가장 가깝지만 그것도 '언제'만 답할 뿐 '왜'는 답하지 못한다."

이 빈 자리는 실행 그래프 학습(레슨 0006)에서 이미 등장한 rulebook.md(규칙이 바뀔 때마다 이유를 한 줄 남기는 문서)와 정확히 연결된다. 표준 도구가 없으니, 지금은 규칙 파일 + 결정 로그로 이 층을 직접 메워야 한다.

실무 번역: Trade Intel/Sales Agent 기능 하나를 이 클리닉으로 진단해보자. 예: "거래처 담당자 자동 배정" — 문제는 명확하고(①아니오), 경로는 이미 몇 번 반복해 안다(②예), 승인·예외 처리 분기가 필요하다(③예) → 실행 그래프로 공식화할 후보다. 반면 "이번 주 특이사항 요약"처럼 매번 형식이 바뀌는 일회성 보고는 ①~⑤ 어디에도 깔끔히 걸리지 않으면, 그래프를 쓰지 않고 사람이 직접 쓰는 편이 맞는 결론일 수 있다.
